@Bean
UserDetailsService userDetailsService(UserMapper mapper) {
    return username -> {
        UserEntity u = mapper.findByUsername(username);
        if (u == null) throw new UsernameNotFoundException(username);
        return User.withUsername(u.getUsername())
                .password(u.getPassword())   // 库里存的是 {bcrypt}$2a$10$…
                .roles(u.getRole())          // "USER" 会变成 ROLE_USER
                .build();
    };
}

@Bean
PasswordEncoder passwordEncoder() {
    return PasswordEncoderFactories.createDelegatingPasswordEncoder();  // 默认 bcrypt
}
  • 声明了这两个 Bean，Spring Security 会自己把 DaoAuthenticationProvider 装好。
  • 用户不存在，也只说“用户名或密码错误”。默认把 UsernameNotFoundException 换成 BadCredentialsException，免得被人试出哪些账号存在。
  • {bcrypt} 前缀决定用哪种算法。以后换算法，老用户的密码照样能比对。
  • JWT、LDAP、记住我，用的是同一个总管，只是换了一个 Provider。

授权：两道门

第一道门在过滤器链的最后一关，按 URL 管；第二道门在方法外面，按方法管。

第一道门：按 URLauthorizeHttpRequests → AuthorizationFilter

看请求的地址和方法。粗粒度，一整片 URL 一起管。

第二道门：按方法@PreAuthorize → AOP 代理

进了 Controller 之后，在 Service 方法外面再查一次。细粒度，能拿参数、返回值来判断。

JDK 8 和 JDK 17：流程没变，写法变了

Boot 2 配 Spring Security 5，Boot 3 配 Spring Security 6。保安队、核验台、工牌、门禁这套模型没变。

Security 5 · Boot 2

JDK 8+
@EnableWebSecurity
public class SecurityConfig extends WebSecurityConfigurerAdapter {
    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http.authorizeRequests()
                .antMatchers("/public/**").permitAll()
                .antMatchers("/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated()
            .and()
            .formLogin();
    }
}
  • 继承 WebSecurityConfigurerAdapter，重写 configure。5.7 起标记过时
  • authorizeRequests() + antMatchers，门禁叫 FilterSecurityInterceptor
  • 方法注解要手动打开：@EnableGlobalMethodSecurity(prePostEnabled = true)
  • 请求结束时，SecurityContextPersistenceFilter 自动把工牌存回 Session
  • javax.servlet 包。Boot 2.7（Security 5.7、5.8）已经能用右边的新写法，升级前先在这一步改

Security 6 · Boot 3

JDK 17+
@Configuration
@EnableWebSecurity
@EnableMethodSecurity
public class SecurityConfig {
    @Bean
    SecurityFilterChain web(HttpSecurity http) throws Exception {
        http.authorizeHttpRequests(a -> a
                .requestMatchers("/public/**").permitAll()
                .requestMatchers("/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated())
            .formLogin(Customizer.withDefaults());
        return http.build();
    }
}
  • WebSecurityConfigurerAdapter 删除，只能声明 SecurityFilterChain Bean
  • authorizeHttpRequests() + requestMatchers，门禁换成 AuthorizationFilter；antMatchers、mvcMatchers 删除
  • @EnableMethodSecurity，@PreAuthorize 默认就开；@EnableWebSecurity 不再自带 @Configuration，要自己加
  • SecurityContextHolderFilter 只取不存：自己写的登录接口，要手动保存工牌
  • 门禁对每次派发都检查，转发到 /error 也要过
  • jakarta.servlet 包；.and() 写法 6.1 起标记过时，统一用 lambda
没变的：过滤器链模型认证三件套工牌放在 SecurityContextHolder401 / 403 的分工

常踩的坑

多数是没想清楚：这一刻请求走到了哪个保安面前，手里拿的是什么牌。

用 Postman 发 POST，一律 403

CSRF 默认开着，没带令牌就拒。用 Session 登录的页面要带上 _csrf；纯 token 的 API 可以 csrf(c -> c.disable())。

hasRole("ADMIN") 一直 403

库里存的权限是 ADMIN，hasRole 查的却是 ROLE_ADMIN。存成 ROLE_ADMIN，或者改用 hasAuthority("ADMIN")。

There is no PasswordEncoder mapped for the id "null"

库里的密码是明文，或者没有 {bcrypt} 这样的前缀。用 PasswordEncoder 加密后再存。

自己写的 JWT 过滤器，一个请求执行两次

标了 @Component，Boot 又把它注册成了普通 Filter。去掉 @Component 直接 new，或者用 FilterRegistrationBean 关掉自动注册。

token 过期的异常，@ControllerAdvice 接不到

是过滤器里抛的，不经过 Spring MVC。用 AuthenticationEntryPoint 统一返回 401 JSON。

@PreAuthorize 拒绝后，前端拿到的是 500

全局 @ExceptionHandler(Exception.class) 先把 AccessDeniedException 吃掉了。单独接住它再抛出去，交还给 Spring Security。

permitAll 的接口一报错，返回的却是 401

出错后会转发到 /error，而 /error 没放行。把 "/error" 也加进 permitAll。

@Async、线程池里拿不到当前用户

工牌挂在 ThreadLocal 上，换了线程就没了。用 DelegatingSecurityContextExecutor 包一下线程池。

判断“登录了没有”，游客也算登录了

游客牌的 isAuthenticated() 也返回 true。要排除 AnonymousAuthenticationToken，或者用 AuthenticationTrustResolver.isAnonymous(…)。

Security 6 自己写登录接口，下一个请求又成了游客

6 里工牌不会自动存回 Session。认证成功后要调用 securityContextRepository.saveContext(…)。
