改个版本号，付款就 400 了：Spring Boot 3 到 4，编译器只抓得到一半

把交易靶场从 Boot 3.5.16 升到 4.1.2，按迁移指南改到编译通过、启动正常，付款接口 6 个请求里还是挂了 5 个（本页实测）。原因只有一行：Jackson 3 默认按 toString() 读写枚举。升级里的变化分两种：改了名的（javax → jakarta、com.fasterxml.jackson → tools.jackson、类名和 starter 改名）编译器会一处不落地报出来；名字没变、行为变了的（Jackson 默认值、旧注解没人认、三方 starter 的顺序声明失效）编译器看不见，只能靠升级前录好的请求级对照测试抓。

全景：一个请求穿过 Spring · 第 5 站（另见第 1 站）地图：J05 · Spring Boot 3 到 4：Jakarta、Jackson 3 怎么升级

①什么时候用得上：3.5 的免费维护已经停了

在全景第 5 站，这一步要解决的是：Jackson 把请求体读成 PayRequest(ALIPAY, 79800)，再把 PayResult 写回 JSON。Boot 4 把这里的 Jackson 2 整个换成了 Jackson 3。交易靶场停在 3.5 不升行不行？看维护期。

开源版的安全补丁停了，靶场要么升，要么买商业支持。直接跳 4.0 也只剩一个多月，所以目标定 4.1。升级不止换一个 Jackson，整套依赖都跳了大版本（表里是两边 BOM 里写的版本）：

②常见笨办法：改版本号，编译过了就上线

最省事的做法是把 spring-boot.version 从 3.5.16 改成 4.1.2，哪里红改哪里，编译过了就算升完。⑤ 里把这条路照走了一遍，一共撞上四道关，只有第一道是编译器拦的：

  • 能做，但不完美。改版本号本身没错，编译错误也必须一个个修。问题出在“编译通过”被当成终点：后三道关编译器根本不参与。
  • 另一种笨办法：一次全换。Boot 4、Java 25、虚拟线程、新的 JSON 格式一起上。出了 400 分不清是哪一项引起的。
  • 还有一种：一直不升。3.5 的开源补丁已经停了（①），越晚升，中间跨的版本越多。

不懂精华时的典型误用：看到一堆 400，加一行 spring.jackson.use-jackson2-defaults=true，测试全绿就收工。⑤ 实测这个开关救回了枚举和 null，但救不回流水号：旧的 @JsonSerialize 注解 Jackson 3 根本不认，开关管不到注解（④-3）。

③工具和路线：编译器带路，对照测试兜底

官方迁移指南给了几样工具，各管一段。没有哪一样能覆盖“名字没变、行为变了”的那一半，那一半要靠升级前录下的请求级对照测试。

工具它做什么管哪一关怎么用
迁移指南官方 wiki “Spring Boot 4.0 Migration Guide”，列出删掉的功能、改名的类和属性、Jackson 3 的变化全部先通读一遍，按自己用到的技术挑章节
编译器改了包名、类名、删了的 API，全部报成编译错误① 编译改版本号，跟着红线修
spring-boot-starter-classic把所有模块都拉回 classpath，像 Boot 3 那样什么自动配置都在① 编译 ② 启动过渡用：先修好 import，再换回按技术列的 starter，看缺了哪个
spring-boot-properties-migrator启动时打印改了名的配置项，并临时按新名字生效② 启动runtime 依赖，迁完删掉
OpenRewrite 配方UpgradeSpringBoot_4_0 自动改依赖和 import，里面串了 Framework 7、Security 7、Hibernate 7.1 等子配方① 编译大项目省体力；改完照样要过 ③④
use-jackson2-defaults让 Boot 4 自动配置的 JsonMapper 尽量用 Jackson 2 时代的默认值③ 请求先开着跑通，再逐项关掉；管不到注解
spring-boot-jackson2继续用 Jackson 2 做 JSON，已标弃用，以后会删③ 请求只在一时迁不动时用
请求级对照测试升级前把关键接口的请求和响应录下来，升级后逐字比对③ 请求 ④ 前端唯一能抓“行为变了”的；就是 J05 测试那个知识点要做的事

选择规则：项目小、依赖少，手改加编译器就够；模块多、三方 starter 多，先上 classic starters 和 OpenRewrite 把编译期的体力活做掉。不管哪种，第 2 步的对照测试都省不了。本页学这条“编译器带路 + 对照测试兜底”的路线，在交易靶场上走一遍。

④背后的机制：为什么有的变化会报错，有的不会

升级会坏在哪，取决于变化落在哪一层：落在名字上（包名、类名、方法签名），编译器看得见；落在运行时的选择上（默认值、认不认某个注解、自动配置的先后），编译器看不见。

先知道这些
  • Jakarta EE：原来的 Java EE（Servlet、Bean Validation、JPA 这些规范）。2017 年 Oracle 把它交给 Eclipse 基金会，改名 Jakarta EE。javax.sql、javax.crypto 是 JDK 自己的包，不在其中，永远不改。
  • Jackson 的三个 jar：jackson-core（逐个读写 JSON 记号）、jackson-databind（JSON 和 Java 对象互转，ObjectMapper 在这里）、jackson-annotations（@JsonProperty、@JsonFormat 这些注解）。
  • 自动配置看 classpath：Boot 启动时按“classpath 上有什么类、容器里有没有某个 bean”决定建哪些 bean，见 Boot 自动配置 和 249 个 bean 是谁建的。
  • 第 5 站的两道关：先是 HttpMessageConverter 里的 Jackson 把 JSON 读成对象，再是 Validator 查 @Positive 这些注解。见 Spring MVC 请求处理。

④-1 为什么要改包名：两个版本得能放进同一个 JVM

Jackson 2 到 3 删了、改了很多 API。如果包名不变，一个项目里只要有一个库还要 Jackson 2，另一个要 Jackson 3，就只能二选一：

不改包名 同名类只能留一份

改包名 Jackson 3 的选择

决定胜负的约束：大项目不可能让所有依赖同一天升级。所以 Jackson 3 宁可让每个 import 都改一遍，也要让 2 和 3 能共存（Jackson 1 → 2 时也这样改过一次：org.codehaus.jackson → com.fasterxml.jackson）。只有 jackson-annotations 留在老包名，所以 DTO 上的 @JsonProperty、@JsonFormat 两个版本都认。

javax → jakarta 的原因不一样：Oracle 交出 Java EE 时，没有允许 Eclipse 在 javax 这个命名空间下继续改规范，Jakarta EE 9 只好整体换包名。那一次 Boot 3 已经替你走完了，Boot 4 跟进的 EE 11 不再改包名。

④-2 编译器看得见的，和看不见的

右边四条有一个共同点：代码里引用的东西都还在（枚举、注解类、ObjectMapper 类、一个类名字符串），只是运行时没人再按原来的方式用它们。编译器只检查“引用的东西存不存在”，不检查“运行时选了谁”。

④-3 第 5 站里，Jackson 是怎么被整个换掉的

整条链从属性、定制器、builder、mapper 到消息转换器全换了一套类型，所以：Boot 3 写的定制器编译不过（看得见）；自己 @Bean 的 ObjectMapper 还能编译，但 MVC 只用 JsonMapper（看不见，迁移指南原话：要替换就定义 JsonMapper bean）。

新链用的是 Jackson 3 的默认值。Boot 3 自己已经改过两项（日期不写成时间戳、未知字段不报错），所以这两项升级后不变；下面四项打到了付款接口：

特性Boot 3.5 实际生效Boot 4 默认付款接口上看到的（⑤ 实测）use-jackson2-defaults
READ_ENUMS_USING_TO_STRING关开channel 只认“支付宝”，传 ALIPAY 的全部 400恢复
WRITE_ENUMS_USING_TO_STRING关开响应里 statusEnum 从 PAID 变成 已支付恢复
FAIL_ON_NULL_FOR_PRIMITIVES关开金额 null 或没传：从 Validator 的 400 变成 Jackson 的 400，错误体换了样子恢复
FAIL_ON_TRAILING_TOKENS关开JSON 后面多一段：从 200 变成 400恢复
Jackson 2 的 @JsonSerialize认不认payNo 从字符串变成数字救不回
WRITE_DATES_AS_TIMESTAMPS关（Boot 3 改的）关paidAt 两边都是 "2026-11-12T20:00:01"—
FAIL_ON_UNKNOWN_PROPERTIES关（Boot 3 改的）关多传 coupon 两边都忽略—

Jackson 3.0 发行说明里改了默认值的还有十几项（如 SORT_PROPERTIES_ALPHABETICALLY、FAIL_ON_EMPTY_BEANS、DEFAULT_VIEW_INCLUSION），java.time 支持也并进了 databind。哪些会打到你的接口，只有对照测试说得准，放到 ⑥。

④-4 模块拆分：自动配置类搬了家，三方 starter 的“排在谁后面”失效

Boot 4 把原来一个大 spring-boot-autoconfigure 拆成按技术分的小模块，模块叫 spring-boot-<技术>，包叫 org.springframework.boot.<技术>。数据源的自动配置就从 org.springframework.boot.autoconfigure.jdbc 搬到了 org.springframework.boot.jdbc.autoconfigure。

同一个 @AutoConfigureAfter 里写的是类名字符串（注解是按字节码读的，类不存在也不会报错），所以这又是一条“名字还在、没人按它办事”。修法只有一个：三方 starter 升到声明支持 Boot 4 的版本，MyBatis 是 4.x。

最少的写法

pom.xml改三处
<!-- 1. 版本 -->
<spring-boot.version>4.1.2</spring-boot.version>
<!-- 2. web 改名 webmvc（旧名还在，已弃用） -->
<artifactId>spring-boot-starter-webmvc</artifactId>
<!-- 3. 三方 starter 跟着升 -->
<artifactId>mybatis-spring-boot-starter</artifactId>
<version>4.1.0</version>
JsonConfigBoot 3 → Boot 4
// Boot 3
@Bean Jackson2ObjectMapperBuilderCustomizer tradeJson() {
  return b -> b.timeZone(SHANGHAI);
}
// Boot 4：类名、包名、builder 方法都换了
@Bean JsonMapperBuilderCustomizer tradeJson() {
  return b -> b.defaultTimeZone(SHANGHAI);
}
// 手动转 JSON：不用再 catch JsonProcessingException
String s = jsonMapper.writeValueAsString(o);

Security 7、Hibernate 7、测试切片（@SpringBootTest 不再自带 MockMvc，要加 @AutoConfigureMockMvc）这些细节放到 ⑥。

第 4 步：修。两种修法，结果不一样

A. 打开兼容开关

    到这里已经能交差了：靶场跑在 Boot 4.1.2 上，付款接口的状态码和 Boot 3 一致，流水号仍是字符串。

    已知还没处理的细节：null 和缺字段的错误体换了样子（坑 3）；Jackson 3 其他改了默认值的特性还没逐项比对（练习 3）；测试代码还没迁（坑 6）；classpath 上还挂着一份没人用的 Jackson 2（练习 1）。

    ⑥刻意练习：先认清会翻车的地方，再练怎么把它们找出来

    升级这门手艺练的是“找”：在上线前把编译器看不见的那一半找出来。先看六个坑，每个都标了它来自 ④ 的哪一条；再做五个练习，每个都写了做对了会看到什么。

    六个坑

    坑 1枚举一重写 toString()，接口就不认枚举名了← ④-3 Jackson 3 默认值实测
    现象
    传 "ALIPAY" 一律 400，错误里列出的可选值是 [微信, 支付宝]；响应里的枚举变成中文名。
    根源
    Jackson 3 把 READ_ENUMS_USING_TO_STRING、WRITE_ENUMS_USING_TO_STRING 默认打开。toString() 本来只为日志写的，现在成了接口格式。
    做法
    全局关掉这两项（⑤ 修法 B），让接口上的枚举值是一份明确的合同，不跟着 toString() 走；要中文名就另加一个字段。
    坑 2Jackson 2 的注解还能编译，但已经没人读← ④-3 两套类型实测
    现象
    payNo 从 "1987654321098765432" 变成数字；前端 JS 解析成 1987654321098765400，拿去查单查不到。服务端 200，日志干净。
    根源
    三方 SDK 把 Jackson 2 带上了 classpath，所以 com.fasterxml.jackson.databind.annotation.JsonSerialize 能编译；Jackson 3 只读 tools.jackson 包里的同名注解。兼容开关也救不回。
    做法
    DTO 上只用 jackson-annotations 里的注解（@JsonFormat(shape = STRING) 两边都认）；需要 databind 注解的，改成 tools.jackson.databind.annotation 下的；能排除 Jackson 2 就排除，让编译器替你报。
    坑 3同样是 400，错误体换了一个出口← ④-3 FAIL_ON_NULL_FOR_PRIMITIVES实测
    现象
    金额传 null：Boot 3 是 Validator 的“amountCents 必须大于 0”，Boot 4 是 Jackson 的“Cannot map null into type long”。前端按字段显示错误的逻辑失效。
    根源
    Jackson 3 默认不许把 null 塞进基本类型，请求在第 5 站的第一道关就被挡下，到不了 Validator。
    做法
    入参用包装类型加 @NotNull（Long amountCents），让“必填”统一由 Validator 判断；同时给 HttpMessageNotReadableException 一个和校验错误同样格式的全局处理。
    坑 4三方 starter 没升，报错却指向自己的 Mapper← ④-4 模块拆分实测
    现象
    OrderMapper bean 找不到，启动失败。
    根源
    MyBatis 3.0.5 的 @AutoConfigureAfter 写的是 Boot 3 的类名，Boot 4 里这个类搬了包，先后声明失效。
    做法
    升级前列出所有三方 starter（MyBatis、Nacos、Seata、springdoc……），逐个查有没有声明支持 Boot 4 的版本；没有的就是升级的阻塞项。看条件报告用 --debug。
    坑 5自己定义的 ObjectMapper bean 不生效了← ④-3 MVC 只用 JsonMapper按迁移指南
    现象
    项目里有 @Bean ObjectMapper 注册了 Long 转字符串等定制，升级后响应格式回到默认。
    根源
    Boot 4 自动配置的是 JsonMapper，消息转换器也只用它；“定义一个 ObjectMapper bean 就能替换”不再成立。
    做法
    定制写成 JsonMapperBuilderCustomizer；确实要整个替换，就定义 JsonMapper bean。
    坑 6测试一升级就红一片，或者更糟，悄悄变绿← ④-4 测试也拆了模块按迁移指南
    现象
    @MockBean 编译不过；@SpringBootTest 里注入 MockMvc、TestRestTemplate 失败；@Mock 字段是 null。
    根源
    @MockBean 在 3.4 弃用、4.0 删除；@SpringBootTest 不再自带 MockMvc 和 TestRestTemplate；暗中初始化 @Mock 的 MockitoTestExecutionListener 删了。
    做法
    换 @MockitoBean；加 @AutoConfigureMockMvc；用 Mockito 自己的 MockitoExtension；测试依赖换成按技术分的 spring-boot-starter-<技术>-test。

    迁移指南里还有几条这个靶场没碰到的：Undertow 不再支持（不兼容 Servlet 6.1）；spring-boot-starter-aop 改名 spring-boot-starter-aspectj；Spring Retry 不再由 Boot 管版本；可执行 jar 的启动脚本删了；健康检查默认带上 liveness 和 readiness。

    五个练习

    1. 找出 classpath 上的 Jackson 2 是谁带来的。mvn -pl spring/spring-boot4-upgrade -Pboot4 dependency:tree -Dincludes=com.fasterxml.jackson.core。做对了：看到 jackson-databind:2.21.x 挂在哪个依赖下面（这里是 pom 里那条模拟 SDK 的直接依赖）。
    2. 一行命令列出“看不见”的嫌疑点。grep -rn "com.fasterxml.jackson.databind" src/。做对了：boot4 能编译的代码里只剩 Model.java 那一处 @JsonSerialize；每一处这样的 import，升级后都可能被静默忽略。
    3. 二分 Jackson 3 的默认值。从 Boot 4 默认出发，每次只用 -D 关掉一项（比如 -Dspring.jackson.deserialization.fail-on-null-for-primitives=false），跑一遍 6 个请求。做对了：能写出一张“哪一项影响了哪个请求”的表，和 ④-3 的表对得上。
    4. 让 properties-migrator 替你找改名的配置。加上 spring-boot-properties-migrator（runtime），在配置里留一条 Boot 3 的旧属性名。做对了（按文档）：启动日志里有一段报告，列出旧名和新名，旧值被临时按新名生效。
    5. 拿 OpenRewrite 跑一遍，看它改了什么、没改什么。在 boot3 的一份副本上运行配方 org.openrewrite.java.spring.boot4.UpgradeSpringBoot_4_0，然后 git diff。做对了：能把改动分成“改名类”（编译器本来也能报的）和“它没碰的”，再对照 ④-2 右边那一栏，说出哪些还得靠对照测试。

    下一圈

    • 升到 Boot 4 以后打开虚拟线程：全景的“下一圈”，第 2 站的 200 线程上限没了，ThreadLocal 上的事务连接和安全上下文还成立吗。
    • Spring Framework 7 新增的东西：API 版本管理、框架内置的重试（迁移指南说 Spring Retry 正被它取代）。
    • JSpecify 空安全注解：Boot 4 全面加上了，配合 NullAway 能在编译期抓空指针。
    • Jakarta Persistence 3.2 和 Hibernate 7：交易靶场换 JPA 时要跨的另一道坎。
    • Spring Security 7 的变化：这次靶场用的 lambda 写法两边都能编译，旧的 and() 链式写法需要改。
    • 自己写 starter 怎么面对两代 Boot：迁移指南强烈不建议一个 artifact 同时支持 3 和 4。

    ↺回到 ⑤：把靶场的升级做扎实

    1. 把 6 个请求写成对照测试。在 boot3 下把每个请求的状态码和响应体录成快照（放 src/test/resources），在 boot4 下逐字比对。做对了：Boot 4 默认会报出 5 个请求的差异，修法 B 之后只剩请求 2、3、5 三处“有意的”差异。这正是 J05 测试那个知识点（待做）要展开的事。
    2. 用坑 3 的做法改入参。amountCents 改成 Long 加 @NotNull。做对了：请求 2、3 在 Boot 3 和 Boot 4 下都由 Validator 拦下，错误体一致。
    3. 删掉 pom 里模拟 SDK 的那条 Jackson 2 依赖。做对了：-Pboot4 编译失败，报的正是 Model.java 第 55 行的两处，和第 1 步的最后两条一样。坑 2 从“看不见”变成了“看得见”。

    自测

    1. 用一句话说出这一页的精华。

    升级的变化分两类：改了名的，编译器一处不落地报出来；名字没变、运行时选择变了的（默认值、认哪个包的注解、自动配置的先后），编译器看不见，只能靠升级前录好的请求级对照测试抓。

    2. “改版本号，编译过了就上线”，疼在哪？

    它只过了四道关里的第一道（②）。启动期的错（MyBatis starter）会炸但指错方向；请求期的 400 要真发请求才看得到；流水号变数字只有调用方知道，服务端零报错。

    3. 付款接口升级后 5 个请求 400，根源是哪条原理？

    ④-3：第 5 站整条 JSON 链换成了 Jackson 3 的 JsonMapper，用的是 Jackson 3 的默认值，其中 READ_ENUMS_USING_TO_STRING 默认打开，枚举按 toString() 的中文名去认，"ALIPAY" 不在可选值里。

    4. 预测：把 payNo 上的注解换成 @JsonFormat(shape = STRING)，Boot 3、Boot 4 默认、Boot 4 加兼容开关三种情况下，payNo 各是什么？

    三种都是字符串。@JsonFormat 在 jackson-annotations 里，这个包 Jackson 3 没有改名，两个版本都认（④-1 的最后一句）。⑤ 里的 payNo2 就是这样写的，四次运行都是字符串。

    5. 预测：Boot 3 项目里有一个 @Bean ObjectMapper，注册了“Long 一律输出成字符串”的模块，升到 Boot 4 并修好编译错误后，响应里的 long 字段是什么？

    数字。MVC 的消息转换器用的是自动配置的 jacksonJsonMapper（④-3 的下半条链），你那个 ObjectMapper bean 还在容器里，但没人用它。要么改成 JsonMapperBuilderCustomizer，要么定义 JsonMapper bean。

    6. 预测：同一个 Boot 4 项目，删掉把 Jackson 2 带进来的那个 SDK 依赖，坑 2 会怎样？

    从静默变成编译错误：com.fasterxml.jackson.databind.annotation 这个包不存在了（④-2 从右栏挪到左栏）。⑤ 第 1 步最后两条错误就是这个情况。

    7. 放回全景：第 5 站前后各发生了什么？Jackson 升级出了问题，整条链路会怎样？

    前面是第 4 站：DispatcherServlet 找到 OrderController#pay，拦截器 preHandle 已经放行；再往前，第 3 站已经认出用户 1024（全景里那 82 ms 的 BCrypt 照样花掉了）。后面是第 6 站：调 OrderService 的 CGLIB 代理，开事务。Jackson 在第 5 站读失败，请求以 400 退回，第 6～10 站都不走，库里没有任何变化；没有 @ExceptionHandler 时，Boot 还会转发到 /error，拦截器再走一遍（见一个 400 进了两次 DispatcherServlet）。如果出问题的是“写”的一侧，表现在第 11 站：服务端照样 200，错在调用方读到的 JSON 上，比如流水号丢精度。
