源码简化版（去掉了异步、缓存和清理）
protected void doDispatch(HttpServletRequest req, HttpServletResponse resp) throws Exception {
    HandlerExecutionChain chain = null;
    ModelAndView mv = null;
    Exception ex = null;
    try {
        try {
            req = checkMultipart(req);                                // ① 文件上传就包一层
            chain = getHandler(req);                                  // ② 查排班表：handler + 拦截器
            if (chain == null) { noHandlerFound(req, resp); return; }
            HandlerAdapter ha = getHandlerAdapter(chain.getHandler());  // ③ 找帮厨
            if (!chain.applyPreHandle(req, resp)) return;             // ④ preHandle，有 false 就收工
            mv = ha.handle(req, resp, chain.getHandler());            // ⑤ 备料 → 下厨 → 装盘
            applyDefaultViewName(req, mv);
            chain.applyPostHandle(req, resp, mv);                     // ⑥ postHandle，倒序
        } catch (Exception e) {
            ex = e;                                                   // 出了错先记下，不马上抛
        }
        processDispatchResult(req, resp, chain, mv, ex);              // ⑦ 善后或渲染，最后 ⑧ afterCompletion
    } catch (Exception e) {
        triggerAfterCompletion(req, resp, chain, e);                  // 善后也没接住：照样 afterCompletion
        throw e;                                                      // 抛给 Tomcat，转发到 /error
    }
}

善后：出了错交给谁

doDispatch 把异常交给一排 HandlerExceptionResolver，按顺序问，谁处理了就算完。拦截器、参数解析、Controller 里抛的都算，过滤器里的不算。

1ExceptionHandlerExceptionResolver

找 @ExceptionHandler：先找 Controller 自己类里的，再找 @ControllerAdvice 里的。

2ResponseStatusExceptionResolver

异常类上有 @ResponseStatus，或者抛的是 ResponseStatusException。

3DefaultHandlerExceptionResolver

Spring MVC 自己的标准异常，翻成对应的 4xx，见下表。

✕谁都不认识

抛给 Tomcat，转发到 /error。Boot 的 BasicErrorController 返回 500：浏览器看到 Whitelabel 页面，接口拿到一段 JSON。

异常状态码常见原因
HttpRequestMethodNotSupportedException405GET 打到了 @PostMapping
HttpMediaTypeNotSupportedException415@RequestBody 收到的是表单格式
HttpMediaTypeNotAcceptableException406Accept 要的格式给不了
MissingServletRequestParameterException400必填的 @RequestParam 没传
MethodArgumentTypeMismatchException400/orders/abc，abc 转不成 Long
HttpMessageNotReadableException400请求体不是合法 JSON
MethodArgumentNotValidException400@Valid 校验没过
NoHandlerFoundException / NoResourceFoundException404没有这个地址
最常用的写法：全局善后
@RestControllerAdvice
public class GlobalErrors {

    @ExceptionHandler(OrderNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)          // 不写，状态码就是 200
    public ErrorBody notFound(OrderNotFoundException e) {
        return new ErrorBody("ORDER_NOT_FOUND", e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ErrorBody invalid(MethodArgumentNotValidException e) {
        return new ErrorBody("INVALID", e.getBindingResult().getFieldErrors().toString());
    }
}
  • 拦截器的 preHandle 也在 doDispatch 的 try 里面，它抛的异常 @ControllerAdvice 接得到。
  • 过滤器在 DispatcherServlet 外面，它抛的接不到。第 01 篇、第 05 篇都碰到过这个问题。
  • 标准异常（上表）走第 3 位时，用的是 response.sendError(…)，最后由 /error 写出响应体。想统一格式，就在 @ControllerAdvice 里把它们也接住。

JDK 8 和 JDK 17：主线没变，细节变了

Boot 2 配 Spring 5，Boot 3 配 Spring 6。doDispatch 八步完全一样，变的是路径匹配和错误处理的默认值。

Spring 5 · Boot 2

JDK 8+
  • javax.servlet 包
  • 路径匹配默认用 AntPathMatcher；Boot 2.6 起默认换成 PathPatternParser，老版 Springfox 因此启动失败
  • /orders/ 也能匹配到 /orders
  • 找不到的地址，静态资源处理器直接 sendError(404)，@ExceptionHandler 接不到
  • 错误响应的 JSON 长什么样，各家自己定

Spring 6 · Boot 3

JDK 17+
  • jakarta.servlet 包
  • 默认 PathPatternParser：** 只能写在末尾，/**/*.html 这种写法启动就报错
  • 结尾斜杠不再自动匹配：/orders/ 会 404
  • 6.1 起找不到的地址抛 NoResourceFoundException，能用 @ExceptionHandler 接
  • 内置标准错误格式 ProblemDetail（application/problem+json），配 spring.mvc.problemdetails.enabled=true 打开
  • 6.1 起参数名只认编译参数 -parameters
没变的：doDispatch 八步九大组件拦截器三个方法参数解析器、返回值处理器三个异常解析器

常踩的坑

先判断卡在了哪一步：查排班表、备料、下厨，还是装盘。

@Controller 返回字符串，结果 404、模板找不到或 Circular view path

没有 @ResponseBody，字符串被当成视图名去找页面了。写接口用 @RestController。

415 Unsupported Media Type

@RequestBody 只读 JSON 这类请求体，前端发的却是表单。前端改发 JSON；或者去掉 @RequestBody，用对象直接接表单字段。

接口返回 400，Controller 里的断点根本没进

备料就失败了：缺参数、类型转不过去、JSON 写错。日志里有一行 WARN：Resolved [org.springframework.web…]，原因写在里面。

405 Method Not Allowed

地址对了，请求方法不对：GET 打到了 @PostMapping。

@ExceptionHandler 返回了错误信息，状态码却是 200

没写 @ResponseStatus，也没返回 ResponseEntity，状态码就保持默认的 200。

postHandle 里加的响应头，前端收不到

@ResponseBody 的响应在装盘时就写出去了。改用 ResponseBodyAdvice，或者在 preHandle 里加。

404 用 @ExceptionHandler 接不住

没人认领的地址被静态资源处理器（/**）接走了。Boot 2：配 spring.mvc.throw-exception-if-no-handler-found=true 并关掉 spring.web.resources.add-mappings；Boot 3.2+：接 NoResourceFoundException。

升级 Boot 3 后，结尾带斜杠的地址 404

Spring 6 不再把 /orders/ 当成 /orders。前端去掉斜杠，或者两个地址都写上。

升级后报 parameter name information not available via reflection

Spring 6.1 起，参数名只靠编译参数 -parameters。用 Boot 的 Maven / Gradle 插件会自动加；否则把名字写全：@PathVariable("id")。

第一个请求特别慢

DispatcherServlet 第一次有请求才初始化。配 spring.mvc.servlet.load-on-startup=1，启动时就做好。
