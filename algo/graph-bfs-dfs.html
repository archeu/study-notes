图的表示、BFS 与 DFS：从 1024 出发，找出所有关联账户

账户之间的关系是一张图：点是账户，边是“同设备、同 IP、互相转账”。图和树只差一点：会有环，所以遍历要多一个“见过没有”的集合，否则会绕圈。用队列一层层往外扩是 BFS，最先碰到的就是最短跳数；用栈一条路走到底是 DFS，适合找整片连通、找环。存图用邻接表，稀疏图用邻接矩阵会大到放不下。

①要解决的问题：1024 是不是一个团伙里的

在全景第 4 站，风控要判断下单的 1024 是不是在“对倒刷量”：一群账户互相买卖，把成交量做大。线索是关系：同一台设备登录过、同一个 IP、互相转过账。要回答三件事：和 1024 关联的有哪些账户（不管隔几层）、1024 和可疑账户 7777 隔几跳、是怎么关联上的（给审核员看路径）。

②朴素做法：SQL 一层层 JOIN，或者把树的遍历直接搬过来

做法疼在哪
SQL：关联表自连接一次查一层隔几层就要 JOIN 几次，层数事先不知道；每多一层结果行数成倍膨胀，同一个账户被重复带出来
把第 13 课的树遍历直接用在图上树没有环，不用记“来过没有”；图有环，2001 → 3001 → 2002 → 1024 → 2001 …… 一直绕，本机三个账户的三角形出队 1000 次还没停
邻接矩阵 boolean[n][n]20 万个账户就是 400 亿格，按位存也要 5 GB；而每个账户平均只连着 10 个
  • 树的遍历之所以简单，是因为“每个节点只有一条路能到”。图里一个账户可能从好几条路被碰到。
  • 缺的那一块：一个 visited 集合（或者距离数组），第一次碰到就记下，以后再碰到直接跳过。每个点只处理一次，每条边只看两次，O(点 + 边)。
不懂精华时的典型误用：BFS 时“出队才标记已访问”。同一个账户在出队前可能被好几个邻居都塞进队列，本机 20 万账户的图上多入队了 80 万次（坑 2）。正确的是入队时就标记。

③几种思路：图怎么存，怎么走

存法内存查“u、v 连着吗”遍历 u 的邻居适合
邻接矩阵O(n²)O(1)O(n)点少、边很密（几千个点以内）
邻接表 Map<点, List<点>>O(n + m)O(度数)O(度数)图会变、点的 id 不连续
CSR：offset[] + to[]O(n + m)，最紧凑O(度数)O(度数)，连续内存图建好就不变、点编号成 0..n−1：夜间离线分析
边列表 [(u, v)]O(m)O(m)O(m)并查集（第 17 课）、最小生成树，只需要一条条看边
走法用什么得到什么
BFS 广度优先队列按跳数一层层扩：最先到达的就是最少跳数（边没有权重时）
DFS 深度优先栈（或递归）一条路走到底再回头：连通性、找环、拓扑排序（第 18 课）
并查集两个数组只问“是不是一伙的”，边一条条来，几乎 O(1)（第 17 课）

本页学邻接表上的 BFS 和 DFS：在线风控用 HashMap 邻接表（账户随时新增）；夜间批量分析把图压成 CSR，内存省一个数量级，BFS 快好几倍。要不要“隔几跳”决定用 BFS 还是 DFS：要就 BFS，只要“在不在一片”两个都行。

④关键洞察：树的遍历 + 一个 visited；队列给出最短跳数

先知道这些
  • 队列、栈：先进先出、后进先出。第 5 课 栈、队列和环形数组。
  • 树的 DFS：递归或显式栈，深度受线程栈限制。第 13 课 递归与二叉树遍历。
  • 度数：一个点连着几条边。所有点的度数加起来 = 2 × 边数（无向图）。

洞察 1 · visited：第一次碰到就记下，之后跳过

图的遍历和树的遍历只差这一个集合。它保证每个账户只进一次队列（或栈）、只处理一次；每条边在两端各被看一次。所以无论图里有多少环，总代价都是 O(点数 + 边数)。记在哪一刻也有讲究：BFS 在入队时记，DFS 用显式栈时在出栈时记（同一个点可能被压好几次，第一次弹出才算）。

洞察 2 · BFS：队列让“近的先处理”，第一次到达就是最短跳数

队列先进先出：离起点 1 跳的全部出队之前，2 跳的不会出队。所以一个账户第一次被发现时，它的跳数就是最小跳数，之后不可能找到更短的路。顺手记下“是谁发现了它”（parent），从终点沿 parent 往回走，就是一条最短关联路径。

洞察 3 · DFS：把队列换成栈，就变成“一条路走到底”

容器同一张图从 1024 出发的访问顺序（⑤ 实测）擅长
BFS队列1024 2001 2002 3001 3002 4001 7777：按层最少跳数、最短关联路径、“三跳以内的都拦下”
DFS栈 / 递归1024 2001 3001 2002 3002 7777 4001：先钻到底整片连通、有没有环、拓扑排序（第 18 课）、回溯（第 20 课）

代码几乎一样，只是 poll() 换成 pop()。DFS 的递归版就是第 13 课的树遍历加一行 if (!seen.add(u)) return;，深度 = 当前路径长度：一条 10 万个账户的转账链，递归 DFS 本机直接栈溢出（坑 3），全景第 4 站的“常出的事”就是这个。

机制 · CSR：用前缀和把邻接表压成两个数组

为什么这样设计：BFS，还是 DFS

BFS（队列）

  • 第一次到达就是最少跳数，能“只看三跳以内”
  • 队列在堆上，不怕深
  • 队列可能很宽：一个热门 IP 下面挂着几万个账户，一层就全进队列

DFS（栈）

  • 内存只和当前路径长度有关（显式栈时是待处理的点）
  • 天然适合“回溯”“找环”“后序”的问题
  • 递归版深度 = 路径长度，长链会栈溢出
  • 找到的路不一定最短
决定胜负的约束：要不要“距离”。风控的“三跳以内”“最短关联路径”只有 BFS 给得出来；只问“是不是一片”时两者都行，选不会栈溢出的那个（BFS 或显式栈 DFS）。如果边是一条条源源不断来的、又只问“是不是一伙”，连图都不用建，用第 17 课的并查集。
BFS 的骨架DFS 把 offer/poll 换成 push/pop
Map<Long, Integer> dist = new HashMap<>();           // 兼做 visited
Deque<Long> q = new ArrayDeque<>();
dist.put(src, 0); q.offer(src);
while (!q.isEmpty()) {
    long u = q.poll();
    for (long v : adj.get(u)) {
        if (dist.containsKey(v)) continue;            // 见过就跳过
        dist.put(v, dist.get(u) + 1);                 // 入队时就标记
        parent.put(v, u);
        q.offer(v);
    }
}

public List<Long> dfs(long src) {                 // 显式栈，不怕深
    List<Long> order = new ArrayList<>();
    Set<Long> seen = new HashSet<>();
    Deque<Long> st = new ArrayDeque<>();
    st.push(src);
    while (!st.isEmpty()) {
        long u = st.pop();
        if (!seen.add(u)) continue;                   // 出栈时标记：第一次弹出才算
        order.add(u);
        List<Long> l = nb(u);
        for (int i = l.size() - 1; i >= 0; i--)       // 倒着压，弹出时按原顺序
            if (!seen.contains(l.get(i))) st.push(l.get(i));
    }
    return order;
}

public static List<Long> path(Map<Long, Long> parent, long src, long dst) {
    List<Long> p = new ArrayList<>();
    for (Long x = dst; x != null; x = x == src ? null : parent.get(x)) p.add(x);
    Collections.reverse(p);                           // 从终点往回走，再倒过来
    return p;
}

⑥边界和变体

第一圈 · 注意事项

1忘了 visited，在环上绕圈实测← ④ 洞察 1
现象
三个账户互相转账（一个三角形），不记 visited 的 BFS 出队 1000 次还没停，队列里还堆着 1001 个。真实图上就是线程卡死、内存涨爆。
根源
图有环，一个点可以从多条路被再次碰到；树没有环，所以树的遍历不需要这一步。
做法
遍历前先建 visited（或距离数组），碰到见过的就跳过。
2BFS 出队时才标记实测← ④ 洞察 1
现象
20 万账户的图：出队时才标记，入队 999,996 次；入队时标记只要 199,990 次。结果一样，但队列大了 5 倍，慢、费内存。
根源
一个账户在出队之前，可能被它的好几个邻居先后“发现”，每次都塞进队列。
做法
BFS 入队时标记。显式栈 DFS 则相反，出栈时标记才能得到和递归一样的顺序（或者入栈时标记，接受顺序不同）。
3递归 DFS 走长链，栈溢出实测← ④ 洞察 3
现象
10 万个账户首尾相接的转账链，递归 DFS StackOverflowError；显式栈 DFS 访问完 100,001 个。
根源
递归深度 = 当前路径长度。和第 13 课退化树、第 4 课递归反转链表是同一回事。
做法
图的规模由外部数据决定，一律用显式栈或 BFS。
4超级节点把全站连成一片← ④ 为什么这样设计
现象
按“同 IP”连边，一个公司出口 IP、一个运营商 NAT、一个公共 WiFi 下面挂着几万个账户，1024 一跳就“关联”上了整个城市；⑤ 的随机图里 20 万账户 199,991 个连成一片。
根源
BFS 不区分“强关系”和“弱关系”，一条边就算连上；度数极高的点让队列一层就爆满。
做法
建图时剔除度数超过阈值的点（或把它们降权）；限制跳数（只看三跳以内）；关系类型分开看。这是业务规则，不是算法能替你决定的。
5有方向的关系当成无向的存← ④ 存法
现象
“A 给 B 转过钱”存成无向边，追资金流向时把“收款方”和“付款方”混在一起，查出来的链路方向是反的。
根源
无向图每条边在两端各存一次；有向图只在起点存一次（要反查就再建一张反向图）。
做法
先想清楚关系有没有方向：同设备、同 IP 无向；转账、邀请、依赖（第 18 课）有向。

第二圈 · 使用规范

  • 先写 visited，再写遍历：防坑 1。BFS 入队时标记，防坑 2。
  • 不写递归 DFS 处理外部数据的图：防坑 3。
  • 给遍历加上限：最大跳数、最大访问数、单点最大度数：防坑 4，也防恶意构造的数据拖垮风控。
  • 离线大图用 CSR，在线小图用邻接表：前者省内存、快，后者能随时加边。
  • 边的方向写进类型或变量名：payTo、paidBy，防坑 5。

第三圈 · 变体和深处

双向 BFS：两头一起找

只问 1024 和 7777 隔几跳时，从两头各做 BFS，每次扩展较小的那一边，碰头就停。每层扩张 b 倍时，单向要看约 bd 个点，双向约 2·bd/2 个。“单词接龙”（LC 127）就是这么过的。

多源 BFS：离任何一个黑名单账户几跳

把所有黑名单账户一开始都放进队列（跳数 0），一次 BFS 就算出每个账户离“最近的黑名单”有几跳，不用对每个黑名单各跑一次。“腐烂的橘子”（LC 994）、“01 矩阵”（LC 542）是同一个套路。

连通分量和二分图

对每个没访问过的点跑一次 BFS / DFS，跑了几次就有几个团伙（LC 200 岛屿数量）。BFS 时给相邻的点涂相反的颜色，涂不下去就说明有奇数长度的环，不是二分图（LC 785）：比如“买家、卖家两类账户只能互相成交”的检查。

图数据库

关联分析做成常态时，Neo4j、NebulaGraph 这类图数据库把邻接关系直接存成指针，“三跳以内”是一条查询语句。底下做的仍然是 BFS / DFS，只是数据放在了数据库里、带索引和分布式。

面试官会怎么问

BFS 和 DFS 的时间、空间复杂度？

邻接表上都是 O(V + E) 时间。空间：BFS 的队列最坏 O(V)（某一层很宽），DFS 的栈最坏 O(V)（一条很长的路）；递归 DFS 还受线程栈限制。

为什么 BFS 能求最短路径，DFS 不能？

只在边没有权重时成立：BFS 的队列保证按距离从小到大处理，第一次到达就是最短。DFS 先钻到底，第一次到达可能绕了远路。边有权重就要 Dijkstra（第 18 课）。

岛屿数量（LC 200）怎么做？

网格就是图：每个格子是点，上下左右是边。遍历每个格子，碰到没访问过的陆地就计数加一，并用 BFS / DFS 把整座岛标记掉。也可以用第 17 课的并查集。

下一圈

  • 并查集：边一条条来、只问“是不是一伙”时，比每次 BFS 快得多（第 17 课）。
  • 有向图上的 DFS：拓扑排序、找环（第 18 课）。
  • 带权的最短路径：Dijkstra 是“用堆代替队列”的 BFS（第 18 课）。
  • 回溯：DFS + 撤销选择（第 20 课）。

自测

1. 用一句话说出这一页的精华

图的遍历 = 树的遍历 + visited；用队列一层层扩是 BFS，第一次到达就是最少跳数；用栈一条路走到底是 DFS；稀疏图用邻接表（离线压成 CSR），别用矩阵。

2. 把树的遍历直接用在图上，痛点在哪？

图有环，同一个点会从多条路被反复碰到，不记 visited 就绕圈不停。

3. BFS 为什么入队时标记？是哪条原理？

一个点出队前可能被多个邻居发现；入队时标记保证每个点只进队一次，O(V + E) 才成立。

从 ④ 洞察 1 推出。

4. 预测：在 ⑤ 的图里加一条边 1024—7777，再做 BFS，跳数表和 7777 的路径怎么变？

7777 变成 1 跳，路径 [1024, 7777]。2001、2002、7777 同在第 1 层；3001、3002 仍是 2 跳；4001 从 3 跳变成 2 跳（经 7777）。

从 ④ 洞察 2 推出：跳数 = 最短路径上的边数。

5. 预测：同一张图，BFS 的队列最长和 DFS 的栈最深，各在什么形状的图上最大？

BFS 怕“宽”：星形图（一个点连着所有点），第一层就把 n − 1 个点全塞进队列。DFS 怕“深”：一条长链，栈（或递归）有 n 层。风控里的超级节点就是星形，转账链就是长链。

从 ④ 为什么这样设计推出。

6. 放回全景：第 4 站前后各发生了什么？关联分析出问题，整条链路会怎样？

前面是第 3 站把订单按到达顺序交给后面，后面是第 5 站撮合。风控的关联分析在下单的同步路径上时：遍历绕圈（坑 1）或碰上超级节点（坑 4），这一单就卡住，入口队列积压，所有用户的下单延迟上升；漏判（只看一跳）让对倒刷量的团伙放行，成交量被做假。所以真实系统常把图分析放到异步或离线，同步路径只查预先算好的“团伙编号”（第 17 课）。

档位：标准。本机跑过（2026-11-18，2 核 Neoverse-N1 虚机，OpenJDK 17.0.21，--release 8 编译，JOL 0.17）：⑤ 的 BFS 每一步、跳数、最短路径、两种 DFS 顺序，20 万账户 / 100 万边的两种存法内存和 BFS 耗时，⑥ 坑 1～3 的现象。按定义推出、没有单独实测：坑 4、5，双向 BFS 的规模估算。
