①什么时候用得上：45 分钟里，前 5 分钟决定方向

②常见笨办法

  • 按题号刷、背答案：刷了 300 道，换个说法就认不出。记住的是题面，不是信号。
  • 看到题就写暴力，写完再想优化：n = 10⁵ 的题，暴力 O(n²) 是 10¹⁰，优化不是改几行，是换算法。
  • 只认一个关键词：看到“连续子数组”就上滑动窗口。数组里有负数时，窗口扩大和不一定变大，滑动窗口的前提没了（下面 ⑤ 第 7 组）。
  • 要练的是：从题面抽出“规模、问什么、有什么性质”三件事，再对照结构能保证的东西。
不懂精华时的典型误用：把“题型”当标签背，“看到 Top K 就用堆”。Top K 用堆是因为堆的不变式“堆顶总是当前第 K 大”，题目一旦要求“前 K 个按出现顺序”，这个不变式就不够了。

③工具和路线：三步认题

第 1 步 · 看规模，定复杂度上限

n 的量级能接受的复杂度多半是
≤ 20O(2ⁿ)、O(n!) 的一小部分回溯、状态压缩（第 20 课）
≤ 500O(n³)区间 DP、三重循环
≤ 5000O(n²)二维 DP（第 22 课）、两两比较
10⁵ ～ 10⁶O(n log n) 或 O(n)排序、堆、二分、哈希、双指针、前缀和、单调栈
≥ 10⁸ 或 n 本身是一个数（如 10⁹）O(log n)、O(√n)、O(1)二分答案、数学（第 0 课）

按“每秒约 10⁸ 次简单操作”的保守口径。本机实测（⑤）：1 亿次简单循环约 160 ms，100 万个 int 排序约 100 ms，比口径快几倍，但 Java 有对象、有缓存未命中时，这个余量很快就用完。口径的由来见 第 3 课。

第 3 步 · 用不变式对答案

选出一个候选后问一句：这个结构一直保证的那件事，是不是正好回答题目问的？是，就写；不是（比如数组有负数，滑动窗口“扩大和变大”不保证），换下一个候选。

④背后的机制：每个结构都在守一条不变式

一张图：题目问什么 → 哪个结构的不变式正好回答它

为什么“不变式”比“关键词”可靠

按不变式认题

  • 题面换了说法也认得出：“过去 60 秒最高价”和“滑动窗口最大值”是同一条不变式
  • 能判断前提是否成立：数组有负数，滑窗的单调性就不成立
  • 代价：要真的懂每个结构，而不是背模板

按关键词认题

  • 快，熟题有效
  • 题面一变就认不出；关键词相同、前提不同的题会认错
决定胜负的约束：面试题的题面是故意包装过的，“订单簿积压”“温度”“股票”说的都是同几类结构。能穿透包装的，只有“这个结构保证什么”这一层——也就是前 24 课 ④ 里每一课都讲的那条不变式。

走一道：1801 积压订单，就是第 5 站本身

  1. 1 规模订单数 ≤ 10⁵ → 要 O(n log n)，每单只能花 O(log n)。
  2. 2 信号买单来了要和“卖簿里最便宜的”比，卖单来了要和“买簿里最贵的”比，而且簿子一直在变：动态取最值。
  3. 3 对不变式小顶堆保证“堆顶是最便宜的卖单”，大顶堆保证“堆顶是最贵的买单”，进出都是 O(log n)。正好。
  4. 4 边界一张大单可能吃掉好几档：用 while 循环吃到价格不够或数量用完；总数要对 10⁹+7 取模，累加用 long（第 1 课）。

for (int[] o : orders) {
    int price = o[0], amount = o[1];
    if (o[2] == 0) {                                     // 买单
        while (amount > 0 && !sell.isEmpty() && sell.peek()[0] <= price) {
            int[] top = sell.peek(); int d = Math.min(amount, top[1]);
            amount -= d; top[1] -= d; if (top[1] == 0) sell.poll();
        }
        if (amount > 0) buy.offer(new int[]{price, amount});
    } else { /* 对称 */ }
}

⑥刻意练习

实验台：看题认招

14 道题，题面是按公开题意重新写的短描述。每题先选，再看信号和对应的课；做完一轮，下面列出认错的课号，回去重看那一课的 ④。

由易到难的五个练习

  1. 只看规模：从 ⑤ 的表里随便挑 5 道题，去题库看数据范围，只写出“最多能接受的复杂度”。做对了：每道题的标准解法都不超过你写的那个。
  2. 只说信号：同样 5 道题，每道用一句话说出“题目里哪句话让你想到这个结构”。做对了：那句话能换成 ③ 信号表里的某一行。
  3. 一题多解：215 第 K 大，分别用排序、堆、快速选择写，说出各自的复杂度和什么时候选哪个。做对了：能说出“流式数据只能用堆”。
  4. 反向：从结构出题：挑一个结构（比如单调栈），给全景的某一站编一道新题。做对了：别人看题能认出是单调栈，而且暴力解会超时。
  5. 限时整题：每天一道中等题，25 分钟内写完并通过；超时就看题解，第二天不看题解重写一遍。做对了：一周后同一道题 15 分钟内写完。

自测

1. 用一句话说出这一页的精华

认题三步：看规模定复杂度上限，找信号词，用结构的不变式对答案；关键词只是线索，不变式才是判断依据。

2. 按题号刷题、背答案，差在哪？

记住的是题面，换个包装就认不出；也没练过“判断前提成不成立”，同样的关键词会认错。

3. 560 和为 K 的子数组为什么不能用滑动窗口？

数组有负数，窗口扩大和不一定变大、缩小也不一定变小，滑窗赖以移动指针的单调性不成立；用前缀和 + 哈希表：区间和 = 两个前缀和之差，数“前面有几个前缀和等于当前减 K”。

4. 预测：一道题 n ≤ 20，问“把这 n 个任务分给两台机器，让完成时间尽量接近”，最可能是哪类解法？

n ≤ 20 允许 2ⁿ ≈ 100 万：直接枚举每个任务去哪台（回溯或二进制枚举）。如果 n 到几百、任务时长不大，就是“分成两半、和尽量接近”的 0-1 背包。

从 ③ 第 1 步（规模）和第 22 课的背包推出。

5. 预测：“设计一个结构，支持插入、删除、随机返回一个元素，都 O(1)”，用什么？

数组 + 哈希表：数组存元素（随机取下标 O(1)），哈希表存“元素 → 数组下标”；删除时把要删的和数组最后一个交换，再删末尾，哈希表里更新被挪动那个的下标。

从 ④ 图里“设计”一栏和第 24 课第三圈“O(1) 找到 + O(1) 维护顺序”推出。

6. 放回全景：讲一遍第 5 站到第 6 站——那张买单进来以后，用了哪几课的东西？

第 5 站：卖簿是按价格的堆或 TreeMap（第 6、14 课），取最低价 100.50 成交 1 手；第 6 站：剩下的 1 手挂进 101.00 那一档，同价位按时间排队的是链表（第 4 课），订单号 → 节点用哈希表（第 8 课），撤单时 O(1) 摘下。整个过程价格用 long 存分（第 1 课）。

档位：标准。本机跑过（2026-11-21，2 核 Neoverse-N1 虚机，OpenJDK 17.0.21，--release 8 编译）：⑤ 的 1801 两个示例和全景那一单、三种循环的耗时。按公开资料：LeetCode 题号和题名（中文站），1801 两个示例的答案 6、999999984 来自题目描述，本机输出与之一致；题面在实验台里是重写的短描述，没有照抄原题。“每秒 10⁸ 次”是常用的保守口径，不是本机测量值。
