前缀和与差分：任意时间段成交量 O(1)

先花一遍 O(n) 把“从开头到第 i 秒的合计”存下来，之后任意一段的合计就是两个前缀相减：P[to] − P[from]，一次减法。差分是它的反过来：要给一段区间整体加一个数，只改两个端点，最后做一遍前缀和就还原出每个位置的值。一个把“区间查询”变 O(1)，一个把“区间修改”变 O(1)。

①要解决的问题：运营随口一问，任意时段的成交量

在全景第 7 站，行情模块按秒把成交量累计成桶，一天 86400 个桶。运营、风控、客户的查询都是“从几点几分到几点几分，成交了多少”，起止随便给，一秒可能来几千个。还有一个反方向的问题：每张挂单活在“挂出 → 成交或撤单”这一段时间里，想知道每一秒盘口上有多少张挂单，找出峰值。

②朴素做法：每次问都扫一遍，每张单都逐秒加

做法一次的代价疼在哪
区间查询：从 from 扫到 toO(区间长度)问一天里的大段，每次几万次加法；本机 100 万次查询 10.5 秒
区间修改：每张挂单逐秒 +1O(区间长度)几十万张单 × 几千秒 = 十亿次以上
滑动窗口（第 11 课）O(1) 摊还只能沿时间往前滑，问不了“任意一段”
  • 每次查询都把同样的秒桶重新加一遍：[09:00, 10:00) 和 [09:00, 10:01) 只差一秒，却各算了 3600 次。
  • 缺的那一块：把“从开头加到这里”的结果存起来，相邻的查询共享同一批加法。这就是前缀和，用 O(n) 空间换掉每次的 O(n) 时间。
不懂精华时的典型误用：数据一直在变（每秒都有新成交写进旧的桶、或者修正历史数据）还用静态前缀和，每改一个桶就要把它后面的前缀全部重算，O(n)。这时该换树状数组（第三圈）。前缀和适合“写完就不改、反复查”的数据，比如收盘后的全天行情。

③几种思路：数据改不改，决定选谁

结构查一段的合计改一个位置给一段整体加适合
原数组，每次扫O(n)O(1)O(n)查得很少
前缀和O(1)O(n)，后面全重算O(n)写完不改、反复查：收盘后的全天行情

本页学前缀和与差分：它们是一对互逆的操作，代码各三行，覆盖了“只查不改”和“只改不查”这两种最常见的情况。边改边查的树状数组放在第三圈，只讲它为什么是 log n。

④关键洞察：一段 = 两个前缀相减；整段加 = 两个端点各改一下

先知道这些
  • 左闭右开：本页的区间都写成 [from, to)，和第 9 课的二分、第 7 课的时间窗口一致。
  • 求和符号：P[i] = a[0] + … + a[i−1]，第 0 课 求和。

洞察 1 · P 多一格，P[0] = 0，sum[from, to) = P[to] − P[from]

洞察 2 · 差分：给 [l, r) 整体加 v，只要 D[l] += v、D[r] −= v

差分数组 D[i] = a[i] − a[i−1] 记的是“从第 i 格开始，比前一格多了多少”。给一段整体加 v，段内相邻格之间的差不变，只有两头变了：进入这段的地方多了 v，离开这段的地方少了 v。所有修改打完，对 D 做一遍前缀和，就还原出 a。下面用 5 张挂单算每秒挂单数：

洞察 3 · 前缀和 + 哈希：合计恰好为 K 的段有几个

一段 [l, r) 合计为 K，等价于 P[r] − P[l] = K，也就是 P[l] = P[r] − K。从左往右扫，用一个 HashMap<前缀值, 出现次数> 记下之前出现过的前缀：每到一个 r，之前有几个前缀等于 P[r] − K，就有几段以 r 结尾、合计为 K。有负数也成立，因为这里不需要单调性，只需要相减。

为什么这样设计

前缀和：预先算好，相减即得

  • 查询 O(1)，任意顺序、任意区间
  • 能处理负数：靠的是减法可逆，不是单调
  • 多 n + 1 个 long；改一个元素，后面的前缀全要改

每次现算（或滑动窗口）

  • 不用额外空间，数据可以随时改
  • 任意区间查询 O(n)
  • 滑动窗口只能单向滑，要求非负
决定胜负的约束：加法有逆运算（减法），所以“一段”可以由“两个前缀”算出来。最大值没有逆运算，max[l, r) 不能由两个前缀最大值相减得到，所以区间最大值要第 7 课的单调队列或稀疏表。判断能不能用前缀和，先问这个运算能不能“减回去”：加法、异或、乘法（非零）可以，最大值、最小值、gcd 不行。
三行前缀和，三行差分细节放到 ⑥
// 前缀和：长度 n + 1，P[0] = 0
long[] P = new long[n + 1];
for (int i = 0; i < n; i++) P[i + 1] = P[i] + a[i];
long sum = P[to] - P[from];                  // [from, to)

// 差分：长度 n + 1，打完再还原
int[] D = new int[n + 1];
D[l] += v; D[r] -= v;                        // [l, r) 整体 + v
for (int i = 0, run = 0; i < n; i++) a[i] = run += D[i];

JDK 里有现成的吗

有一个：Arrays.parallelPrefix(long[], LongBinaryOperator)，原地把数组变成前缀和，多核时并行算（JDK 8 起）。传 Long::sum 就是前缀和，传 Math::max 是前缀最大值。它不会帮你多留 P[0] = 0 那一格，相减时要自己处理 from = 0。

⑥边界和变体

第一圈 · 注意事项

1前缀和数组少开一格，下标差一← ④ 洞察 1
现象
P 开成 n 格、P[i] = a[0..i]（含 i），查 [from, to] 就得写 P[to] − P[from − 1]，from = 0 时越界，于是到处加 if。
根源
“前 i 个的合计”需要 i = 0 到 n 共 n + 1 个值；少一格，就有一个边界情况要特判。
做法
固定写法：P 长度 n + 1，P[0] = 0，区间左闭右开，sum = P[to] − P[from]，没有特例。
2前缀和用 int实测← ④ 洞察 1
现象
每秒 3 万手，全天 86400 秒：int 前缀和最后一格是 −1702967296，long 是 2592000000。有意思的是 [09:00, 10:00) 用 int 相减仍然得到正确的 108000000。
根源
前缀和是整天累加的，比任何一段都大得多，先溢出的是它。int 加减是模 232 的运算，只要真正的差能放进 int，溢出的两个数相减会“绕回来”变对；差本身超过 21 亿就真错了。别依赖这个巧合。
做法
前缀和一律 long。成交额（分 × 手）累加更快，必要时 Math.addExact。
3前缀和 + 哈希，忘了先放 {0: 1}实测← ④ 洞察 3
现象
净流入 [3, −1, −2, 5, −3, 3, 0] 里合计为 0 的段：漏了空前缀数出 4 个，正确是 5 个，少的是从开头起的 [3, −1, −2]。
根源
从下标 0 开始的段，对应的“左边那个前缀”是 P[0] = 0。它不是哪个元素加出来的，要事先放进去。
做法
循环前 seen.put(0L, 1)；求“最长一段”时放 {0: −1}（记位置而不是次数）。
4金额用 double 做前缀和实测← ④ 洞察 1
现象
100 万笔、每笔 0.1 元手续费，最后 10 笔用前缀相减 = 1.000000000058208，不是 1.0。
根源
0.1 在二进制里存不准（第 1 课），累加 100 万次以后前缀本身已经很大，两个大数相减，误差留在了结果里。
做法
金额用 long 存“分”或“厘”；非要小数用 BigDecimal，但前缀和数组会很重。
5数据还在变，用了静态前缀和← ④ 为什么这样设计
现象
盘中每秒都有新成交补进当前桶，偶尔还有延迟到达的成交改历史桶，每改一次就重建前缀和，CPU 打满。
根源
改 a[i] 会影响 P[i+1..n] 全部，O(n)。
做法
只追加不改历史：只更新最后一格前缀，O(1)；要改历史：树状数组（第三圈），查和改都 O(log n)。
6差分的结束点放错一格← ④ 洞察 2
现象
挂单在第 4 秒撤掉，写成 D[5]−−，第 4 秒多数了一张；或者 D 只开 n 格，结束在最后一秒的单越界。
根源
差分里 −v 放在“第一个不再包含”的位置，也就是左闭右开的 r。
做法
区间一律 [start, end)，D 开 n + 1 格，D[start] += v; D[end] −= v。

第二圈 · 使用规范

  • P 长度 n + 1，P[0] = 0，区间 [from, to)：防坑 1、坑 6，和第 9 课的二分同一套约定。
  • 前缀和、累加器一律 long，金额存整数：防坑 2、坑 4。
  • 写清这份前缀和对应哪一刻的数据：比如“截至 15:00 收盘”，防坑 5 里拿旧前缀答新问题。
  • 先问运算能不能减回去：能才用前缀和；最大值、最小值用第 7 课的结构。

第三圈 · 变体和深处

二维前缀和：价格 × 时间的热力图

S[i][j] = 左上角 i × j 那块的合计。任意矩形 = S[r2][c2] − S[r1][c2] − S[r2][c1] + S[r1][c1]（容斥：减两次的那块加回来）。比如“10:00～10:30、价格 100～101 之间成交了多少”。二维差分同理，四个角各改一下。

树状数组：边改边查，O(log n)

每个格子 T[i] 管一段长度为 i & −i（i 的最低位 1）的合计。查前缀：i −= i & −i 往前跳；改一格：i += i & −i 往后跳，都只跳 log n 次。十几行代码，常数比线段树小。

前缀和 + 单调队列：有负数的最短段

第 11 课坑 1 的那道题（LC 862）：对每个 r，要找最大的 l 使 P[r] − P[l] ≥ K。在 P 上维护一个递增的单调队列（第 7 课）：队头满足就弹出并记答案，队尾比 P[r] 大的也弹掉（它们“被压住”了）。O(n)。

前缀异或、前缀计数

异或的逆运算是它自己：xor[l, r) = X[r] ^ X[l]。“前缀里有几个买单”也是前缀和：把买单记 1、卖单记 0。“买卖单数相等的最长一段”：卖单记 −1，就变成“合计为 0 的最长段”，用 ④ 的前缀和 + 哈希。

面试官会怎么问

和为 K 的子数组个数（LC 560），为什么不能用滑动窗口？

元素可以是负数，“窗口变长合计不减”不成立。用前缀和 + 哈希：P[r] − P[l] = K ⇔ P[l] = P[r] − K，扫一遍数之前出现过几次，O(n)。别忘了 {0: 1}。

前缀和和差分是什么关系？

互逆：差分数组做前缀和得到原数组，原数组做差分得到差分数组。前缀和让“区间求和”变 O(1)，差分让“区间加”变 O(1)，就像积分和微分。

区间最大值能用前缀和吗？

不能，最大值没有逆运算，max[l, r) 不能由两个前缀最大值算出来。静态数据用稀疏表 O(1) 查，动态用线段树 O(log n)，滑动窗口用单调队列。

下一圈

  • 线段树：区间加、区间求和、区间最大值都 O(log n)，懒标记怎么下推。
  • 扫描线：把差分推广到“很多矩形的面积并”“会议室最少几间”（LC 253），按端点排序后扫一遍。
  • 时序数据库的降采样：按分钟、小时预聚合，本质是分层的前缀和（见可观测性那几页）。

自测

1. 用一句话说出这一页的精华

先存下“从开头到这里”的合计，任意一段就是两个前缀相减，O(1)；差分反过来，给一段整体加只改两个端点，最后做一遍前缀和还原。前提是运算能减回去。

2. 每次扫一遍的痛点是什么？滑动窗口为什么也不行？

每次扫把同样的加法重复做，O(区间长度)；滑动窗口只能沿一个方向滑，回答不了乱序的任意区间。

3. 为什么前缀和能处理负数，第 11 课的滑动窗口不能？

前缀和靠的是“减法可逆”，和元素正负无关；滑动窗口靠的是“窗口变长合计不减”的单调性，有负数就不成立。

从 ④ 为什么这样设计推出。

4. 预测：⑤ 的挂单数据里再加一张 [0, 10) 的挂单，diff 和每秒挂单数怎么变？

D[0] += 1、D[10] −= 1，其他格不变；还原后每一秒都多 1：[1, 2, 3, 4, 3, 3, 2, 3, 2, 1]，峰值仍在第 3 秒，4 张。D[10] 那一格就是为这种“一直活到最后”的单留的。

从 ④ 洞察 2 推出。

5. 预测：能用两个前缀相减算出“[3, 7) 秒里的最高成交价”吗？

不能。最大值没有逆运算，前 7 秒的最高价和前 3 秒的最高价放在一起，推不出中间那段的最高价（中间那段可能整体都比前 3 秒低）。要用稀疏表或第 7 课的单调队列。

从 ④ 为什么这样设计推出。

6. 放回全景：第 7 站前后各发生了什么？前缀和错了，整条链路会怎样？

前面是第 6 站挂单撤单（差分算的每秒挂单数就来自这里），后面是第 8 站查询：运营查任意时段成交量，直接读第 7 站建好的前缀和。前缀和溢出或差一，查询结果全天都错，而且错得悄无声息；第 12 站回测拿这些成交量做策略，结论也会偏。撮合本身不受影响。

档位：标准。本机跑过（2026-11-18，2 核 Neoverse-N1 虚机，OpenJDK 17.0.21，--release 8 编译）：⑤ 的前缀和、差分、前缀和 + 哈希输出，100 万次查询的扫描与前缀和对比，⑥ 坑 2、3、4 的现象。按 JDK 源码核对：Arrays.parallelPrefix（JDK 8 起）。按定义推出、没有单独实测：坑 1、5、6，树状数组和二维前缀和。
