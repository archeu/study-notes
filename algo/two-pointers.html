双指针与滑动窗口：每个指针只往前走

两层循环慢，是因为内层每次从头再来。如果能证明“左端往右挪以后，右端不需要往回退”，两个指针就都只往前走，各走 n 步，O(n²) 变 O(n)。这条“不用回头”的理由要靠单调性：成交量都非负，窗口变长合计只会变大。理由不成立时（有负数），双指针就会给出错答案。

①要解决的问题：一段连续成交，什么时候算“放量”

在全景第 7 站，行情要实时给出“过去 60 秒成交量”；风控还要找“最短的一段连续成交，合计超过 K 手”，越短说明放量越猛，可能是有人在砸盘。第 10 站的对账，排好序以后要两份流水一起往前走。这三件事都是“两个下标在一个数组上移动”。

②朴素做法：每个起点往后加

两层循环每个 l 都从头加起
for (int l = 0; l < n; l++) {
    long sum = 0;
    for (int r = l; r < n; r++) {               // 每换一个起点，r 回到 l 重新加
        sum += qty[r];
        if (sum >= k) { best = Math.min(best, r - l + 1); break; }
    }
}
  • 起点从 l 挪到 l + 1，内层把 [l + 1, r] 又加了一遍：上一轮已经知道的合计被扔掉了。
  • 窗口平均要 m 笔时是 O(n·m)；本机 10 万笔、窗口约 3.6 万笔，1.4 秒。实时行情每笔都要算，追不上。
  • 缺的那一块：上一个窗口的合计减掉 qty[l]，就是下一个起点的合计，r 不用回头。
不懂精华时的典型误用：把“滑动窗口”当成一个模板，见到“连续子数组”就套。数据里有负数（比如净流入 = 买量 − 卖量）时，“合计够了就缩左边”的理由不成立，⑥ 里实测双指针说“找不到”，暴力找到了长度 2 的一段（坑 1）。

③几种思路：最短一段合计 ≥ K

思路复杂度能处理负数吗说明
两层循环O(n²)能对拍用
同向双指针O(n)不能合计随窗口变长单调变大，左端不用回头
前缀和 + 二分O(n log n)不能前缀和单调递增时，对每个 r 二分找最右的 l（第 9 课 + 第 12 课）
前缀和 + 单调队列O(n)能LC 862，第 7 课的队列放在第 12 课的前缀和上

本页学同向双指针：成交量、成交额、订单数都非负，最常见，也最便宜，一个循环一个累加器。数据有正有负时，换成前缀和加单调队列，放到第 12 课。

④关键洞察：左端往右挪，右端不用往回退

先知道这些
  • 单调：一个量只增不减（或只减不增）。第 9 课的二分要求判定单调，这里要求“窗口合计随窗口变长而不减”。
  • 区间写法：本页窗口写成闭区间 [l, r]，长度 r − l + 1；时间窗口写成 (now − 60s, now]，和第 7 课一致。

洞察 · 成交量非负，所以“不用回头”

机制 · 每一步：右边进一个，合法就从左边一直缩

  1. 1 进右指针 r 往右一格，sum += qty[r]。
  2. 2 缩while sum ≥ K：这是以 r 结尾、合法的窗口，记下长度；然后 sum −= qty[l++]，看更短的还合不合法。不是 if：一次进来的大单可能让左边连缩好几格（坑 2）。
  3. 3 不变式每轮结束时 sum 正好是 [l, r] 的合计，而且 sum < K（能缩的都缩了）。

机制 · 时间窗口：左指针追着过期的走

“过去 60 秒成交量”是窗口长度固定为时间的版本：r 每来一笔就进，左指针 l 把时间 ≤ now − 60s 的都减掉。成交按时间有序，过期的一定在左边，所以 l 也只往右。和第 7 课单调队列的区别：这里窗口里每一笔都要算进合计，不能扔，所以左指针一格一格挪；单调队列能提前扔掉“被压住的”。

这笔成交量1058271
移出的———0s 的 10—20s、50s、61s 的

⑤ 的 rollingVolume 本机实测输出 [10, 15, 23, 15, 22, 8]。125s 那一步一次移出了三笔：和单调队列一样，单步可能不是 O(1)，但每笔只移出一次，摊下来 O(1)。

另外两种：快慢、对撞，各有一句“为什么不用回头”

样子不变式为什么不用回头
快慢：有序流水去重a[0..slow] 是去重后的结果，fast 之前的都看过了有序，重复的一定挨着；fast 看到和 a[slow] 不同的，就是新值
对撞：有序卖单里两笔凑 need答案如果存在，一定在 [i, j] 里a[i] + a[j] < need 时，a[i] 配谁都不够（a[j] 已经是最大的），i 可以永久排除；大于时 a[j] 同理
两份有序流水对账（第 10 课）两边指针之前的都已经配对或报出号小的那边，在另一边剩下的部分里不可能有同号的

为什么这样设计

双指针：维护一个累加器

  • O(n) 时间，O(1) 额外空间
  • 能边收数据边算，适合实时行情（流式）
  • 要求单调性：数据非负、或者有序
  • 只能回答“以每个 r 结尾”的那一类问题

前缀和：先存下来再随便问

  • 任意区间合计 O(1)，可以乱序问（第 12 课）
  • 配合单调队列能处理负数
  • O(n) 额外空间，要先有全部数据
决定胜负的约束：问题是不是“窗口一路往右、合法性对窗口长度单调”。是，就用一个累加器边走边算，最省；不是（有负数、要随机问任意区间），就先把前缀和存下来。
同向窗口的骨架只换“进”“缩的条件”“记答案”三处
int l = 0; long sum = 0;
for (int r = 0; r < n; r++) {
    sum += qty[r];                         // 1 进
    while (sum >= k) {                     // 2 合法就缩（while，不是 if）
        best = Math.min(best, r - l + 1);  // 记答案：最短
        sum -= qty[l++];
    }
}
// “最长一段合计 ≤ K”：条件反过来——不合法就缩，缩完记最长

⑥边界和变体

第一圈 · 注意事项

1数据里有负数，还用滑动窗口实测← ④ 洞察
现象
净流入 [5, −3, 1, 6, −10, 8, 4]，找最短一段合计 ≥ 12：双指针说“没有”，暴力找到 [8, 4]，长度 2。
根源
有负数时“往右长合计不减”“左边缩合计不增”都不成立。双指针只在“合计够了”时才缩左边。这里合计一直没到 12，左边就一直不缩，8、4 前面始终背着 5 −3 1 6 −10 这段累计为负的拖累；把它扔掉合计反而变大，但双指针没有“扔掉让合计变大”这个动作。
做法
换前缀和 + 单调队列（LC 862，第 12 课）；或者先确认数据非负（成交量、成交额、订单数）。
2缩窗口写成 if实测← ④ 每一步
现象
[1, 1, 1, 1, 20, 1] 找最短合计 ≥ 20：if 版本得到 5，正确答案是 1（那笔 20）。
根源
一笔大单进来，窗口可能一下从“刚好够”变成“绰绰有余”，左边要连缩好几格才到最短。if 每轮只缩一格，不变式“缩完时 sum < K”被破坏了。
做法
缩的那一步一律 while；写完用暴力对拍。
3合计用 int实测← ④ 累加器
现象
1000 笔、每笔 60000.00 元（600 万分）：int 合计 1705032704，long 合计 6000000000。
根源
累加器会把整个窗口的值加起来，比单个元素大得多，超过 int 的 21 亿就绕回去（第 1 课 补码）。
做法
累加器一律 long；成交额还可能超过 long 时（很少）用 Math.addExact 抛异常而不是悄悄绕回。
4“过去 60 秒”写成了“最近 N 笔”← ④ 时间窗口
现象
冷清时“最近 600 笔成交量”可能横跨十几分钟，行情页显示的“60 秒成交量”虚高。
根源
左指针该看时间，不该看个数。和第 7 课单调队列的 坑 1 是同一件事。
做法
左指针的条件写成 time[l] <= now − window；查询时刻没有新成交时也要先清过期再答。
5对撞指针、快慢去重用在无序数组上← ④ 另外两种
现象
卖单没排序就对撞找两笔凑数，明明有答案却返回 null；没排序就快慢去重，隔开的重复值留了下来。
根源
“a[i] 配谁都不够”“重复的一定挨着”都要靠有序。
做法
先排序（第 10 课）；不能排序时用哈希集合（第 8 课），O(n) 时间、O(n) 空间。

第二圈 · 使用规范

  • 动手前先写一句“为什么不用回头”：写不出来就别用双指针，防坑 1、坑 5。
  • 窗口区间在注释里写清开闭：[l, r] 还是 [l, r)、(now − 60s, now]，长度公式跟着写。
  • 缩的一步用 while，累加器用 long：防坑 2、坑 3。
  • 配一个暴力版本做对拍：随机小数组比 1 万次，边界错一眼就能抓到。

第三圈 · 变体和深处

题窗口里维护什么什么时候缩
LC 209 最短子数组合计 ≥ K合计合计 ≥ K 时缩，边缩边记最短
LC 3 最长无重复子串窗口里每个字符的次数（哈希或数组）新字符次数 > 1 时缩，缩完记最长
LC 76 最小覆盖子串还差几种字符没凑齐都凑齐了就缩，边缩边记最短
LC 1438 最大差值 ≤ limit 的最长子数组两个单调队列（第 7 课）：窗口最大、最小最大 − 最小 > limit 时缩
LC 15 三数之和排序后固定一个，剩下两个对撞O(n²)，比三层循环少一层

“恰好 K” = “至多 K” − “至多 K−1”

问“恰好有 K 种不同用户的连续成交段有几个”，恰好不单调，直接滑不了；但“至多 K 种”是单调的，能滑。两个“至多”相减就是“恰好”（LC 992）。

流式数据：窗口状态要能撤销

合计能减、次数能减，所以能滑；最大值不能直接“减掉”，所以要第 7 课的单调队列。判断一个统计量能不能用滑动窗口，看它支不支持“移出一个”。

面试官会怎么问

滑动窗口的时间复杂度为什么是 O(n)，里面不是还有个 while？

数指针走了多少步，不数循环套了几层：l 和 r 都只往右，各最多走 n 步，总共 ≤ 2n。和单调队列的摊还是同一个数法。

什么时候不能用滑动窗口？

“窗口合法”关于窗口长度不单调时，比如有负数的合计、“恰好 K 种”。前者换前缀和 + 单调队列，后者拆成两个“至多”。

两数之和（无序数组）为什么一般用哈希而不是对撞指针？

对撞要先排序 O(n log n)，而且排序后下标变了，要返回原下标还得多存一份；哈希一遍 O(n)。数组本来就有序时（LC 167）对撞更省空间。

自测

1. 用一句话说出这一页的精华

能证明“左端往右挪以后右端不用回退”，两个指针就都只往前走，O(n²) 变 O(n)；这个证明靠单调性，成交量非负时成立，有负数时不成立。

2. 两层循环的痛点在哪？

换起点时内层从头再加，上一轮算好的合计被扔掉；其实减掉 qty[l] 就能得到。

3. 坑 1 的根源是哪条原理？

“往右长合计不减、左边缩合计不增”只在元素非负时成立；有负数，左端就可能需要回头。

从 ④ 洞察推出。

4. 预测：⑤ 的数据里把 9 改成 0，再找最短一段合计 ≥ 15，答案是多少？双指针还对吗？

数据变成 3 1 4 1 5 0 2 6 5 3。和 ≥ 15 的最短一段长度是 4：2 6 5 3 = 16。还有 4 1 5 0 2 6 这些更长的。0 不是负数，单调性还在，双指针仍然对。

从 ④ 洞察推出：要求的是非负，不是正数。

5. 预测：时间窗口从 60 秒改成 1 秒，rollingVolume 的总耗时会变吗？

几乎不变：每笔成交仍然只进一次、出一次，总步数 2n 和窗口长度无关。变的是每次查询时 sum 里有几笔。

从 ④ 时间窗口和“各走 n 步”推出。

6. 放回全景：第 7 站前后各发生了什么？窗口算错了，整条链路会怎样？

前面是第 6 站挂单撤单，撮合吐出成交；第 7 站拿成交更新 K 线、60 秒成交量和最高价；后面是第 8 站查询，把行情给用户看。成交量算错（坑 3 溢出、坑 4 按笔数），行情页数字不对，量化客户按它下单会误判；风控的放量检测写错（坑 1），该报警的砸盘没报出来。撮合本身不受影响。
