动态规划入门：状态和转移，带手续费的买卖为什么贪心不行

动态规划（DP）就是回溯 + 记账：回溯里同一个子问题被反复算，DP 把它的答案按“状态”记下来，下次直接查。会 DP 只要会两件事：状态（走到这一步，要记住哪几个数才够往下算）和转移（今天的状态由昨天的哪几个状态怎么来）。

②朴素做法：回溯，每天“动 / 不动”都试

第 20 课的写法：rec(day, holding) 表示“从第 day 天开始，手里有没有货，以后最多还能赚多少”。每天两个分支（不动 / 买或卖），调用次数 2ⁿ⁺¹ − 1。

  • 指数级：n = 20 调用 210 万次，n = 25 调用 6700 万次（⑤ 实测）。
  • 浪费在重复：不同的状态一共只有 2n 个，却被算了 2ⁿ 遍。
  • 缺的那一块：每个状态算一次，记下来。这就是 DP。
不懂精华时的典型误用：背“股票问题六种模板”，换个条件（多了冷冻期、最多两笔）就不会。模板是同一个想法的六个实例：找出决定未来的最少信息，当状态。

③几种思路：同一个状态，三种写法

写法怎么做好处代价
记忆化搜索（自顶向下）回溯代码不动，加一个 Map / 数组缓存从回溯改过来最自然；只算用得到的状态递归深度 = n，36 万层栈溢出（⑤ 实测）
递推表（自底向上）按天从前往后填 cash[i]、hold[i]没有递归；顺序一目了然要想清楚填表顺序
递推 + 滚动变量今天只用到昨天，只留两个变量O(n) 时间、O(1) 空间，能边读价格边算丢了中间结果，要输出买卖点得另外记

本页学状态和转移，三种写法都写一遍：先用记忆化从回溯改过来（最好想），再改成递推（最好用）。

④关键洞察：状态 = 决定未来的最少信息

先知道这些
  • 回溯的参数：第 20 课的递归函数里，除了 path 以外的参数，决定了子树长什么样。见 第 20 课 · 洞察 1。
  • 哈希表做缓存：Map.get 平均 O(1)，见 第 8 课。

洞察 1 · 状态：以后能赚多少，只取决于“第几天”和“有没有货”

过去怎么买卖的、赚了多少，对以后的选择没有影响；影响以后的只有两件事：今天是第几天、手里有没有货。这两个数就是状态，一共 2n 个。DP 能成立要两个条件：

重叠子问题

同一个状态被不同的路径反复走到（② 里同色的框）。没有重叠，记了也没用，那就是普通的分治（如归并排序）。

无后效性

到了这个状态，以后怎么走、能拿多少，和“怎么到这里的”无关。冷冻期会破坏它：今天能不能买取决于昨天卖没卖，所以要把“昨天刚卖”加进状态（洞察 3）。

洞察 3 · 条件多了，就往状态里加东西

条件状态复杂度
不限次数，无费用(天, 有没有货)；退化成第 19 课的贪心O(n)
每次扣手续费(天, 有没有货)，卖出那条箭头减 feeO(n)
卖后冷冻一天(天, 持有 / 刚卖 / 可买)O(n)
最多 k 笔(天, 已做几笔, 有没有货)O(nk)

为什么这样设计：用空间换掉重复计算

DP：每个状态算一次

  • 时间 = 状态数 × 每个状态的转移数 = 2n × 2
  • 不用证明“不后悔”：所有选择都比过了
  • 代价：要找对状态；状态多了表就大

回溯：每条路走一遍

  • 不用想状态，最直接
  • 同一个状态被不同路径重复算，2ⁿ
决定胜负的约束：路径有 2ⁿ 条，但“不同的局面”只有 2n 个。只要以后的事只看局面、不看来路（无后效性），就只需要为每个局面算一次。DP 的难点全在“局面要记几个数”：少了算错（冷冻期），多了表太大。
从回溯到 DP 的三步细节放到 ⑥
// 1. 回溯：参数里除了 path 的，就是状态
long rec(int day, int holding)
// 2. 记忆化：查缓存，没有才算
if (cache[day][holding] != null) return ...;
// 3. 递推：按天从前往后填，只留昨天
long cash = 0, hold = -p[0];
for (int i = 1; i < n; i++) {
    long c = Math.max(cash, hold + p[i] - fee);
    long h = Math.max(hold, cash - p[i]);
    cash = c; hold = h;     // 两个都算完再一起换
}
return cash;

写 DP 的四问

1. 状态：走到这一步，记哪几个数就够算以后？
2. 转移：每个状态由哪几个上一步的状态来，取 max / min / 求和？
3. 起点：第 0 步每个状态是多少，不可能的状态填什么？
4. 顺序和答案：按什么顺序填，答案在表的哪一格？

⑤手推一遍，再把三种写法跑一遍

手推就是 ④ 的分步动画：cash 那一行最后一格是 8。下面把纯递归、记忆化、递推表、两个变量放在一起跑，再和暴力对拍。

⑤StockDp.java完整代码 →
// 记忆化：回溯原样不动，进门先查缓存
static long memo(int[] p, int fee, int day, int holding, Map<Long, Long> cache) {
    calls++;
    if (day == p.length) return 0;
    long key = (long) day * 2 + holding;
    Long hit = cache.get(key);
    if (hit != null) return hit;
    long stay = memo(p, fee, day + 1, holding, cache);
    long act = holding == 1 ? p[day] - fee + memo(p, fee, day + 1, 0, cache)
                            : -p[day] + memo(p, fee, day + 1, 1, cache);
    long r = Math.max(stay, act);
    cache.put(key, r);
    return r;
}

读出来的结论
  • 纯递归调用 2ⁿ⁺¹ − 1 次，记忆化 4n − 1 次：n = 25 时差 67 万倍。记下来的就是 2n 个状态。
  • 记忆化写法最好从回溯改，但递归深度等于天数，36 万层直接栈溢出；生产上用递推。
  • 冷冻期多一个状态就对了；同样三个状态，更新顺序写错就多算 1（坑 2）。
到这里已经能交差了：带手续费、带冷冻期的回测收益都能 O(n) 算对，且有对拍。
已知还没处理的细节：状态少记一个（坑 1），更新顺序（坑 2），起点填错（坑 3），递归太深（坑 4）。

⑥边界和变体

第一圈 · 注意事项

1状态少记了一个← ④ 洞察 1
现象
冷冻期只用 cash / hold 两个状态，算出来的方案“今天卖、明天就买”，收益偏高。
根源
“明天能不能买”取决于“今天是不是刚卖”，这个信息不在状态里，无后效性被破坏。
做法
问自己：同一个状态下，以后能做的事是不是完全一样？不一样，就把造成差别的那个信息加进状态。
2滚动变量原地更新，用到了“今天的”值实测← ④ 洞察 2
现象
冷冻期 [1,2,3,0,2]：正确 3，原地按 sold → rest → hold 的顺序更新得 4。
根源
转移要的是“昨天的”rest，原地更新后 hold 用到了“今天刚卖完就算可买”的 rest，等于跳过了冷冻期。
做法
先用临时变量把今天的值全算出来，再一起赋值（④ 代码里的 c、h）。手续费版碰巧顺序无关，别指望每题都这样。
3起点填 0← ④ 洞察 2
现象
hold[0] = 0：等于白送了一份货，结果多出一个 p[0]。
根源
起点也是状态，要符合含义：第 0 天收盘就持有，只能是当天花 p[0] 买的。不可能的状态（第 0 天“刚卖”）要填负无穷，不能填 0。
做法
用 Long.MIN_VALUE / 4 当负无穷（除以 4 是防加减时溢出），见 第 1 课。
4记忆化递归太深实测← ④ 洞察 1
现象
36 万个分钟价，StackOverflowError。
根源
记忆化省的是重复计算，没省递归深度：从第 0 天一路递归到最后一天，深度 = n。JDK 17 默认栈大约一万层，见 第 13 课。
做法
改成递推；或者只在状态少、深度浅时用记忆化（比如第 22 课的背包按物品递归）。

第二圈 · 使用规范

  • 注释里写清状态的含义：“cash[i] = 第 i 天收盘时空仓的最大现金”。防的是半年后改代码的人把 cash 当成“已实现收益”。
  • 先写暴力和记忆化，再改递推：前两个几乎不会写错，拿来对拍递推版。
  • 金额一律 long、用分：36 万步的累加，int 会溢出（第 1 课）。

第三圈 · 从这里往外

最多 k 笔交易

状态加一维“已经做了几笔”：dp[j][持有?]，j = 0..k。k ≥ n/2 时等于不限次数，可以直接退回贪心，这是常见的优化。

DP 和最短路是一回事

把每个状态当成图上的点、转移当成边，DP 就是在一张有向无环图上按拓扑序求最长 / 最短路（第 18 课）。“无后效性”对应“没有环”。

和贪心的关系

无手续费时，DP 的 cash 每天都等于“到今天所有正差价之和”，正好是第 19 课的贪心。贪心是 DP 在特殊结构下的简化，不是另一种东西。

状态压缩

今天只用到昨天，表就只留一行；用到前两天（冷冻期的另一种写法），就留两行。空间从 O(n) 变 O(1)，代价是不能回头找买卖点。

实验台：手续费越高，最优方案做几笔？

先猜：同一段 60 天的价格，手续费从 0 涨到 6，DP 给出的最优方案的交易笔数会怎样？

浏览器里现算：60 天价格由固定种子生成；DP 就是 ④ 的两个变量，额外记一下每个状态是做了几笔走到的（同样收益取笔数少的）；朴素贪心是第 19 课“涨幅大于手续费就做”。

自测

1. 用一句话说出这一页的精华

DP 是回溯加记账：找出决定以后的最少信息当状态，每个状态只算一次，由上一步的几个状态转移过来。

2. 回溯慢在哪？DP 省掉的是什么？

不同的局面只有 2n 个，回溯却按路径算了 2ⁿ 遍；DP 省掉的是“同一个局面被不同路径重复计算”。

3. 冷冻期只用两个状态为什么会错？

“明天能不能买”取决于“今天是不是刚卖”，这条信息不在状态里，同一个“空仓”状态下以后能做的事不一样，无后效性被破坏。

4. 预测：手续费改成“买入时扣”而不是“卖出时扣”，答案会变吗？

不变。每一笔交易恰好一次买、一次卖，费用扣在哪一端，总共都是每笔 fee；只是 hold 那一行的数整体少 fee，cash 那一行不变。

从 ④ 洞察 2 推出：费用挂在哪条箭头上，只改变中间状态的值，不改变完整交易的总费用。

5. 预测：价格单调上涨 100 天，手续费 5，最优方案做几笔？

1 笔：第 0 天买、第 99 天卖，只付一次费。拆成几笔每笔都要多付 5，涨幅一分不多。

从 ④ 洞察 2 推出：hold 一路取“不动”，cash 只在最后一天走卖出箭头。

6. 放回全景：第 12 站的回测要用前面哪几站的数据？这一页错了影响谁？

回测用的是第 6～10 站产生的成交价、K 线（第 7 站的窗口最高价、第 10 站排好序的流水）。这一页算错，前面 11 站都不受影响，坏的是回测报告：手续费估少了，策略看起来比实际赚钱。

档位：标准。本机跑过（2026-11-21，2 核 Neoverse-N1 虚机，OpenJDK 17.0.21，--release 8 编译）：⑤ 的全部输出，包括调用次数、2000 组对拍、冷冻期更新顺序、36 万点耗时和栈溢出。实验台是浏览器里现算的。“最多 2 笔”练习的答案 6 是 LeetCode 123 的公开样例。
