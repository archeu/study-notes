拓扑排序与最短路径：清算谁先谁后，换汇走哪条路

两个问题都在有向图上。拓扑排序：没有前置依赖的任务先做，做完就把它指出去的边删掉，又会冒出新的“没有前置”的任务；最后排不完，就说明依赖里有环。最短路径：把第 16 课 BFS 的队列换成按“目前已知最短距离”排序的堆，每次取出最近的那个点，它的距离就再也不会变短，前提是边的成本不为负；有负的（返佣、汇率套利）就要 Bellman-Ford。

①要解决的问题：任务谁先谁后，钱走哪条路最省

在全景第 10 站，夜间清算有一串任务：成交汇总做完才能算手续费和持仓，持仓和收盘价都有了才能算保证金，资金和保证金都有了才能算风险度……调度系统要排出一个不违反任何依赖的执行顺序，依赖写错成环时要能发现。第 12 站的回测还有一个问题：手上的 BTC 想换成 ETH，直接换手续费加滑点 30 bp，绕道 USDT、USDC 可能更便宜，哪条路总成本最低？

②朴素做法：人工排、反复扫；枚举所有路、或者直接用 BFS

做法疼在哪
清算顺序写死在脚本里加一个任务就要人重新排；有人加了一条反向依赖，没人发现，任务读到旧数据
每轮扫一遍所有任务，找“依赖都完成了的”每轮 O(V + E)，最多 V 轮，O(V·(V + E))
换汇：枚举所有路线路线数随币种数指数增长；几十个币种就算不完
换汇：第 16 课的 BFSBFS 找的是跳数最少，会选直接换（1 跳、30 bp），而不是 3 跳、19 bp 的那条
  • 拓扑排序缺的：每个任务记一个“还剩几个前置没完成”（入度），完成一个就给它的后继减一，减到 0 的放进可做队列，不用每轮重扫。
  • 最短路径缺的：BFS 按“跳数”排队，要改成按“目前已知的总成本”排队，用堆（第 6 课）每次取最小的。
不懂精华时的典型误用：把 BFS 的“入队就标记 visited”照搬到 Dijkstra。BTC 一出发就把 ETH 标记为 30 bp 并“定下来”，后面发现的 19 bp 的路再也更新不进去。本机实测这种写法答 30（坑 2）。Dijkstra 必须在出堆时才定下来。

③几种思路：排先后两种，找最短四种

算法解决复杂度要求
Kahn（入度 + 队列）拓扑排序O(V + E)有向图；顺手检测环
DFS 后序再倒过来拓扑排序O(V + E)要三色标记才能检测环；递归深度问题同第 16 课
BFS（第 16 课）最短路O(V + E)边都一样长
Dijkstra（堆）单源最短路O((V + E) log V)边不能为负
Bellman-Ford单源最短路O(V·E)可以有负边；能发现负环
Floyd-Warshall所有点对O(V³)点少（几百个）时最省事

本页学 Kahn 和 Dijkstra：清算调度用 Kahn，顺序和环检测一次拿到；换汇成本（手续费、滑点）都是非负的，用 Dijkstra。汇率本身相乘、可能出现“绕一圈回来钱变多”的套利，那是负环，留给 Bellman-Ford（⑥ 第三圈）。

④关键洞察：先做没有前置的；先确定最近的

先知道这些
  • 有向图、入度：边有方向，A → B 表示 A 在前；入度 = 指向它的边数。第 16 课 图的表示。
  • 堆：O(log n) 进出、O(1) 看最小。Java 的 PriorityQueue 不能修改已在堆里的元素的优先级。第 6 课 堆和优先队列。

洞察 1 · Kahn：入度为 0 的先做，做完给后继减入度

洞察 2 · Dijkstra：堆顶那个点的距离不会再变短

维护每个点“目前已知的最低成本” dist。每次从堆里取 dist 最小的点 u，把它定下来，再用它去更新邻居：dist[u] + 成本 < dist[v] 就改小（叫松弛）。为什么 u 定下来以后不会再变短？任何还没定下来的点的成本都 ≥ dist[u]，再加上非负的边只会更大，绕不出一条更便宜的路回到 u。这一步推理正是“边不能为负”的来源。

准备点“下一步”。

PriorityQueue 没法把已经在堆里的 ETH 从 30 改成 23，所以直接再放一份 (23, ETH)；弹出 (30, ETH) 时发现它比 dist[ETH] 大，是旧的，跳过。这叫延迟删除，⑤ 里一共跳过了 3 个旧条目。

洞察 3 · 边为负时，“定下来”就错了

A → B 成本 5，A → C 成本 2，B → C 成本 −4（这一段有返佣），C → D 成本 1。Dijkstra 先定下 C = 2、D = 3，等到处理 B 时才发现 A → B → C 只要 1，可 C 和 D 都已经定下来了。⑤ 实测 Dijkstra 答 D = 3，Bellman-Ford 答 2。Bellman-Ford 不“定下来”任何点，而是把所有边松弛 V − 1 轮（任何最短路最多 V − 1 条边）；第 V 轮还能变短，就说明有一个越绕越便宜的负环。

为什么这样设计

Kahn

  • O(V + E)，迭代写，不怕深
  • 同一层可以并行跑，调度系统直接用
  • 结果数 < 任务数 = 有环，检测是白送的

Dijkstra

  • 贪心：每个点只定一次，O((V + E) log V)
  • 靠“非负”才能贪心，负边直接答错

Bellman-Ford

  • 不贪心，能处理负边、能报负环
  • O(V·E)，大图上慢得多
决定胜负的约束：边能不能为负决定能不能贪心。手续费、滑点、延迟、距离都非负，用 Dijkstra；有返佣、或者要用 −log(汇率) 把“乘起来最大”变成“加起来最小”，权重就可能为负，用 Bellman-Ford，负环正好就是套利机会。拓扑排序不关心长短，只关心有没有环。
Kahn 的骨架细节放到 ⑥
Deque<String> ready = 入度为 0 的任务;
while (!ready.isEmpty()) {
    String t = ready.poll();
    order.add(t);
    for (String nx : out.get(t))
        if (--indeg[nx] == 0) ready.offer(nx);
}
if (order.size() < 任务数) throw new IllegalStateException("依赖有环");
Dijkstra 的骨架出堆才定下来
dist[src] = 0; pq.offer(new long[]{0, src});
while (!pq.isEmpty()) {
    long[] top = pq.poll(); int u = (int) top[1];
    if (top[0] > dist[u]) continue;          // 旧条目
    for (int[] e : adj[u])
        if (dist[u] + e[1] < dist[e[0]]) {
            dist[e[0]] = dist[u] + e[1]; prev[e[0]] = u;
            pq.offer(new long[]{dist[e[0]], e[0]});
        }
}

⑥边界和变体

第一圈 · 注意事项

1有环时没检查结果数，任务悄悄少跑实测← ④ 洞察 1
现象
有人加了“持仓要等风险度”，Kahn 只排出 3 个任务就停了，队列空、程序正常结束。调度系统以为当晚清算跑完了，持仓、资金、报表都没算。
根源
环上的任务互相等，入度永远降不到 0，不会进队列；Kahn 不报错，只是少输出。
做法
排完一定比较 order.size() 和任务数，不等就报警，并列出卡住的任务（⑤ 的写法）；加依赖时就跑一次排序做校验。
2Dijkstra 入队时就“定下来”实测← ④ 洞察 2
现象
照搬第 16 课 BFS 的“入队就标记”，BTC → ETH 答 30 bp（直接换），正确是 19 bp。
根源
BFS 里边都一样长，先碰到的一定更近；Dijkstra 里先碰到的可能是一条贵的直达边，要等更便宜的绕路被松弛。只有“出堆”那一刻，才能保证它最小。
做法
出堆时才定下来；松弛时只比较 dist，不看“见没见过”。
3有负边还用 Dijkstra实测← ④ 洞察 3
现象
A → B 5、A → C 2、B → C −4（返佣）、C → D 1：Dijkstra 答 D = 3，Bellman-Ford 答 2。
根源
“堆顶的不会再变短”依赖“边非负”；有负边，晚出堆的点可以把早定下来的点再拉低。
做法
权重可能为负就用 Bellman-Ford（或 SPFA）；能把负数挪走就挪走，比如把返佣并进同一条边的成本里，让每条边整体非负。
4堆里的旧条目没跳过← ④ 延迟删除
现象
结果是对的，但同一个点被“处理”了好几次，邻居被反复松弛，大图上慢好几倍；如果处理时还有副作用（比如记日志、发事件），就会重复。
根源
PriorityQueue 没有 decrease-key，距离变短时只能再放一份，旧的那份还在堆里。
做法
出堆时先判断 top[0] > dist[u] 就 continue。
5汇率直接相乘求“最大”← ④ 洞察 3
现象
想找“换完最多”的路线，把 Dijkstra 的加法改成乘法、最小改成最大，结果时对时错。
根源
Dijkstra 的正确性要求“越走越不划算”。汇率可以大于 1，乘上去反而更多，相当于负边。
做法
取 −log(汇率) 当权重，乘积最大 = 和最小；有权重为负时用 Bellman-Ford。只算手续费损耗时 −log(1 − 费率) 一定非负，可以用 Dijkstra。

第二圈 · 使用规范

  • 拓扑排序后断言结果数等于点数：防坑 1。
  • Dijkstra 出堆才定、出堆先判旧：防坑 2、坑 4。
  • 上线前检查边权非负：构图时遇到负权直接拒绝或换算法，防坑 3、坑 5。
  • 记 prev，最短路要能还原路径：只给一个数字没法解释“为什么走这条路”。
  • 依赖关系存成数据，不写死在脚本里：每次变更都能自动重排、自动查环。

第三圈 · 变体和深处

套利 = 负环

权重 = −log(汇率)。USDT → BTC → ETH → USDT 三个汇率相乘大于 1，就是 −log 之和小于 0：一个负环。Bellman-Ford 跑完 V − 1 轮后再松弛一轮，还能变短的边就在负环上（或通向它）。这是量化里“三角套利”的检测思路，只是真实市场里要加上手续费、深度和速度。

关键路径：清算最快多久跑完

每个任务带耗时，在拓扑序上做“最长路”：一个任务最早开始时间 = 它所有前置的（最早开始 + 耗时）的最大值。最后一个任务的完成时间就是整晚清算的最短总时长，那条最长的链叫关键路径，优化别的任务没用。

A*：带方向感的 Dijkstra

堆里按 dist[u] + h(u) 排序，h 是“到终点至少还要多少”的估计（不能高估）。地图导航用直线距离当 h，搜索范围小得多。h ≡ 0 时就是 Dijkstra。

0-1 BFS 和多源最短路

边权只有 0 和 1 时，用双端队列：0 权边放队头、1 权边放队尾，O(V + E)。所有点对的最短路、点数几百以内时用 Floyd-Warshall：三层循环，d[i][j] = min(d[i][j], d[i][k] + d[k][j])。

面试官会怎么问

课程表（LC 207 / 210）：能不能修完所有课，给出一个顺序。

课程是点，先修关系是边，跑 Kahn：结果数等于课程数就能修完，顺序就是结果；否则有环。

Dijkstra 为什么不能处理负权边？

它的正确性来自“堆顶的点距离不会再变短”，前提是后面加上的边都非负。有负边时，晚处理的点可以经过负边把已经定下来的点变得更近。

网络延迟时间（LC 743）：信号从 k 出发，多久所有节点都收到？

从 k 做 Dijkstra，答案是所有 dist 里的最大值；有点不可达就返回 −1。

自测

1. 用一句话说出这一页的精华

拓扑排序：入度为 0 的先做，做完给后继减入度，排不完就有环；Dijkstra：用堆每次取目前最近的点定下来再松弛邻居，靠边非负才成立，有负边用 Bellman-Ford。

2. 用 BFS 找换汇路线，痛点在哪？

BFS 求的是跳数最少，会选直接换的 1 跳 30 bp，而不是 3 跳 19 bp 的那条。边有长短时要按总成本排队。

3. 为什么 Dijkstra 必须出堆时才定下来？

入队时只是“目前已知”的成本，后面可能被更便宜的绕路松弛；出堆时它是所有未定点里最小的，加上非负边不可能再变小。

从 ④ 洞察 2 推出。

4. 预测：把 USDT—USDC 的成本从 1 改成 5，BTC → ETH 的最优路线和成本是多少？

BTC → USDC → USDT → ETH 变成 8 + 5 + 10 = 23；BTC → USDT → ETH = 20；BTC → BNB → ETH = 12 + 7 = 19。最优变成经 BNB，19 bp，成本没变、路线变了。

从 ④ 洞察 2 推出：最短路是所有路径成本的最小值，换一条边可能换一条路。
