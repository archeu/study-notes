递归与二叉树遍历：盘口从优到劣，就是一次中序遍历

树的每个节点有两个孩子，走完左边还得回来走右边，一个 for 循环记不住“回到哪”，要一个栈。递归就是让 JVM 的调用栈替你记：写清“空树怎么办”，再相信对子树的同一个调用会把子树处理好。把“处理自己”放在两次递归调用的前、中、后，就是前序、中序、后序；二叉搜索树的中序正好从小到大。

①要解决的问题：价位存成一棵树，怎么从优到劣列出来

在全景第 8 站，盘口要按价格从优到劣列出前五档。卖盘最优是价格最低。价位如果放在一棵二叉搜索树里（每个节点左边的都比它小、右边的都比它大，第 14 课的 TreeMap 就是这样），插入、撤单都是 O(树高)；问题是：怎么把树里的价位按从小到大的顺序走一遍？

本页的树7 个价位不做平衡
递归深度= 树高平衡时 log n，退化时 n
一路涨的价位1 万层就溢出默认栈 2040 KB，本机
面试对应LC 94 / 102 / 104中序、层序、树高

②朴素做法：用循环走，或者每次全拿出来排序

  • 链表、数组只有“下一个”，一个指针够用；树有两个“下一个”，走了一个，另一个要先存起来。
  • 要么自己用 ArrayDeque 当栈存岔路，要么让函数调用自己，JVM 的调用栈会替你存。后者就是递归。
不懂精华时的典型误用：觉得递归“优雅”就处处用，不看深度。价位一路上涨时，不平衡的树退化成一条向右的链，树高 = 价位数，递归遍历 1 万层就 StackOverflowError（坑 2，本机实测）。

③几种思路：谁来记“待回去的岔路”

思路谁记岔路额外空间说明
递归JVM 调用栈O(树高)代码最短，几行就和定义一样；深度受线程栈大小限制
显式栈（ArrayDeque）堆上的一个栈O(树高)不怕深；能随时停（前 5 档就停）；代码要多想一步
层序（队列）队列O(最宽一层)一层一层走，不是有序的；求“第几层”、最短步数用它（第 16 课 BFS）
Morris 遍历临时改树里的空指针O(1)走完再改回来；并发读时不能用，面试里偶尔考

本页学递归，再把它改写成显式栈：递归是理解树、图、回溯、动态规划的共同语言；显式栈是它在生产里的安全版本。两者走的顺序完全一样，⑤ 会对拍。

④关键洞察：写清空树，相信子树，决定自己放哪

先知道这些
  • 调用栈：每次方法调用在线程栈上压一个栈帧（局部变量、返回地址），返回时弹掉。HotSpot 默认线程栈 1～2 MB 左右，本机 aarch64 上 JDK 17 是 2040 KB（-Xss 可调）。第 5 课 栈。
  • 二叉搜索树：每个节点左子树的值都比它小、右子树都比它大。怎么保持平衡是第 14 课。

洞察 1 · 递归的三句话

中序遍历：和定义一模一样三句话各占一行
static void inorder(Node n, List<Long> out) {
    if (n == null) return;          // ① 基础情况：空树什么都不做（没有它就无限递归）
    inorder(n.left, out);           // ② 相信：这一行返回时，左子树已经从小到大输出完了
    out.add(n.price);               // ③ 自己：左边全比我小，所以轮到我
    inorder(n.right, out);          // ② 再相信一次：右边全比我大，放在我后面
}

写递归时不要在脑子里展开每一层，那会绕晕。只检查两件事：基础情况对不对；假设对子问题的调用已经正确，用它们拼出自己的答案对不对。这和数学归纳法是一回事：n = 0 成立，n − 1 成立能推出 n 成立。

动画里的栈帧就是递归里“待回去的岔路”：每一帧记着“左边处理完以后，输出我、再去右边”。显式栈版本把同样的东西放进 ArrayDeque：一路向左压栈，弹出一个就输出它、再转向它的右子树（⑤ 的 inorderIter）。

机制 · 递归有多深 = 树有多高

树的形状树高（n = 100 万）递归深度什么时候出现

“随机插入平均高度约 2.99·log₂n”是已知的数学结论（Devroye，1986），这里按文献写，没有本机实测。最后一行本机实测见 ⑥ 坑 2。

为什么这样设计：递归，还是显式栈

递归

  • 代码就是定义，最不容易写错
  • 前中后序只差一行的位置
  • 深度受线程栈限制，溢出是 Error，很难优雅恢复
  • HotSpot 不做尾调用优化，写成尾递归也一样占栈

显式栈

  • 栈在堆上，深度只受内存限制
  • 可以随时停、随时恢复（分页取盘口）
  • 中序、后序的迭代写法要多想：“什么时候输出”“右边走过没有”
决定胜负的约束：深度有没有上限。平衡树（深度 log n）、题目保证不深的场景，递归最清楚；深度取决于外部输入（用户数据、行情走势、链表一样的树）时，用显式栈，或者先保证结构平衡。

⑤手推一遍：卖盘价位树，列出前 5 档

价位单位是“分”（10100 = 101.00 元）。插入用循环写（插入只走一条路，不需要栈）；遍历写递归和显式栈两版，互相对拍。代码按 JDK 8 写法，--release 8 编译，JDK 17 运行。

// 显式栈中序：一路向左压栈，弹出一个输出，再转向它的右子树；k > 0 时输出 k 个就停
static List<Long> inorderIter(Node root, int k) {
    List<Long> out = new ArrayList<>();
    Deque<Node> stack = new ArrayDeque<>();
    Node cur = root;
    while (cur != null || !stack.isEmpty()) {
        while (cur != null) { stack.push(cur); cur = cur.left; }
        Node n = stack.pop();
        out.add(n.price);
        if (k > 0 && out.size() == k) break;    // 前 k 档够了，不用走完整棵树
        cur = n.right;
    }
    return out;
}

// 后序的典型用法：先要两个孩子的答案
static int height(Node n) { return n == null ? 0 : 1 + Math.max(height(n.left), height(n.right)); }

⑥边界和变体

第一圈 · 注意事项

1基础情况漏了或写错← ④ 洞察 1
现象
忘了 if (n == null) return;，第一次碰到叶子的空孩子就 NullPointerException；基础情况写成“n.left == null 就返回”，右子树被整个跳过，输出少了一半。
根源
“相信子问题”成立的前提是最小的问题有正确答案。基础情况错了，归纳从第一步就错。
做法
基础情况用“空树”，不用“叶子”：空树一行 return，叶子会自动走通。写完先拿空树、一个节点、只有左孩子三种情况手算一遍。
2树退化成链，递归太深实测← ④ 递归有多深
现象
价位一路上涨、按到达顺序插入不平衡的树：本机默认栈（2040 KB），树高 1 万时递归中序 StackOverflowError；同一进程里接着试 2 万层反而过了，5 万层又溢出。-Xss8m 时 10 万层都能过。显式栈每次都过。
根源
递归深度 = 树高，退化时树高 = n。溢出门槛不固定：同一个方法解释执行时栈帧大，被 JIT 编译以后栈帧小，所以“先溢出一次、后面又过了”。生产上不能指望一个固定的安全深度。
做法
深度由外部数据决定时用显式栈；或者用平衡树（第 14 课）把深度压到 log n。不要靠调大 -Xss 解决，每个线程都会多占内存。
3递归里反复算同一个子问题实测← ④ 洞察 1
现象
按定义写 fib(n) = fib(n−1) + fib(n−2)：fib(30) 调用 269 万次，fib(40) 调用 3.3 亿次、641 ms；记下来再用只要算 39 次。
根源
两次递归调用的子问题有重叠，没人记住算过的结果，调用次数随 n 指数增长。二叉树遍历没这个问题，因为左右子树没有交集。
做法
先看子问题会不会重叠：会，就加一个备忘表（HashMap 或数组），这就是第 21 课的动态规划。
4以为写成尾递归就不占栈← ④ 为什么这样设计
现象
从 Scala、Kotlin（tailrec）或函数式语言来的写法，在 Java 里照样栈溢出。
根源
HotSpot 不做尾调用优化，每次调用都压一帧。Kotlin 的 tailrec 是编译器把它改写成了循环，不是 JVM 做的。
做法
深的尾递归直接改成循环；参数就是循环变量。
5递归时传了一个共享的可变对象，忘了它是共享的← ④ 调用栈
现象
求“根到每个叶子的价位路径”，往同一个 List 里 add，回到上一层时没 remove，后面的路径越来越长。
根源
栈帧里存的是引用，所有层看到的是同一个 List。局部变量每层一份，对象不是。
做法
进去前 add、出来后 remove（回溯，第 20 课）；或者每层传一份拷贝（简单但多花内存）。

第二圈 · 使用规范

  • 先写基础情况，并用空树、单节点手算：防坑 1。
  • 先估深度，再决定递归还是显式栈：深度可能到几千以上、或由用户数据决定，用显式栈。防坑 2、坑 4。
  • 两次递归调用的子问题会重叠时，加备忘表：防坑 3。
  • 共享的可变参数，谁 add 谁 remove：防坑 5。
  • 递归函数的注释写“它返回时保证了什么”：比如“返回时 out 里追加了这棵子树的全部价位，从小到大”。这句话就是“相信”的内容。

第三圈 · 变体和深处

由前序 + 中序还原一棵树

前序第一个是根；在中序里找到它，左边是左子树、右边是右子树，长度也就知道了，递归下去（LC 105）。这说明“前序 + 中序”能唯一确定一棵没有重复值的二叉树；只有前序 + 后序不行。把树存进 Redis 或发给另一台机器时，常用“前序 + 空节点标记”序列化（LC 297）。

Morris 遍历：O(1) 空间

走到一个节点时，把它左子树最右下那个节点的空右指针临时指回它自己，下次顺着这根“线”就能回来，用完再改回 null。不用栈、不用递归，代价是遍历期间改了树，别的线程不能同时读。

任何递归都能改成循环 + 栈

通用办法：把栈帧显式化，存“节点 + 执行到哪一步”（比如 0 = 刚进来，1 = 左边做完了，2 = 右边也做完了），循环里按状态往下走。中序、后序的迭代写法都可以这样推出来，不用背。

分而治之 = 后序

第 10 课的归并排序：先递归排好左右两半，再合并，就是后序；快排：先划分（处理自己），再递归两边，就是前序。树形 DP（第 21、22 课）也是后序：先拿到孩子的答案，再算自己。

面试官会怎么问

不用递归写二叉树中序遍历（LC 94）。

一个栈：一路向左压栈；弹出一个，输出它，转向它的右子树；栈空且当前为空时结束。⑤ 的 inorderIter 就是。

二叉树的最大深度（LC 104），递归和层序各怎么写？

递归是后序：1 + max(左高, 右高)，空树为 0。层序：一层一层走，走了几层就是深度。树很深时层序不怕栈溢出。

递归和迭代哪个快？

差别通常很小，迭代少了方法调用的开销，JIT 内联后差距更小。选哪个主要看深度安全和可读性，不是速度。

自测

1. 用一句话说出这一页的精华

树要“走完左边再回来走右边”，得有个栈记岔路；递归让调用栈来记，写清空树、相信子树、决定自己放在哪一行，就得到前中后序，二叉搜索树的中序就是从小到大。

2. 为什么一个 while 循环走不完一棵树？

每个节点有两个“下一个”，走了一个，另一个必须先存起来，后进先出地回来处理。一个指针存不下，要一个栈。

3. 坑 2 的根源是哪条原理？

递归深度等于树高，不平衡的树在有序输入下退化成链，树高 = n。

从 ④ 递归有多深推出。

4. 预测：把 ⑤ 的 inorder 里 out.add 挪到两次递归调用之后，在这棵树上输出什么？

后序：10020 10080 10050 10150 10300 10200 10100。根最后输出，每个节点都在它两个孩子之后。

从 ④ 洞察 2 推出。

5. 预测：一棵平衡的价位树有 100 万档，递归中序遍历，调用栈最深多少帧？会溢出吗？

约 20 帧（log₂ 100 万 ≈ 20），每帧几十字节，远不会溢出。危险的不是节点多，而是树高。

从 ④ 递归有多深推出。
