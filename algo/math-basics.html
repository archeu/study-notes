④关键洞察：六样工具，各自在算什么，在 Java 里怎么算对

先知道这些
  • Java 的数有位数上限：int 32 位，最大 2,147,483,647（约 2.1×10⁹）；long 64 位，最大约 9.2×10¹⁸。超过上限不报错，直接绕回负数。为什么会这样，见第 1 课 · 补码。
  • double 只有 53 位有效二进制：大约 15～16 位十进制有效数字，比这更长的整数放进 double 就不准了（第 1 课 · IEEE 754）。
  • 大 O 只看涨势：常数和小项都扔掉（第 3 课）。所以这一页的公式只要量级对，复杂度就对；可写代码时每一位都要算对。

洞察 1 · 幂和对数是一对：一个问“乘 k 次是多少”，一个问“要几次才到 n”

叫法指的是 2³ = 8 里的哪部分在复杂度里
底数2：被乘的那个数—
指数3：右上角的小数字，表示乘几次—
幂（乘方）8：整个结果，也指“2³”这种写法本身—
幂函数 xᵏ底数在变，指数固定：n²、n³多项式级，n 翻倍，n² 变成 4 倍
指数函数 kˣ底数固定，指数在变：2ⁿ指数级，n 加 1，2ⁿ 就翻倍，比任何多项式都涨得快

“幂”和“指数”常被混着说，但说的是同一个式子的不同部分。所以“O(n²) 是幂函数（多项式级）”和“O(2ⁿ) 是指数级”说的是两回事：看变量 n 在底数上还是在指数上。本页标题说的“幂”，包括这两种情况。

2¹⁰ = 1024≈ 10³记住这一条，其余都能换算
2²⁰ ≈ 10⁶ · 2³⁰ ≈ 10⁹log₂ 10⁹ ≈ 3010 亿个元素二分也只要 30 次
int 上限2³¹ − 12,147,483,647，约 2.1×10⁹
long 上限2⁶³ − 1约 9.2×10¹⁸
幂的规则对应的对数规则在算法里用在哪
aᵐ · aⁿ = aᵐ⁺ⁿlog(x·y) = log x + log y两层各 log n 的循环叠起来是 2 log n，还是 O(log n)
(aᵐ)ⁿ = aᵐⁿlog(xᵏ) = k · log xlog(n²) = 2 log n：n² 个元素二分，也只多一倍次数
a⁰ = 1，a⁻ⁿ = 1/aⁿlog 1 = 0只有 1 个元素，不用比
换底logₐ n = log_b n ÷ log_b a不同底数只差一个常数倍，所以复杂度里不写底数（第 3 课）

Java 里：2ᵏ 用 1 << k（int 只到 k = 30）或 1L << k；Math.pow 返回 double（坑 4）。⌊log₂ n⌋ 用 31 - Integer.numberOfLeadingZeros(n)，这是纯整数运算；Math.log 是以 e 为底的 ln，Math.log10 以 10 为底，两者都返回 double（坑 3）。

算法里最常见的三种写法，都是在正整数上取整：中点 lo + (hi - lo) / 2 是下取整；分页数 ⌈a/b⌉ 写成 (a + b - 1) / b（a ≥ 0，b > 0）；堆的父节点 (i - 1) / 2（第 6 课，i ≥ 1，所以不会碰到负数）。Math.floor、Math.ceil 返回的是 double，Math.round(double) 返回 long。

洞察 3 · 取模：把一条直线绕成一个圈

容量是 2 的幂时，% 可以换成 &

i % 8 等于 i & 7（i ≥ 0），因为 8 = 2³，余数就是二进制的低 3 位。HashMap 把桶数取成 2 的幂，就是为了用 (n - 1) & hash 代替 %（JDK 17 源码）。负数 hash 时 h & (n-1) 的结果也和 floorMod 一样落在 [0, n)。

为什么 Java 不像 Python 那样向下取整

Java 沿用了 C 的做法：CPU 的除法指令（x86 的 IDIV、ARM 的 SDIV）都向零截断，C99 把这一点写进了标准。Python 选了下取整，所以 Python 里 -7 % 3 是 2。两种语言都满足规定 2，只是规定 1 不同。

洞察 4 · 求和：循环套循环一共跑几次，就是一个求和式

求和式算出来量级在哪见过
1 + 2 + … + n（等差）n(n+1)/2O(n²)插入排序、冒泡；第 i 轮比 i 次
两两配对 C(n, 2)n(n−1)/2O(n²)n 张单两两比一次（⑤ 第 5 题）
1 + 2 + 4 + … + 2ᵏ（等比，公比 2）2ᵏ⁺¹ − 1最后一项的 2 倍扩容摊还（第 3 课）；满二叉树节点数
n + n/2 + n/4 + …（等比，公比 ½）< 2nO(n)每层只处理一半的算法；堆的建堆也是这个路子
1 + 1/2 + 1/3 + … + 1/n（调和）≈ ln nO(log n)下一圈：筛法、随机算法的期望

求和符号 Σ 读作“把后面那项加起来”。Σᵢ₌₁ⁿ i 就是 for (int i = 1; i <= n; i++) sum += i;：下面写 i 从几开始，上面写加到几。看到 Σ，就把它当成一个 for 循环来读。

把六样放在一起：看数据范围，就知道该用什么复杂度

题目给出 n 的上限，其实就是在暗示该用多快的算法。按每秒大约 10⁸ 次简单操作估算（这是常用的估算口径，不是实测），每种复杂度能吃下的 n 如下表。先在下面的实验台里猜一题。

n 的上限1 秒内能接受的复杂度典型做法
≤ 10O(n!)全排列回溯
≤ 20O(2ⁿ)、O(2ⁿ·n)子集枚举、状态压缩
≤ 500O(n³)三重循环、区间 DP

实验台：n 变大，每种复杂度要跑多久

先猜：订单簿里有 10 万张单，用 O(n²) 的做法把它们两两比一遍，1 秒内能跑完吗？

估算模型：操作次数 ÷ 10⁸ 次/秒，算的是量级，不是实测。次数用对数算，所以 n! 这种天文数字也能显示。“int 装得下 / long 装得下”说的是这个次数能不能当计数器放进对应类型。

为什么这样设计：题目为什么都让“答案对 1e9+7 取模”

组合数、路径数涨得比 long 还快（洞察 5），题目只好让你输出余数。可模数为什么总是 1,000,000,007？把三种候选摆在一起，看哪一种能同时满足三个约束：

1e9 + 7（选中）

  • 两个余数相加 < 2×(10⁹+7) ≈ 2.0×10⁹，还在 int 范围里
  • 两个余数相乘约 10¹⁸，long（上限 9.2×10¹⁸）装得下
  • 是质数：除了 0，每个数都能“做除法”（有逆元）
  • 代价：乘法前必须先转 long（坑 6）

让 long 自然溢出（模 2⁶⁴）

  • 不用写 %，最快
  • 2⁶⁴ 不是质数，偶数没有逆元，做不了除法
  • 拿它做字符串哈希时，有现成的构造能让两个不同的串算出同一个值

10⁹（看着整齐）

  • 也满足“加不爆 int、乘不爆 long”
  • 10⁹ = 2⁹ × 5⁹，所有 2 和 5 的倍数都没有逆元
  • 组合数要除以 k!，k! 里一般都有 2 和 5，模 10⁹ 时这一步做不了
决定胜负的约束：结果要装进 int，乘一次不能爆 long，还得能做除法。在 2³¹ 以内、又离它不太近的质数里，10⁹+7 最好记，于是成了惯例。另一个常见的 998244353 也满足这三条，它是为另一种算法（NTT）选的。

先看返回类型

pow、sqrt、log、log10、floor、ceil 都返回 double；round(double) 返回 long，round(float) 返回 int；abs、max、min、floorDiv、floorMod 的返回类型和参数一样。

只要中间走过一趟 double，就可能带进精度误差。所以算法里能用整数算的，就别经过 double。

// ⌊log₂ n⌋：不经过 double
static int floorLog2(long n) { return 63 - Long.numberOfLeadingZeros(n); }

// ⌈a / b⌉，a ≥ 0，b > 0
static long ceilDiv(long a, long b) { return (a + b - 1) / b; }

// C(n, k)：边乘边除，不先算 n!
static long comb(int n, int k) {
    k = Math.min(k, n - k);
    long r = 1;
    for (int i = 1; i <= k; i++) r = r * (n - k + i) / i;  // 每一步都整除
    return r;
}

⑥边界和变体

第一圈 · 注意事项：每一条都在 JDK 17 上跑过

1负数的除法和取模实测← ④ 洞察 2、3
现象
-7 / 2 = −3，-7 >> 1 = −4，Math.floorDiv(-7, 2) = −4；-7 % 3 = −1，Math.floorMod(-7, 3) = 2。
根源
/ 向零截断，% 是被等式 (a/b)*b + a%b == a 逼出来的，所以符号跟着被除数；右移是下取整，所以和 /2 在负数上差 1。
做法
可能出现负数的下标、分桶、环形位置，一律用 Math.floorMod；要下取整的除法用 Math.floorDiv。
2Math.round 碰到 .5实测← ④ 洞察 2
现象
round(2.5) = 3，round(-2.5) = −2，round(-2.6) = −3。Math.rint(2.5) = 2.0，rint(3.5) = 4.0。
根源
按 Javadoc，round 的 .5 一律往正无穷进，不是“绝对值进一”。rint 碰到 .5 取偶数，也就是银行家舍入。
做法
金额不要用 double 再 round。价格存成“分”的 long（第 1 课），或者用 BigDecimal 并写明 RoundingMode。
3用 Math.log 算 log 再取整实测← ④ 洞察 1
现象
Math.log(1000) / Math.log(10) = 2.9999999999999996，取整得 2。在 10⁰～10¹⁸ 里，10³、10⁶、10⁹、10¹²、10¹³、10¹⁵、10¹⁸ 都少算 1；用 log(v)/log(2) 算 2ᵏ − 1，k ≥ 48 时都多算 1。
根源
两次 log 各带一点误差，相除后正好落在整数下面一点点。2ᵏ − 1 和 2ᵏ 的对数只差约 1/(2ᵏ·ln 2)，k ≥ 48 时这个差比 double 在 48 附近能分辨的最小间隔还小；k ≥ 54 时，2ᵏ − 1 存进 double 就已经变成了 2ᵏ。
做法
⌊log₂ n⌋ 用 31 - Integer.numberOfLeadingZeros(n)（long 用 63）；十进制位数用循环除以 10，或者 Long.toString(n).length()；非要用 double，就用 Math.log10，再拿整数验一下结果。
4Math.pow 返回的是 double实测← ④ 洞察 1
现象
3³⁹ 用循环乘，得到 4052555153018976267；(long) Math.pow(3, 39) 得到 4052555153018976256，差了 11。
根源
double 只有 53 位有效位，超过 2⁵³ ≈ 9×10¹⁵ 的整数就存不准了（第 1 课）。
做法
整数幂用循环乘或快速幂（见第三圈），2 的幂用移位；结果可能超过 long 时用 BigInteger.pow。
5移位超过位宽实测← ④ 洞察 1
现象
1 << 31 = −2147483648；1 << 32 = 1，不是 0；1L << 32 = 4294967296。
根源
历史原因（JLS §15.19）：int 移位只取移位数的低 5 位，long 取低 6 位，所以 << 32 等于 << 0。和 x86 移位指令的做法一致，从幂的数学里推不出来。
做法
k 可能 ≥ 31 时用 1L << k，并且确认 k < 63。
6中间结果溢出：公式对，算的时候爆了实测← ④ 洞察 4
现象
lo = 1.5×10⁹、hi = 2×10⁹ 时，(lo+hi)/2 = −397483648；(long)(n*(n+1))/2 在 n = 10⁵ 时得到 705082704；int a*b % M（a = b = 999999999）得到 808348673，正确答案是 64。
根源
求和、乘积的量级远比单个数大（n 是 10⁵，n² 就是 10¹⁰）。Java 先按 int 算完，再做转换，转换的时候已经晚了。
做法
中点写 lo + (hi - lo) / 2 或 (lo + hi) >>> 1；乘之前先把一个乘数转成 long：(long) n * (n + 1) / 2；拿不准时用 Math.multiplyExact，溢出会直接抛 ArithmeticException。

第二圈 · 使用规范

  • 计数、求和、乘积一律用 long：防的是坑 6，两两配对的次数在 n = 65537 时就超过 int 上限了。
  • 能用整数算的不走 double：防的是坑 3、坑 4。log₂ 用 numberOfLeadingZeros，幂用移位或循环乘。
  • 下标、分桶、环形位置用 floorMod：防的是坑 1，负数 hash 一定会出现（hashCode 本来就可能是负数）。
  • 上取整写成一个函数，不要到处手写：(a + b - 1) / b 只在 a ≥ 0、b > 0 时成立；JDK 18 起直接用 Math.ceilDiv。
  • 取模题每做一步就取一次模：(long) a * b % M，减法写 ((a - b) % M + M) % M。防的是中间值溢出，以及减法得到负数。
  • 金额不用 double：用“分”的 long，或者 BigDecimal（第 1 课）。

第三圈 · 更深一点：把 log 反过来用

快速幂：算 aⁿ 只要乘 log n 次

a¹³ = a⁸ · a⁴ · a¹，因为 13 的二进制是 1101。每轮把 a 平方一次，指数右移一位，碰到 1 就乘进结果。n = 10¹⁸ 也只要转约 60 轮，这就是洞察 1 里的 log 反过来用。本机实测：2^(10^18) mod 1e9+7 = 719476260。

long r = 1; a %= m;
while (e > 0) {
    if ((e & 1) == 1) r = r * a % m;
    a = a * a % m;  e >>= 1;
}

最大公约数：辗转相除也是 O(log n)

gcd(a, b) = gcd(b, a % b)，直到 b = 0。每两轮，较大的那个数至少减半，所以步数是 O(log n)。最小公倍数写 a / gcd(a, b) * b，先除后乘，防溢出。实测 gcd(84, 36) = 12，lcm = 252。

2 的幂判断：n > 0 && (n & (n - 1)) == 0。2 的幂在二进制里只有一个 1，减 1 后那个 1 变成 0，低位全变成 1，两者按位与就是 0。

自测

1. 用一句话说出这一页的精华

学算法只要六样中学数学：幂、对数、取整、取模、求和、排列组合，用来看懂复杂度；再加上 Java 整数的规则：位数有限、除法向零截断、% 跟着被除数的符号，用来把边界写对。

2. 只背公式、跳过这一层，会在哪里吃亏？

能说出“二分是 O(log n)”，却说不清为什么是 20 次；在 Java 里写出 n*(n-1)/2、(lo+hi)/2、负数 % 这类代码，小数据测试全过，数据一大就出错，而且不报错。

3. 负数 hash 用 % 分桶会得到负下标，根源是哪条原理？

Java 的整数 / 向零截断，% 又必须满足 (a/b)*b + a%b == a，所以余数的符号跟着被除数。被除数是负数，余数就是负数或 0。

从 ④ 洞察 3 推出。

4. 预测：10 亿个价位按价格排好序，二分查找最多比几次？如果数据量变成原来的平方，也就是 10¹⁸ 个呢？

2³⁰ ≈ 1.07×10⁹ > 10⁹ > 2²⁹，所以 ⌊log₂ 10⁹⌋ = 29，最多比 30 次。n 变成 n² 后，log(n²) = 2 log n，大约 60 次，只多一倍。

从 ④ 洞察 1：2¹⁰ ≈ 10³，以及 log(xᵏ) = k log x 推出。

5. 预测：n 等于多少时，两两配对的次数 n(n−1)/2 第一次超过 int 上限？

n(n−1)/2 > 2³¹ − 1，等价于 n(n−1) ≳ 2³² ≈ 4.29×10⁹，所以 n ≈ 65537。n = 65536 时是 2,147,450,880，还差一点；n = 65537 时是 2,147,516,416，超了。只要单数到 6 万多就会出事，比很多人估计的要早得多。

从 ④ 洞察 4 的 n(n−1)/2，以及 2³¹ − 1 ≈ 2.1×10⁹ 推出。

6. 预测：Math.floorMod(-7, -3) 和 -7 % -3 各是多少？

-7 % -3：-7 / -3 = 2（2.33 向零截断），余数 = -7 − (2 × −3) = −1。floorMod(-7, -3)：floorDiv = ⌊2.33⌋ = 2，余数同样是 −1。除数是负数时，floorMod 的符号跟着除数，结果落在 (−3, 0]。

从 ④ 洞察 3 的两条规定推出：先定除法怎么取整，余数由等式算出来。

7. 放回全景：撮合引擎第 3 站（网关到撮合之间的环形队列）要是把下标写成 tail % cap，而 tail 是一直递增的 int，跑久了会怎样？

tail 一直加，超过 2³¹ − 1 后绕成负数，tail % cap 跟着变负，写队列时抛 ArrayIndexOutOfBoundsException，撮合线程挂掉，这一段的委托全部卡住。按每秒 100 万笔算，大约 36 分钟就会溢出。修法有三种：tail 用 long；cap 取 2 的幂并写 tail & (cap - 1)（负数时也落在 [0, cap)）；或者用 floorMod。

从 ④ 洞察 3（% 的符号、2 的幂可以用 &）和 int 上限推出。
