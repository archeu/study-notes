单调栈和单调队列：过去 60 秒最高价，每笔 O(1)

一笔价格如果比它后来的某一笔还低，它就再也当不上最高价了，可以马上扔掉。只留下“后面没人压得住它”的那些，剩下的自然从高到低排好：单调队列的队头就是窗口最高价，单调栈的弹出时刻就是“等到了更高价”。每笔进一次、出一次，摊下来每笔 O(1)。

①要解决的问题：窗口在滑，最高价每笔都要更新

在全景第 7 站，撮合线程每吐出一笔成交，行情模块就要回答“过去 60 秒最高价是多少”。按每秒 1 万笔算，窗口里有 60 万笔，而且窗口每笔都往右挪一格：进来一笔新的，掉出去一笔旧的。同一站还有另一个问题：每一笔成交之后，第一笔比它高的是哪一笔（多久后被“突破”）。

行情速度1 万笔/秒全景页的假设
窗口长度60 秒窗口里 60 万笔
要做到每笔 O(1)摊还，不随窗口变大
面试对应LC 239 / 739滑动窗口最大值、每日温度

②朴素做法：每笔扫一遍，或者只记一个最大值

  • 做法 A：每笔 O(W)，W 是窗口里的笔数。窗口一大就追不上行情。
  • 做法 B：只能处理“只进不出”。窗口会掉出旧数据，一个变量就不够了。
  • “下一个更高价”的朴素做法也一样：每笔往后扫，一路下跌再暴涨时是 O(n²)。
不懂精华时的典型误用：知道要“候补名单”，就把窗口里的每一笔都放进堆或 TreeMap。能对，但留了一堆永远不会当上最高价的人：本机实测堆的延迟删除版本到最后存了近 300 万个对象（坑 4）。

③几种思路：候补名单怎么存

都是给“最高的走了，谁接班”准备一份候补名单，差别在名单里留了谁、怎么排。下面的数字是同一份行情（300 秒、每秒 1 万笔、窗口 60 秒）在本机跑出来的，见 ⑤。

思路名单里留谁每笔代价本机每笔名单最长
每笔重扫窗口不留，现扫O(W)约 820,000 ns—
堆 + 延迟删除所有人，过期的等浮到堆顶再扔O(log n)约 130 ns2,983,727（只涨不跌）
TreeMap<价格, 笔数>窗口里每个不同价格O(log k)约 340 ns83,315
单调队列只留“后面没人压得住”的摊还 O(1)约 14 ns2,051
稀疏表（ST 表）预先算好每段 2k 长的最大值查 O(1)，建 O(n log n)没测数据一变就要重建

本页学单调队列和单调栈：窗口两头进出（新的从右边进，旧的从左边出），只问最大或最小，就用单调队列；问“下一个更大 / 更小”，就用单调栈。要在任意区间上随便问、数据又不变，才轮到稀疏表；要在窗口里删任意一笔、问第 k 大，才轮到 TreeMap。

④关键洞察：被压住的，永远翻不了身

先知道这些
  • 双端队列：两头都能进出，Java 里是 ArrayDeque，底下是一个环形数组。第 5 课讲过：栈、队列和环形数组。
  • 摊还：某一次操作可能很贵，但一长串操作的总代价除以次数很小。第 3 课：摊还。

洞察 · 比你晚来、又不比你低的人一出现，你就没机会了

不变式 · 队列从头到尾：时间越来越晚，价格越来越低

把所有被压住的都扔掉，剩下的人两两之间都没有压住关系：后来的一定更低。于是队列自动排好了序，队头就是最高价。每来一笔做三件事，顺序不能乱：

  1. 1 队尾弹新价格 p 来了，队尾只要 ≤ p 就弹掉（它们被 p 压住了），直到队尾比 p 高或者队空。
  2. 2 入队尾把 (时间, p) 放进队尾。存时间，是为了第 3 步知道谁过期了。
  3. 3 队头弹要回答“现在的最高价”前，先把时间 ≤ now − 60 秒 的队头弹掉，剩下的队头就是答案；队空就是“窗口里没有成交”。

单调栈 · 被弹出的那一刻，就是等到了更高价

“下一个更高价”反过来想：栈里放还没等到更高价的成交。新来一笔 p，栈顶只要 < p，它就等到了，答案就是 p，弹掉；一直弹到栈顶 ≥ p，再把 p 压栈。栈里从底到顶价格不升，道理和单调队列一样：没等到的人里，后来的一定不比先来的高，否则先来的早就被它弹走了。

为什么每笔 O(1)：每个人一辈子只进一次、最多出一次

第 8 秒那一步弹了 3 次，看起来不是 O(1)。换个数法：不数“每一步弹几次”，数“每个人被弹几次”。n 笔成交，每笔入队 1 次、出队最多 1 次，总操作 ≤ 2n，平均每笔 ≤ 2 次，这就是摊还 O(1)。单调栈同理。单笔的最坏情况仍然是 O(W)（一路跌了很久，突然一笔暴涨），延迟敏感时要知道这一点（坑 6）。

为什么这样设计

单调队列：被压住的立刻扔

  • 扔掉的人对以后每一次查询都没用，不丢答案
  • 剩下的天然有序，不用比较排序，队头就是答案
  • 旧的从头走、新的从尾进，正好是双端队列能 O(1) 做的
  • 代价：只能问最大（或最小），问不了第 2 大、中位数

堆 / TreeMap：所有人都留着

  • 能问更多：第 k 大、删任意一笔
  • 每次进出 O(log n)，还要比较、建节点
  • 堆删不了中间的过期元素，只能延迟删除，名单只涨不跌
决定胜负的约束：窗口是先进先出地滑（掉出去的一定是最早的），查询又只问最大。这两条一起成立，“被压住”才是永久的，才敢扔。窗口能删任意一笔（比如撤单），或者要问第 2 大，这个洞察就不成立了，得回到 TreeMap。
ArrayDeque 当双端队列 / 栈细节放到 ⑥
Deque<long[]> dq = new ArrayDeque<>();
dq.peekLast();  dq.pollLast();  dq.offerLast(x); // 队尾
dq.peekFirst(); dq.pollFirst();                  // 队头

// 当栈用：push / pop / peek 都在“头”这一端
Deque<Integer> st = new ArrayDeque<>();
st.push(i); st.peek(); st.pop();

存什么

队列里存时间（或下标），不只存价格：过期要看时间，相等的价格要分得清谁是谁。单调栈里存下标，弹出时才能把答案写回 ans[j]。

不要用 java.util.Stack：它继承 Vector，每个方法都加锁；JDK 文档自己写着优先用 Deque（坑 5）。

⑤WindowMax.java（核心）完整代码 →
private final Deque<long[]> dq = new ArrayDeque<>();   // {时间毫秒, 价格}

public void onTrade(long timeMs, long price) {
    while (!dq.isEmpty() && dq.peekLast()[1] <= price)
        dq.pollLast();                         // 被新来的压住了，永远当不上最高
    dq.offerLast(new long[]{timeMs, price});
}

public long max(long nowMs) {                  // 窗口 (now - window, now]
    while (!dq.isEmpty() && dq.peekFirst()[0] <= nowMs - windowMs)
        dq.pollFirst();                        // 按时间过期，不按笔数
    return dq.isEmpty() ? -1 : dq.peekFirst()[1];
}

⑥边界和变体

第一圈 · 注意事项

1窗口按笔数滑，冷清时最高价停在很久以前实测← ④ 不变式第 3 步
现象
09:00 成交一笔 120，冷清 10 分钟，09:10 来了 100、101。“最近 3 笔最高价”答 120，那是 10 分钟前的价；“过去 60 秒最高价”答 101。
根源
过期要看时间，不是看队列里有几个。队列里存了时间，第 3 步才能按时间弹队头；查询前没先弹，或者窗口里没成交时返回了上一个值，都会答出旧价。
做法
每次查询前先按 now 清队头；队空返回“无”（本页返回 -1），由展示层决定显示“—”。
2相等的价格弹不弹实测← ④ 单调栈
现象
队列里弹 <= 和弹 <，最高价都对，但 10 笔都是 100 时一个队列长 1、一个长 10。单调栈里写成 <=，100 100 101 的第 0 笔会说“下一个更高价是第 1 笔的 100”，错了。
根源
队列只问最大值，相等的谁留都一样，弹掉更省；栈问的是“严格更高”，相等的那笔不算等到。题目问“更大或相等”时反过来。
做法
先写下问的是 > 还是 ≥，再决定弹的条件；在代码旁边写一行注释说清。
3迟到的成交把队列搞乱实测← ④ 洞察
现象
先到 105@10 秒，再到一笔迟到的 108@6 秒：108 从队尾弹掉了 105，自己排进队列。第 10 秒查询，108 已过期被弹掉，队列空了，答“无”，正确答案是 105。
根源
“被压住就永远没机会”的前提是后来的不早于先来的。时间倒着来，晚到的那笔其实更早过期，它压不住任何人。
做法
只喂撮合线程按顺序产出的成交（全景第 6 站出来就是有序的）；数据来自多个源时，先按时间排序或者设一个等待水位，再进队列。
4用堆做窗口最大值，内存只涨不跌实测← ④ 为什么这样设计
现象
⑤ 的测速里，PriorityQueue + 延迟删除到最后存了 2,983,727 个元素，300 万笔几乎一笔没扔。
根源
堆只能删堆顶。过期但价格低的元素沉在堆底，永远浮不上来；行情一路走高时，它们一直占着内存。
做法
只问最大值就用单调队列；非要用堆，定期整堆重建，或者换 TreeMap 按价格计数、出窗口时精确删除。
5用 java.util.Stack 当栈历史原因
现象
代码能跑，但每次 push/pop 都进一次 synchronized；Stack<Integer> 还要装箱。
根源
Stack 是 JDK 1.0 的类，继承 Vector，方法都加锁。JDK 17 源码的类注释自己写着：更完整的栈操作在 Deque 里，应该优先用它；ArrayDeque 的注释说它当栈用比 Stack 快。
做法
单线程用 ArrayDeque；存的是 int 下标、长度有上限时，直接 int[] + top，像 ⑤ 那样。注意 ArrayDeque 不能放 null。
6摊还 O(1) 不等于每笔都快← ④ 摊还
现象
行情一路跌了 60 秒，谁都弹不掉，队列长到 60 万；然后一笔暴涨，这一笔要弹 60 万次。平均很快，这一笔的延迟是平时的几万倍。
根源
摊还说的是一长串操作的平均。单笔最坏仍是 O(W)，内存最坏也是 W。
做法
行情计算通常能接受；要严格控制单笔延迟（比如撮合主线程上），把行情计算挪到撮合线程之外，或者用环形数组预分配好 W 个格子，免得扩容再叠一次停顿。

第二圈 · 使用规范

  • 队列里存时间或下标，不只存值：防坑 1、坑 3，过期判断和相等价格都要靠它。
  • 在类上写一行不变式注释：“从头到尾时间递增、价格严格递减”。防别人改代码时把 <= 改成 < 而不知道后果。
  • 先写清“严格”还是“不严格”：防坑 2，> 和 ≥ 各对应一个弹出条件。
  • 查询前先清过期，队空返回“无”：防坑 1 的旧价。
  • 用 ArrayDeque 或数组，不用 Stack / LinkedList：防坑 5 的锁和多余的节点对象。

第三圈 · 变体和深处

单调栈是一类题的固定套路：“左边 / 右边第一个比我大 / 小的是谁”。看清栈里放什么、弹出那一刻算什么，就能认出来。

题栈里放（从底到顶）弹出那一刻算什么
LC 739 每日温度下标，温度不升等了几天：i − j
LC 901 股票价格跨度（价格, 跨度），价格严格降把被弹者的跨度加到自己身上：今天往前连续几天 ≤ 今天
LC 84 柱状图最大矩形下标，高度递增以被弹那根为高，左右边界就是新栈顶和 i，算面积
LC 42 接雨水下标，高度递减被弹的是坑底，左边新栈顶和右边 i 夹出一层水
LC 503 下一个更大元素 II下标数组是环：遍历 2n 次，下标取 i % n

单调队列 + 前缀和、+ DP

LC 862“和至少为 K 的最短子数组”有负数，滑动窗口失效，要在前缀和数组上维护单调递增队列（第 12 课 前缀和会回到这里）。LC 1696“跳跃游戏 VI”：dp[i] = nums[i] + max(dp[i−k..i−1])，那个 max 就是滑动窗口最大值，DP 从 O(nk) 降到 O(n)。

双栈队列：什么聚合都能做

单调队列只能做最大、最小这类“能压住别人”的。要窗口里的和、gcd、矩阵乘积，用两个栈拼一个队列，每个栈元素顺带存“从栈底到我”的聚合值，查询时把两个栈顶的聚合合起来，同样摊还 O(1)，只要求运算满足结合律。

同时要最高和最低

开两个队列：一个价格递减（最高），一个价格递增（最低），振幅 = 两个队头相减。1 分钟 K 线的高、低也能这样算，但 K 线是固定窗口（每分钟清零），直接用变量记就够了，不需要队列。

稀疏表：数据不变时更快

一天的成交收盘后不再变，回测时要问任意区间最值：预处理每个位置往后 2k 长的最大值，O(n log n) 建好，任意区间拆成两段重叠的 2k 段，O(1) 回答。数据在变就不划算。

面试官会怎么问

滑动窗口最大值，能不能用堆？复杂度多少？

能。堆里放（值, 下标），取堆顶前把下标出窗口的弹掉，O(n log n)。单调队列 O(n)。追问“堆为什么不能直接删过期的”：堆只支持删堆顶，删中间要先找到它，O(n)；Java 的 PriorityQueue.remove(Object) 就是线性查找。

单调队列里一步可能弹很多个，为什么说是 O(n)？

每个元素最多进一次、出一次，总操作 ≤ 2n。按“每个元素被处理几次”数，不按“每一步做几次”数。

什么时候单调栈，什么时候单调队列？

问“左 / 右第一个比我大 / 小的”，用栈：只在一头进出。问“窗口里的最大 / 最小”，用队列：新的从尾进、过期的从头出。

自测

1. 用一句话说出这一页的精华

比你晚来、又不比你低的人一出现，你就再也当不上最高价，可以马上扔；扔完剩下的天然有序，队头就是答案，每人进出各一次，摊还 O(1)。

2. 只记一个 max 变量，缺的是什么？

缺“候补名单”：最高的那笔掉出窗口后，不知道第二高是谁，只能重扫 O(W)。

3. 堆的延迟删除为什么会让内存只涨不跌？是哪条原理决定的？

堆只能删堆顶，过期的低价沉在堆底浮不上来。单调队列能马上扔，是因为窗口先进先出、只问最大，“被压住”是永久的。

从 ④ 为什么这样设计推出。

4. 预测：行情一路上涨（每笔都比上一笔高），队列最长多长？一路下跌呢？

一路涨：每笔都把前面的全弹掉，队列永远只有 1 个。一路跌：谁都弹不掉，队列和窗口一样长，60 秒就是 60 万个。

从 ④ 洞察推出：只有“更晚又不更低”的才能压住别人。

5. 预测：把队列的弹出条件从 <= 改成 <，查询结果会变吗？

不会，最高价还是对的；只是相等的价格都留在队列里，队列更长。单调栈里改了就会错，因为栈问的是“严格更高”。

从 ④ 不变式和单调栈推出。

6. 放回全景：第 7 站前后各发生了什么？这一页的东西坏了，整条链路会怎样？

前面是第 6 站挂单撤单：撮合线程按顺序吐出成交，第 7 站拿这些成交更新 K 线和“过去 60 秒最高价”；后面是第 8 站查询，盘口和成交查询会把这些行情数据给用户看。第 7 站按笔数滑或者迟到的成交没处理，行情页显示错的最高价，撮合本身不受影响；要是把每笔重扫放在撮合线程上，就会拖慢撮合，整条链路排队。
