贪心：每一步只拿眼前最好的，什么时候不会后悔

贪心就是每一步都拿眼前最好的那个，拿了不回头。它快（往往排个序再扫一遍），但只有在能证明“这一步拿了，最优解里也有它”时才对；证明的办法叫交换论证。证明不了，就是第 20～22 课回溯和 DP 的地盘。

这一页的位置第五圈“算法思想：解法是怎么想出来的”的第一课。前四圈学的是“数据怎么放”，这一圈学“解法怎么想”。其实你已经见过贪心：第 18 课的 Dijkstra 每次取离起点最近的点定下来，就是贪心。这一课把“为什么能贪”讲清楚，再看它在哪里失灵，那里就是第 21 课 DP 的起点。

①要解决的问题：回测站要两个答案

全景第 12 站，收盘后拿今天的价格做回测。两个问题都要尽快给出答案：

一年交易日≈ 250天，一天一个收盘价
分钟级回测≈ 36 万个价格点（250 天 × 1440 分钟）
要的速度O(n)扫一遍就要出结果

②朴素做法：把每一种买卖方式都试一遍

每天只有三种动作：不动、买、卖。把所有走法列出来，取最赚的那条。这一定对，但走法的数量是指数级。

做法对不对多快
枚举所有买卖方式对（⑤ 里拿它对拍）每天“持有 / 空仓”两种状态往下分叉，约 2ⁿ 条路；n = 30 就是 10 亿
找全天最低点买、最高点卖错：最低点 98 在最高点 108 之前，只赚 10，答案是 14O(n)
每段上涨都拿下对（④ 证明）O(n)，一遍
  • 枚举要 2ⁿ，36 万个价格点根本跑不完；第 20 课回溯讲怎么剪枝，也只能把 2ⁿ 砍小，不能变成 n。
  • “最低买最高卖”是只许买卖一次的答案，还要求最低在最高前面，问题一换就错。
  • 缺的那一块：一个“局部拿最好、拿了不后悔”的理由。有了理由，一遍扫完。
不懂精华时的典型误用：觉得“每步最好，加起来就最好”是常识，什么题都先贪一把。贪心对不对要证明；问题 2 里“最短的先排”“最早开始的先排”听着都合理，⑥ 的实验台里它们都会排少。

③几种思路：同一个“选什么”的问题，三种想法

思路怎么想什么时候用代价
贪心（本课）每一步按一个规则挑当前最好的，挑了就不改能证明“当前最好的那个一定在某个最优解里”通常 O(n log n)：排序 + 一遍
回溯（第 20 课）每一步把所有选择都试，走不通就退回来要列出全部方案，或者 n 很小指数级，靠剪枝省
动态规划（第 21、22 课）把“走到这一步、处在这个状态”的最好结果记下来，后面直接用当前选择会影响以后，但影响能用几个状态概括状态数 × 每个状态的选择数

本页学贪心：先试贪心，因为它最快；但写之前先问一句“这一步拿了，以后会不会后悔”。答得出“不会”，用贪心；答不出，退到 DP。

④关键洞察：拿了不后悔，要能换得过来

先知道这些
  • 排序：贪心大多先按某个规则排序，复杂度的大头是 O(n log n)，见 第 10 课。
  • 求和拆分：p[j] − p[i] 等于中间每天差价之和，这是 第 12 课前缀和的反过来用。

洞察 1 · 任何一次买卖，都能拆成“每天的差价”

第 i 天买、第 j 天卖，赚的是 p[j] − p[i] = (p[i+1] − p[i]) + … + (p[j] − p[j−1])。所以不管怎么买卖，总收益都是若干个“相邻两天差价”之和，而且每个差价最多用一次（手里最多一份）。

洞察 2 · 交换论证：把最优解的第一步换成贪心的那一步，不会变差

问题 2 里，每个格子不再互不影响：选了一个任务，和它重叠的都不能选。规则选“最早结束的先排”。为什么对？

洞察 3 · 什么时候会后悔：这一步的选择改变了以后能选什么、值多少

不会后悔

  • 每天差价互不影响（洞察 1）
  • 结束越早，留给后面的时间越多，没有坏处（洞察 2）

会后悔 · 手续费

  • 每次买卖扣 2。连涨两天时“拆成两笔”要付两次费，“合成一笔”只付一次；今天卖不卖，取决于明天还涨不涨

会后悔 · 怪面额

  • 面额 {1,3,4} 凑 6：先拿 4，剩 2 只能 1+1，共 3 枚；最优是 3+3 两枚。拿了 4，堵死了 3+3
决定能不能贪的约束：这一步拿了以后，剩下的问题是不是“和原来一样、只是变小了”，而且不会因为这一步变得更差。是，就能用交换论证；不是（手续费把相邻两步绑在一起、面额让一种拿法堵死另一种），就要把“处在什么状态”记下来，这就是 DP。

为什么这样设计：先排序，再一遍扫

贪心：排序 + 一遍

  • O(n log n)，不用额外表格
  • 可以边读边算（问题 1 连排序都不用，来一个价格算一次）
  • 代价：要先证明，证明不了就不敢用

DP：把每个状态都记下

  • 不用证明，“所有可能都考虑过了”
  • 要定义状态、开表格；问题 2 用 DP 要先排序再二分找前一个不冲突的任务，也是 O(n log n)，但写起来长三倍
决定胜负的约束：贪心的“每步只看一个规则”是靠问题结构换来的。结构在（能交换），贪心又短又快；结构不在，它连对都不对。所以工程里贪心常和对拍一起出现：先写一个小规模的暴力，随机数据比一比。
两种贪心的骨架细节放到 ⑥
// 1. 互不影响：能拿的都拿
for (int i = 1; i < p.length; i++)
    if (p[i] > p[i-1]) sum += p[i] - p[i-1];

// 2. 有冲突：按规则排序，能放就放
Arrays.sort(jobs, (a, b) ->
    Integer.compare(a[1], b[1])); // 按结束时间
int end = Integer.MIN_VALUE;
for (int[] j : jobs)
    if (j[0] >= end) { count++; end = j[1]; }

写贪心前的三问

1. 按什么排序、每步挑哪个？
2. 能不能把最优解的第一步换成我挑的，还不变差？
3. 挑完以后，剩下的是不是同一个问题、变小了？
三问都答得上，再写代码；答不上，写个暴力对拍一下就知道。

// 暴力：每天“不动 / 买 / 卖”全试一遍，只拿来对拍
static long brute(int[] p, int day, boolean holding, long cash, int fee) {
    if (day == p.length) return holding ? Long.MIN_VALUE / 4 : cash;
    long best = brute(p, day + 1, holding, cash, fee);                 // 不动
    if (holding) best = Math.max(best, brute(p, day + 1, false, cash + p[day] - fee, fee));
    else         best = Math.max(best, brute(p, day + 1, true,  cash - p[day], fee));
    return best;
}
// 2000 组随机价格，贪心和暴力逐组比
for (int t = 0; t < 2000; t++) {
    int[] p = randomPrices(r, 1 + r.nextInt(14));
    if (maxProfitUnlimited(p) != brute(p, 0, false, 0, 0)) mismatch++;
}

读出来的结论
  • 不限次数的贪心在 2000 组随机数据上和暴力完全一致，④ 洞察 1 的证明站得住。
  • 加 2 块手续费，同一个贪心少赚 1：在 2→8 和 4→9 两段之间，“8 卖了 4 再买”多付了一次费，持有到 9 更好。
  • 区间调度四条规则里，只有“最早结束”一次没错；“冲突最少”一万组里也错了 13 组。
  1. 1 先写暴力小规模（n ≤ 14）的暴力是标准答案，几行就能写完。
  2. 2 再写贪心一遍扫，或排序 + 一遍扫。
  3. 3 随机对拍固定种子，跑几千组；有一组不一致，就打印出来看是规则错还是证明错。
到这里已经能交差了：不限次数的买卖、区间调度都能写出来，并且有对拍证明它对。
已知还没处理的细节：手续费下贪心失灵（坑 1），排序规则选错（坑 2），面额贪心（坑 3），端点相等算不算冲突（坑 4）。

⑥边界和变体

第一圈 · 注意事项

1加了手续费、冷冻期，还用每段上涨都拿实测← ④ 洞察 3
现象
价格 [1,3,2,8,4,9]、手续费 2：贪心算出 7，正确是 8。
根源
手续费让相邻两笔交易绑在一起：今天卖不卖，取决于明天涨不涨。差价不再互不影响，洞察 1 的拆分失效。
做法
用 DP 记“今天收盘时持有 / 空仓”两个状态，见第 21 课。也有带“延迟卖出”的贪心写法，但要单独证明，不如 DP 直接。
2排序规则凭感觉选实测← ④ 洞察 2
现象
“最早开始”一万组错 2934 组；“最短的先排”错 379 组。
根源
只有“最早结束”能通过交换论证：换进来的任务结束不晚，留给后面的时间不会少。最早开始的任务可能很长，把后面全占了。
做法
写之前做一次交换论证；做不出，写暴力对拍，用反例说话。
3找零、拆单先拿最大的实测← ④ 洞察 3
现象
面额 {1,3,4} 凑 6，贪心 3 枚，最优 2 枚。
根源
拿了 4，剩下的 2 只能用小面额补；“3+3”这条路被堵死。人民币面额 {1,2,5,10,…} 恰好是能贪的（每个面额 ≥ 小面额的组合能替代的部分），这是面额体系特意设计的，不是普遍规律。
做法
面额是配置出来的（积分、券、拆单手数），一律用第 22 课的完全背包 DP。
4区间端点相等算不算冲突
现象
[10,11) 和 [11,12) 是否能连着排，写成 > 还是 >=，结果差一个。
根源
这是题意，不是算法：左闭右开（结束那一刻机器就空了）用 start >= end；闭区间用 >。
做法
先在代码注释里写明区间是 [start, end) 还是 [start, end]，和第 9 课二分的边界一样，先定区间再写比较。

第二圈 · 使用规范

  • 贪心代码旁边留一句证明或一个对拍测试：防以后有人改了题意（加手续费）却不知道贪心前提没了。
  • 排序用 Integer.compare，不写 a[1] - b[1]：时间戳是 long 或者有负数时，相减会溢出，排出错序（第 1 课）。
  • 证明不了就别上线贪心：用 DP 先求正确答案，再看能不能优化成贪心；顺序反过来会把错误的“快”带进生产。

第三圈 · 贪心在你熟悉的系统里

Dijkstra 就是贪心

第 18 课：每次从堆里取离起点最近的点“定下来”。交换论证靠的是“边权非负”：后面再绕，路只会更长。有了负边，定下来的点可能后悔，所以负边要换 Bellman-Ford。

Huffman 编码

gzip 用的 DEFLATE 压缩里有 Huffman：每次把出现次数最少的两个合并。交换论证：最少的两个一定可以放在最深的一层。实现就是第 6 课的堆。

最小生成树

Kruskal 按边权从小到大，不成环就选（成没成环用第 17 课的并查集查）；Prim 每次加离当前树最近的点。后端很少直接用，知道它们都是贪心即可。

什么时候贪心一定对：拟阵

数学上有一类结构叫拟阵（matroid），在上面“按权重从大到小、能加就加”一定最优，生成树就是一例。面试和工作里不用会证明，知道“贪心正确有一整套理论”就够。

实验台：四条排序规则，哪条会少排

先猜：一台回测机排任务，“冲突最少的先排”在几百组随机数据里会不会错？

浏览器里现算：固定种子生成随机任务（开始 0～23 点，长 1～最长小时，左闭右开），最优解用 2ⁿ 暴力求，和 ⑤ 的 Java 版是同一个方法。组数和种子不同，次数和 ⑤ 不会一样。

下一圈

  • 带权区间调度：每个任务有收益，要收益最大而不是个数最多，贪心失灵，变成“排序 + 二分 + DP”。
  • 多台机器的区间调度：最少要几台机器才能排下所有任务，按开始时间排序 + 第 6 课的最小堆（会议室问题）。
  • 跳跃游戏、加油站、分发糖果：面试高频贪心题，第 25 课题型地图里归到这一课。
  • 反悔贪心：先贪，再用堆把“当初不该选的”换掉，介于贪心和 DP 之间。

↺回到⑤：改一改

  1. 打印买卖点：改 maxProfitUnlimited，除了总数，再输出每一笔“第几天买、第几天卖”。连续上涨的几天要合成一笔（[1,2,3] 是一笔 1→3，不是两笔），做对了 ⑤ 的价格会输出 3 笔。（洞察 1）
  2. 找出反例：让 BacktestSlots 在“冲突最少”出错时把那组任务打印出来，手画一下它错在哪一步。（坑 2）
  3. 会议室：同样的任务，有足够多台机器，最少要几台？按开始时间排序，用 PriorityQueue 存每台机器的结束时间。⑤ 的 7 个任务答案是 2。

自测

1. 用一句话说出这一页的精华

每步拿眼前最好的、拿了不回头；只有能用交换论证说明“最优解里也可以有这一步”时才对，说明不了就用 DP。

2. 枚举所有买卖方式差在哪？

每天持有 / 空仓两种状态往下分叉，约 2ⁿ 条路，n = 30 就是 10 亿；贪心一遍 O(n)。

3. 加了手续费为什么贪心就错了？是哪条洞察失效了？

洞察 1 的前提是“每天差价互不影响”。手续费让“连着两笔”和“合成一笔”付的费不同，今天卖不卖要看明天，差价之间有了依赖。

4. 预测：区间调度改成“最晚开始的先排”（从后往前看），对不对？

对。它就是“最早结束”的镜像：把时间轴倒过来，最晚开始就是最早结束，同一个交换论证照样成立。

从 ④ 洞察 2 推出：交换论证只要求“换进来的那个给剩下的问题留的空间不少”，倒过来看同样满足。

5. 预测：问题 1 改成“手里最多持有 2 份，每份独立买卖”，贪心答案怎么变？

还是每天差价互不影响，只是每个正差价可以吃两次：答案 = 2 × 14 = 28。只要“份数上限”对每一天都一样、每份独立，拆分照样成立。

从 ④ 洞察 1 推出：每个正差价最多被每一份各用一次。

6. 放回全景：第 12 站用错了贪心（带手续费），整条链路会怎样？

前面 11 站（网关到报表）都不受影响，坏的只是回测结果：策略收益被高估或低估，拿去做决策的人会选错策略参数。第 12 站是最后一站，错误不会再往下传，但会被人拿去用，所以要对拍。

档位：标准。本机跑过（2026-11-21，2 核 Neoverse-N1 虚机，OpenJDK 17.0.21，--release 8 编译）：⑤ 的所有输出，包括 2000 组对拍、手续费和面额反例、四条区间规则一万组对拍。实验台的数字是浏览器里用同样方法现算的。按公开资料：DEFLATE 用 Huffman 编码（RFC 1951）；Kruskal、Prim、拟阵上的贪心是教材结论，没有在本机实验。
