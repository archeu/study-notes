推理模型和“思考”：用 token 换质量

模型每写一个 token 的计算量是固定的，难题在一圈里“想”不完。推理模型的办法是先在同一个循环里写一段草稿（思考），再写回答：草稿写进前文，后面每一圈都能回看，等于多算了很多圈。代价是这些 token 照输出价收费、照输出速度等。实测同一道数数题，打开思考多花了 70～300 倍的 token；而 6 亿参数的小模型想了 2503 个 token，还是数错了。

这一页的位置站 02 第 6 个知识点。它就是第 1 页那个循环多写了一段，用到注意力的“回看前文”。Claude Opus 5.5 的思考关不掉，只能用 effort 调深浅，所以这一页直接关系到值班助手的成本和延迟。

①为什么需要：有些问题，一步说不出对的答案

在全景第 8 站，这一步要解决：值班助手问的不只是“是不是 GC”，还会问“这 10 分钟里停顿超过 200ms 的有几次”“堆在哪个时间点开始涨”。这些问题要逐行看、逐个比、再计数，一个 token 里给不出答案。第 1 页说过：结论一旦先写出来就改不了。那就让它先打草稿。

②没有它会怎样：直接答，或者在提示词里喊“一步一步想”

要求直接回答提示词里写“请一步一步思考”推理模型（内置思考）
多步的问题能想完不能：一圈的计算量固定，实测 3 次答 8、3、3，没有一次对能多想，推理过程写在回答里能，而且是训练出来的习惯：会检查、会回头改
回答干净，程序好解析能不能：推理和结论混在一起，要自己从长文里抠答案能：思考和回答分成不同的块返回
简单问题别浪费能不能：每次都写一大段看设置：Claude 的自适应思考会自己决定想多少，effort 调上限
又快又便宜能不能不能：实测多 70～300 倍输出 token

“一步一步想”这招叫思维链提示（Wei 等人 2022 年的论文让它出了名）：只是在提示词里要求，模型就会把推理写出来，难题的正确率明显提高。推理模型把这个习惯直接训练进了模型（④ 机制 2），并把草稿和回答分开放。

不懂精华时的典型误用：以为“思考”是模型在后台查资料、跑程序，所以开了思考就该算得准。思考只是多写一些 token、多转一些圈，它能放大模型本来就有的能力，补不上它没有的能力：数数、查值这种事，交给程序最可靠。

③相邻方案：花更多算力换正确率的几种办法

办法多花在哪适合
思维链提示回答里多写推理不能开思考的老模型、开源小模型
推理模型的思考单独的思考块，按输出计费多步推理、写代码、排障这类真正“要想”的问题
多次采样再投票同一个问题问 N 次答案短、能比较的判断题（采样页）
让程序算一次工具调用数数、算钱、查数据库：答案确定、程序算得对的事（站 04）

本页学推理模型的思考：用 Claude 时它默认就在，绕不开；要学的是它的原理、成本，以及什么时候该换成“让程序算”。

④原理：一圈的算力是固定的，想多算就多写

先知道这些
  • 每圈的计算量：每写一个 token，模型完整跑一遍，约“参数量”那么多次乘加，和问题难不难无关（够用的数学）。
  • 回看前文：每一圈都能通过注意力读到前面写过的所有 token（注意力）。

机制 1 · 草稿就是外接的内存：中间结果写进前文，后面的圈能读到

机制 2 · 怎么学会的：做可以验对错的题，答对就奖励

思维链提示是“临时要求”，推理模型是“练出来的”。公开资料（如 DeepSeek-R1 的论文）描述的做法是：拿数学题、编程题这种答案能自动判对错的题，让模型先想再答，答对就奖励、答错就惩罚（强化学习）。练多了，模型自己学会了写长思考、中途检查、发现不对就换思路。所以思考的长度不是写死的：难题想得长，简单题想得短。

  • 好处：在数学、代码、多步推理上，正确率随思考长度上升，这是推理模型的主要卖点。
  • 副作用：在没练过的题型上，它也会“习惯性多想”；小模型会想着想着把对的改成错的（⑤ 的思考片段就是这样）。

机制 3 · 计费和控制：思考是输出，按输出价收、算进 max_tokens

事实后果
思考 token 按输出计费，不管显示不显示Opus 5.5 输出每百万 20 美元：多想 1500 个 token，每次多 3 美分
思考算在 max_tokens 里上限给小了，思考写满就截断，回答一个字没有（⑤ 实测）
Claude Opus 5.5 的思考关不掉只能用 output_config.effort（low / medium / high / xhigh / max）调深浅，默认 medium（按文档）
思考内容默认不返回（display: "omitted"）流式时会先“卡”一会儿才出字；要给用户看进度，设 display: "summarized" 拿摘要；原始思考任何时候都不返回（按文档）

为什么这样设计：为什么用“多写 token”，而不是把模型做得更深

按需多写（思考）

  • 简单问题少想、难题多想，算力只花在需要的地方。
  • 不用改模型结构：还是同一个生成循环，KV 缓存、流式、计费全都照用。
  • 代价：延迟和费用随思考长度涨，而且要等思考写完才有回答。

把模型做深一倍

  • 每一圈都更聪明，回答也不用等草稿。
  • 每一个 token（包括“的”“，”）都要多付一倍的算力，简单问题也一样贵；训练成本也跟着翻倍。
决定胜负的约束：问题的难度差别极大，大多数 token（标点、套话、照抄的日志）根本不需要多想。按需把算力花在少数难题上，比给每个 token 都加算力划算得多；于是“推理时多花算力”成了提升能力的另一条路。

⑤亲眼看到：同一道数数题，关掉思考和打开思考

本机另起一个 llama-server（8091 端口），加载 Qwen3-0.6B：它和 Qwen2.5-0.5B 差不多大，但能用一个开关打开或关掉思考。题目是 10 行 GC 日志，问“停顿超过 200ms 的有几次”，真实答案 4 次，停顿值都离 200 远远的（最近的 158 和 236）。两种模式各跑 3 次（温度 0.6，seed 1～3，按 Qwen3 推荐的思考模式参数）。

⑤main.py（核心）完整代码 →
def ask(thinking, seed, max_tokens=3000):
    r = post("/v1/chat/completions", {
        "messages": [{"role": "user", "content": LOG + "\n\n" + QUESTION}],
        "max_tokens": max_tokens, "temperature": 0.6, "top_p": 0.95, "seed": seed,
        "chat_template_kwargs": {"enable_thinking": thinking},     # 开关思考
    })
    m = r["choices"][0]["message"]
    got = re.search(r"<answer>\s*(\d+)\s*</answer>", m["content"])   # 只从回答里取数
    return got, m.get("reasoning_content"), r["usage"]["completion_tokens"]

读出来的结论
  • 代价是实打实的：打开思考后，计费的输出从 8 个变成 545～2503 个（约 70～300 倍），用时从不到 1 秒变成 1～5 分钟；看得见的回答始终只有 7 个 token。
  • 草稿真的有用，但模型自己没守住：seed=1 的思考第一轮就逐行比出了“总共是 4 次”，之后自我怀疑、把第 6 行看成 312.530，在 7、3、4 之间来回改，最后交了 5。6 亿参数的模型，思考放大不出它没有的“仔细”。
  • 思考吃掉上限：max_tokens=300 时思考还没写完就被截断，回答是空字符串，300 个 token 照样算钱。
  • 按实验预算，这个对比只跑了两轮（第一轮的提问有歧义，见 README）。“推理模型在数学和代码上正确率更高”的结论来自各家公开的评测，不是本页实测；本页实测的是成本和失败的样子。
到这里已经能交差了：你能说清思考是什么、为什么能提高正确率、钱和时间花在哪，并且知道它不是万能的。

⑥细节：开着思考时最容易踩的坑

第一圈 · 注意事项

1指望“想久一点”就能数对、算对实测← ④ 机制 1
现象
⑤ 里想了 2503 个 token，还是答错；思考里写对过一次，又被自己改掉了。
根源
草稿是自然语言写的“变量”，模型读回来时会看错、会怀疑；思考放大已有的能力，补不上没有的。大模型错得少得多，但不是零。
做法
能用程序确定的（计数、求和、比较、查值）交给程序或工具（站 04），模型只负责解读和下结论。
2max_tokens 给小了，回答一个字都没有实测← ④ 机制 3
现象
max_tokens=300：结束原因 length，回答为空，钱照收。
根源
思考和回答共用同一个输出上限，思考先写。
做法
开思考时 max_tokens 给足（Anthropic 的 API 使用指南建议非流式约 16000、流式约 64000）；检查 stop_reason，是 max_tokens 就别用这个结果。
3开了流式，还是要盯着空白等很久← ④ 机制 3
现象
用户点了“分析”，十几秒没有任何字出来，以为卡死了。
根源
思考先写，而且默认不返回内容（display: "omitted"），流里先来的是空的思考块。
做法
界面上显示“正在分析”；需要给用户看进度时设 display: "summarized"；对延迟敏感的接口用更低的 effort。
4所有接口用同一个 effort← ④ 机制 2
现象
告警分类这种简单任务也开着高 effort，账单和延迟都高；复杂排障却用了 low，结论草率。
根源
思考长度随难度和 effort 变化，effort 是上限也是倾向。按 Claude 文档：分类、聊天这类常常 low 就够，编码和多步的 agent 任务才值得 high 以上；Opus 5.5 默认 medium。
做法
按接口配 effort，并用一小批真实请求量一下：正确率不掉就往下调。

第二圈 · 使用规范

  • 先拆再问：确定性的子步骤用程序做好，模型只拿到“已经数好的结果”去解释。防坑 1。
  • effort 写进配置、按接口区分：分类 low，诊断 high，改了就对比一次正确率和成本。防坑 4。
  • 上限和停因一起管：开思考的调用统一给足 max_tokens，统一检查 stop_reason。防坑 2。
  • 不要替模型规定思考步骤：按 Claude 文档的说法，给新模型写过细的“第一步、第二步”往往反而降低质量；说清目标和约束就好。

第三圈 · 思考的深处

推理时算力也能“扩展”

过去提升能力靠训练时堆算力；推理模型说明了推理时多花算力（多想、多采样再投票）也能换来正确率。代价按次付，所以要按任务挑。

工具调用之间也在想

agent 调完一个工具、拿到结果后，会再想一想下一步做什么（交错思考）。站 04、05 的 agent 循环里，思考 token 会在每一轮重复出现，成本要按轮算。

思考内容不一定是真实的理由

研究发现，模型写出的推理过程不总是它“真正”依赖的依据。思考摘要适合给人看进度，不适合当审计证据。

任务预算

Claude 还有一个 beta 的“任务预算”：告诉模型整个 agent 任务大约能用多少 token，让它自己控制节奏，而不是被 max_tokens 硬截断（按文档，站 05 再用）。

实验台：思考的账

先猜：值班助手每天 2000 次调用，每次回答 300 个 token。用 Opus 5.5，每次再多想 1500 个 token，一个月多花多少钱？

只算输出（输入另计，见 token 和计费）。Claude 单价按文档；输出速度除了本机实测那一档，都是为了算账假设的数，不是 Claude 的实测速度；8.4 个/秒是 ⑤ 里 2503 个 token 用了 324.5 秒折算的（含读输入）。

自测

1. 用一句话说出这一页的精华

模型每圈的算力固定，推理模型先在同一个循环里写草稿再回答，用更多输出 token 换正确率；思考按输出计费、算进 max_tokens，而且只能放大已有的能力。

2. 为什么“写出来”就能让模型算得更多？

每写一个 token 就多跑一遍完整的模型；写下的中间结果留在前文里，后面的圈通过注意力直接读到，不用在一圈里同时完成所有步骤。

从 ④ 机制 1 推出

3. 预测：Opus 5.5 上，把 effort 从 high 降到 low，对“这条告警是哪一类”这种分类任务和“这次故障的根因”这种诊断任务，影响一样吗？

不一样。分类本来就不需要多想，降到 low 省钱省时、正确率基本不变；诊断要多步推理，降到 low 思考变短，结论更容易草率。所以要按接口分别设，并用真实请求量一下。

从 ④ 机制 2（思考长度随难度变化）推出

4. 预测：开着思考、开着流式，max_tokens 设成 500，问一道难题，会看到什么？

先收到思考块（默认内容为空），思考写到 500 个 token 被截断，回答块可能根本没出现，stop_reason 是 max_tokens，500 个 token 照收。

从 ④ 机制 3 推出，⑤ 实测了 300 的情况

5. 既然思考能提高正确率，值班助手为什么不把所有接口都开到 max？

思考 token 按输出单价收，每次多想几千个 token，一天几千次就是一笔大钱；延迟也成倍增加，值班时等不起。而且分类这类简单任务想得再多也不会更准。

从 ④ 机制 3 和为什么这样设计 推出；实验台可以算账

6. 放回全景：思考发生在哪一站？它前后各是什么？如果思考写了 10 万个 token 还没停，整条链路会怎样？

发生在第 8 站的循环里（每圈还是第 6、7 站算概率、挑一个），之前是第 5 站读完输入，之后是第 9 站停下、第 10 站结算。思考停不下来时：要么写到 max_tokens 被截断，第 9 站以 max_tokens 停下、没有回答；要么撞上窗口上限。第 10 站要按 10 万个输出 token 结算，Opus 5.5 约 2 美元一次，用户还要等很久。

档位：标准。本机跑过（2 核 ARM，llama.cpp b12618，Qwen3-0.6B Q4_K_M，--jinja，Python 3.13，2026-11-22）：同一道数数题关掉 / 打开思考各 3 次的答案、计费 token 和用时，max_tokens=300 时的截断，思考过程节选。第一轮实验的提问有歧义（“最后一行只写数字”被理解成日志的最后一行），已改题重跑，两轮的原始输出都在实验仓库的 README 里说明。按文档：Claude 的思考计费、Opus 5.5 思考不能关、effort 档位和默认值、display 选项、max_tokens 建议值、任务预算、提示词别写太细的建议。按公开资料：思维链提示（Wei 等人 2022）、DeepSeek-R1 论文描述的强化学习做法。没有实测：推理模型在大模型上的正确率提升。
