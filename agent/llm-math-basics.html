够用的数学：向量、点积和概率

大模型里用到的数学，够用的只有四样：向量（一串数表示一个东西），点积（两串数对应相乘再相加，越大越“像”），矩阵乘（一次做很多个点积），softmax（把一组分数变成加起来是 1 的概率）。注意力、Embedding 检索、采样，全是这四样拼出来的。

①要解决的问题：怎么让程序知道“Full GC”和“老年代回收”是一回事

在全景第 4、5、6 站，模型要做三件 Java 程序很少做的事：把每个 token 变成一串数（第 4 站）；判断前文里哪些 token 和现在这个最相关（第 5 站）；给 15 万个候选打分再变成概率（第 6 站）。三件事背后是同一个问题：怎么用数字表示“意思”，怎么算两个意思有多近。

②朴素做法：Java 里平时怎么表示和比较

做法“Full GC”和“老年代回收”像不像问题
枚举 / 编号两个不同的编号，看不出关系编号只能比相等，比不出“有多像”
hashCode两个毫不相干的整数哈希故意把东西打散，越像越该分开放
字符串相似度（编辑距离）一个字都不重合，判成完全不像只看字面，不看意思；“GC”和“垃圾回收”也连不上
手写同义词表能，只要表里写了写不完，新词、新说法要一直补
缺的那一块：一种能“算”的表示，让意思近的东西在数值上也近，而且近不近能用一个公式直接算出来，不靠人写规则。这就是向量加点积。

③几种思路：两串数，怎么算“有多像”

算法公式看什么用在哪
欧氏距离√Σ(aᵢ−bᵢ)²两个点离得多远，越小越像聚类、可视化
点积Σ aᵢ·bᵢ方向越一致、长度越长，越大注意力打分、第 6 站打分
余弦相似度a·b / (|a|·|b|)只看方向，范围 −1 到 1Embedding 检索（站 06）

本页学点积和余弦：点积是最便宜的（一次乘加循环），GPU 最擅长；余弦是点积除以长度，向量事先归一化成长度 1 时，两者就是同一个数。

④关键洞察：四样东西，各一句话

先知道这些
  • 求和符号 Σ：Σ aᵢ·bᵢ 就是 Java 里 for (i…) sum += a[i] * b[i];。
  • ex：Math.exp(x)。x 每加 1，结果乘 2.718；永远大于 0。

洞察 1 · 向量：一串数就是空间里的一个箭头，意思近的箭头方向近

洞察 2 · 点积：对应位置相乘再相加；方向一致就大，垂直就是 0，相反就是负

GC 停顿 · Full GC = 0.9×0.8 + 0.2×0.3 = 0.72 + 0.06 = 0.78 GC 停顿 · 下单失败 = 0.9×0.1 + 0.2×0.9 = 0.09 + 0.18 = 0.27 GC 停顿 · 支付超时 = 0.9×(−0.1) + 0.2×0.8 = −0.09 + 0.16 = 0.07 余弦 = 点积 ÷ (两个箭头的长度相乘)，只剩方向：GC 停顿 和 Full GC 0.990，和 下单失败 0.323

几何上，a·b = |a|·|b|·cos θ：θ 是两个箭头的夹角。所以点积同时受“方向像不像”和“箭头多长”影响；余弦把长度除掉，只看方向。Embedding 检索多用余弦，注意力直接用点积（再除以 √维数，防止维数大时分数过大）。

洞察 3 · 矩阵乘向量：矩阵的每一行和向量做一次点积，模型的计算几乎全是它

Java 写出来就是两层循环m 行 n 列 × n 维向量
double[] matvec(double[][] W, double[] x) {
    double[] y = new double[W.length];
    for (int i = 0; i < W.length; i++)      // 每一行
        for (int j = 0; j < x.length; j++)  // 做一次点积
            y[i] += W[i][j] * x[j];
    return y;
}

放回模型里

第 6 站：最后那个 896 维向量乘一个 151936 × 896 的矩阵，就是和词表里每个 token 的向量各做一次点积，得到 151936 个分数。整个模型每出一个 token，约做“参数量”那么多次乘加（Qwen2.5-0.5B 约 4.9 亿次）。GPU 快，就快在能同时做成千上万个这样的乘加。

洞察 4 · softmax：先 ex 变成正数，再除以总和；概率连乘要改成 log 相加

分数 z = [2.0, 1.0, 0.1] e^z = [7.389, 2.718, 1.105] 总和 11.212 概率 = [0.659, 0.242, 0.099] 加起来正好 1 温度 T：先把分数除以 T 再做 softmax（采样页的 p^(1/T) 就是这么来的）
  • 指数让差距被放大：分数差 1，概率差 2.7 倍。所以第 6 站第一名常常一家独大。
  • 工程上要先减去最大分数再算 ex：数学上结果不变，但 exp(1000) 会溢出（⑤ 实测）。
  • 一句话的概率是每个 token 概率的连乘，几百个小于 1 的数相乘会下溢成 0；所以 API 返回的是 logprob（对数概率），连乘变成相加。第 1 页里的 math.exp(c["logprob"]) 就是把它换回概率。

把四样拼起来：一次迷你“注意力”

1. 拿当前位置的向量（查询）和前文每个 token 的向量（键）做点积 → 一组分数 2. softmax → 一组加起来是 1 的权重 3. 用权重把前文每个 token 的向量（值）加权平均 → 当前位置取到的信息

这三步就是下一页要讲的注意力，⑥ 的实验台可以亲手拧一拧。真模型里查询、键、值是同一个向量分别乘上三个不同的矩阵得到的，这一页先把它们当成同一个向量。

为什么这样设计：为什么用点积和 softmax，不用别的

点积 + softmax

  • 点积就是乘加，成批做就是矩阵乘，硬件（GPU、CPU 的向量指令）为它专门优化过。
  • softmax 处处可导、输出永远是正的概率，训练时能顺畅地往回调参数。
  • 代价：softmax 永远给每个候选一点点概率，长尾永远在（采样页的 top_p 就是为它补的）。

“取最大的那个”这类硬规则

  • argmax 只给出一个赢家，没有“第二名差多少”的信息，训练时不知道往哪调。
  • 欧氏距离要先相减再平方再开根，比点积多几步，成批算也不如矩阵乘直接。
决定胜负的约束：模型要靠“比较输出和正确答案、往回微调几十亿个参数”来学，每一步都必须是能求导的连续运算，而且要能在硬件上成批跑。点积、矩阵乘、softmax 正好三样都满足。

⑤手推一遍：五段手算，只用标准库

不连模型，纯 Python 把 ④ 的四样东西各算一遍，再拼一次迷你注意力。函数都只有两三行，和 Java 的写法一一对应。

⑤main.py（四个函数）完整代码 →
def dot(a, b):    return sum(x * y for x, y in zip(a, b))
def norm(a):      return math.sqrt(dot(a, a))
def cos(a, b):    return dot(a, b) / (norm(a) * norm(b))
def matvec(m, v): return [dot(row, v) for row in m]       # 一行一个点积

def softmax(z, safe=True):
    m = max(z) if safe else 0.0      # 先减最大值：结果不变，exp 不溢出
    e = [math.exp(x - m) for x in z]
    return [x / sum(e) for x in e]

读出来的结论
  • 余弦把“意思近”算出来了：“老年代回收”和“GC 停顿”一个字都不重合，余弦 0.995；和“下单失败”只有 0.323。② 里的编辑距离做不到这一点。
  • softmax 只看分数的差：[1000, 999, 990] 和 [10, 9, 0] 得到同样的概率，所以减去最大值不改结果。
  • 迷你注意力的权重偏向两个 GC 相关的 token（0.30 对 0.18），但差得不多：2 维、数值小，分数拉不开。真模型几百上千维，分数差得大，权重会集中得多（实验台里调“放大”就能看到）。

⑥边界和变体

第一圈 · 边界情况

1exp 溢出、连乘下溢实测← ④ 洞察 4
现象
Python 的 math.exp(1000) 抛 OverflowError；Java 的 Math.exp(1000) 返回 Infinity，再除一下就是 NaN。300 个 0.05 连乘得到 0.0。
根源
double 最大约 1.8×10308，exp(710) 就超了；最小正数约 4.9×10−324，连乘几百个小概率就掉到它下面。
做法
softmax 先减最大值；概率一律用 log 存、用加法合并；要概率时再 exp 回来。
2点积被“长度”带偏← ④ 洞察 2
现象
做相似检索时，几个特别长的向量总排在前面，不管问的是什么。
根源
点积 = 长度 × 长度 × cos θ；向量长的，和谁点积都大。
做法
检索用余弦，或者先把向量归一化成长度 1 再用点积（两者此时相等）。站 06 的向量库会让你选“距离度量”，就是这件事。
3维数一大，分数一大，softmax 就“一家独大”← ④ 拼起来
现象
维数从 2 涨到 896，点积的数值也跟着变大，softmax 后几乎全部权重落在一个 token 上，其他的都学不到东西。
根源
点积是 d 项相加，维数越多，数值的波动越大；指数又把差距放大。
做法
注意力里先除以 √d 再做 softmax（缩放点积注意力）。实验台里“放大”那个旋钮就是在模拟维数变大。

第二圈 · 变体

  • log-softmax：直接算 log 概率，训练时的损失函数就用它，比先 softmax 再取 log 更稳。
  • 低精度：推理时向量常用 16 位甚至 4 位存（本站的模型就是 4 位量化），点积在高精度里累加。精度和速度的取舍，站 11 本地部署再讲。
  • 向量归一化：很多 Embedding 模型直接输出长度为 1 的向量，这时余弦 = 点积，向量库用点积就行。

第三圈 · 在你熟悉的系统里

推荐系统、搜索

“用户向量 · 商品向量”打分排序，是点积最早的大规模工业用法；Elasticsearch 的 dense_vector 字段和 PostgreSQL 的 pgvector 也是这一套（pgvector 那页）。

负载均衡的加权随机

按权重随机选一台机器，和采样页的“按概率抽签”是同一个算法：权重归一化、累加、掷随机数。区别只是权重从哪来。

自测

1. 用一句话说出这一页的精华

意思用向量表示，像不像用点积（或余弦）算，模型的计算是成千上万个点积组成的矩阵乘，最后用 softmax 把分数变成概率；概率连乘要用 log 相加。

2. 为什么 hashCode 不能用来判断两段文字意思像不像？

哈希的目标是把东西尽量打散，相近的输入也要映射到相距很远的值；向量正相反，要让意思近的靠在一起。

3. softmax 为什么可以先减去最大值？

分子分母同时乘了 e−max，比值不变；减完后最大的指数是 e0 = 1，不会溢出。

从 ④ 洞察 4 推出

4. 预测：两个向量都先归一化成长度 1，它们的点积和余弦相似度谁大？

一样大。余弦 = 点积 ÷ 长度乘积，长度乘积是 1。

从 ④ 洞察 2 推出

5. 预测：注意力里如果不除以 √d，维数从 64 涨到 4096，会出什么事？

点积数值的波动随维数变大，softmax 后权重几乎全压在一个 token 上，梯度变得极小，模型很难学；所以缩放点积注意力要除以 √d（实验台里“×30”就是这个样子）。

从 ⑥ 边界 3 推出

6. 放回全景：第 4 站和第 5 站之间流过的是什么？如果第 4 站的向量表坏了，每个 token 都查到同一个向量，整条链路会怎样？

第 4 站把 token 编号换成 896 维向量，交给第 5 站做注意力。每个 token 都是同一个向量时，第 5 站所有点积分数一样，注意力只能平均分配，模型分不出“Full GC”和“订单”；第 6 站算出的概率表对任何输入都差不多，回答变成和问题无关的固定套话。
