pytest 写测试：不起日志代理，也能把值班助手测透

pytest 只要求测试是名字以 test_ 开头的普通函数，断言就用普通的 assert：它在导入测试文件时改写这些 assert，失败时把两边的值摊开给你看。精华是 fixture：测试函数的参数名就是它要的东西，pytest 按名字找到同名的 fixture，现场造好、用完收拾；作用域决定造几次、哪些测试共用一份。再配上 FastAPI 的 dependency_overrides 和 httpx 的 MockTransport，不起任何外部服务就能把接口测透。不懂这一点的典型误用：几个测试共用一份可变数据，单独跑都过、一起跑就挂；或者替身换上了却忘了换回来。

全景：一个 FastAPI 请求的一生 · 第 10 站地图：站 01 · pytest 写测试以 pytest 9.2.0、FastAPI 0.162.2 为例

①为什么学：同一条路，在测试里再走一遍，但把网络换成假的

在全景第 10 站，这一步要解决的是：不可能每次跑测试都有 5 台机器、一个日志代理在线，可要测的偏偏是“order-04 卡住不回”“日志为空”“参数越界”这些平时碰不到的情况。办法是让请求照样走第 2～9 站的路由、校验和序列化，只把最外面拉日志那一下换成假的，假数据想造什么样就造什么样。

需求工作要用：站 04 开始，每个工具、每次改提示词都要靠测试和评测兜底；站 09 的评测进 CI，用的也是 pytest。⑤ 要能直接抄，⑥ 先讲最容易让测试“时过时不过”的坑。

unittest 照搬 JUnit 3 的风格
class TestParse(unittest.TestCase):
    def setUp(self):
        self.log = fake_log(12.0, 244.05)

    def test_max(self):

必须写类、继承 TestCase，断言要记一堆 assertXxx；共享准备只有 setUp 这一种粒度。
pytest 普通函数 + 普通 assert
def test_max(agent_logs):
    h = parse("order-01", agent_logs["order-01"])
    assert h.max_ms == 244.05
    assert h.error is None
要什么写在参数里，断言就是 Python 的 assert，失败时 pytest 自己把值打出来。
  • 更老的办法是写个脚本 print 一下、肉眼看对不对：没法进 CI，改代码后也没人会重跑。
  • unittest 能用，但样板多：类、继承、self.assertEqual，准备数据只能放在 setUp 里，粒度太粗。
  • 缺的那一块就是这页的精华：按参数名注入、可组合、可指定作用域的 fixture，加上会“自己解释失败原因”的 assert。

④原理：按名字收集，改写 assert，按参数名注入 fixture

先知道这些
  • 生成器和 yield：函数跑到 yield 停住，之后再从那里接着跑。fixture 用它把“准备”和“收拾”写在一个函数里。见 asyncio 页的“先知道这些”。
  • 名字可以重新绑定：monkeypatch 改的是某个模块字典里的一个名字，见 闭包和装饰器 ④-4。
  • FastAPI 的依赖：每个请求现场调用依赖函数，见 FastAPI ④-3。

  • 1pytest 装了一个导入钩子：导入 test_*.py 和 conftest.py 时，先把源码解析成语法树，把每个 assert 改写成“先算出每个子表达式、失败时把它们拼成说明”的代码，再编译执行。
  • 2所以不用记 assertEqual、assertIn：字典比较会指出哪个键不同，列表比较会指出第几个元素不同。上面是本机实测输出 实测。

4换掉外部依赖的三层办法：越靠近边界越好 ≈ @MockBean、WireMock、反射改字段

dependency_overrides（换依赖）

app.dependency_overrides[get_client] = 假的。FastAPI 调依赖时先查这张表。只对 FastAPI 的 Depends 有效，用完要 clear()。≈ @MockBean。

MockTransport（换网络）

真的 httpx.AsyncClient，只是传输层换成一个函数：请求不出进程，由 handler 决定返回什么，或者抛什么异常。≈ WireMock，但在进程里。

monkeypatch（换名字）

monkeypatch.setattr(模块, "名字", 假的)，测试结束自动改回。什么都能换，但要换对模块。≈ 反射改字段。

怎么选：⑤ 里两层一起用：overrides 把客户端换掉，MockTransport 让这个客户端返回假日志。这样 fetch、parse、超时和异常处理都是真代码在跑，被替换的只有“网络”这一层。monkeypatch 留给环境变量、时间这类没有依赖注入入口的东西。

5为什么这样设计

pytest：普通函数 + 按名字注入选了它

  • 测试就是函数，要什么写在参数里。准备和收拾按需组合，不用把所有准备都塞进一个 setUp。
  • assert 改写让断言既短又能解释失败原因。
  • 代价：规则隐式。fixture 从 conftest 里“凭空”出现，名字拼错就报 fixture 'clinet' not found；作用域选错就互相污染。

xUnit（JUnit、unittest）：类 + 生命周期注解没选

  • 结构显式，读代码就知道 setUp 在哪。
  • 准备工作和测试类绑死，不同测试要的东西不同时，只能拆类或者在 setUp 里全准备一遍。
  • 断言要记一整套方法名，失败信息靠方法自己写。

决定胜负的约束：Python 的函数参数在运行时可以读出来（上一页 FastAPI 也靠这一点），所以“参数名即依赖”几乎零成本；而 Python 本来就有 assert 语句，只要改写一下就能给出好的失败信息。两件事都不需要新语法，学起来就是写普通函数。

2tests/conftest.py 两个 fixture：假日志数据，和接好替身的 TestClient
import httpx
import pytest
from fastapi.testclient import TestClient

import main

PAUSE_LINE = "[2026-11-08T20:05:00.000+0800][info][gc] GC(0) Pause Young (Normal) (G1 Evacuation Pause) 512M->128M(1024M) {ms}ms"

def fake_log(*ms: float) -> str:
    return "\n".join(PAUSE_LINE.format(ms=f"{m:.3f}") for m in ms)

@pytest.fixture
def agent_logs():
    """每个测试一份新的“日志代理数据”，测试里可以随便改。"""
    return {"order-01": fake_log(12.0, 244.05), "order-02": fake_log(80.4),
            "order-03": "", "order-04": None, "order-05": fake_log(41.0)}   # None = 卡住不回

@pytest.fixture
def client(agent_logs):
    async def handler(request: httpx.Request) -> httpx.Response:
        host = request.url.path.split("/")[1]
        if agent_logs[host] is None:
            raise httpx.ReadTimeout("agent hung", request=request)
        return httpx.Response(200, text=agent_logs[host])

    fake = httpx.AsyncClient(transport=httpx.MockTransport(handler), base_url="http://agent")
    main.app.dependency_overrides[main.get_client] = lambda: fake
    with TestClient(main.app) as c:          # with：会跑 lifespan
        yield c
    main.app.dependency_overrides.clear()     # 收尾：别让替身漏到别的测试

第一圈

注意事项：不知道就会出事

1文件或函数没叫 test_，一个都没跑← ④-1 按名字收集
现象
check_parse.py、def parse_test()、class GcTests 都不会被收集。输出 no tests ran，退出码 5。
根源
pytest 只按名字规则找测试，名字不对就当普通代码。
做法
统一 tests/test_*.py、def test_*、class Test*；CI 里把退出码 5 也当失败。
2TestClient 没写 with，lifespan 没跑← ④-3 准备和收拾
现象
c = TestClient(main.app) 直接请求，报 AttributeError: 'State' object has no attribute 'client'。
根源
lifespan 是在 with TestClient(app) 进入时跑的。不写 with，共享客户端根本没建。
做法
放进 fixture：with TestClient(app) as c: yield c。
3替身没清掉，漏到下一个测试← ④-4 overrides 是全局的
现象
test_a 把 get_hosts 换成 lambda: [] 没清；test_b 期望 404，拿到 200。单独跑 test_b 是通过的。
根源
dependency_overrides 挂在 app 上，app 是整个进程共用的模块级对象。
做法
只在 fixture 里设，yield 之后 clear()；或者用 monkeypatch.setitem(app.dependency_overrides, dep, fake)，自动还原。
4共享作用域的 fixture 被改了← ④-3 作用域
现象
scope="module" 的字典被 test_1 改了，同文件的 test_2 挂；单独跑 test_2 通过。换成 session，另一个文件的 test_3 也挂。见实验台。
根源
作用域越大，共用这一个对象的测试越多。
做法
可变数据用默认的 function 作用域；大作用域只放只读或昂贵的东西（数据库连接、加载好的模型），并且返回只读视图或副本。
5浮点数用 == 比较设计如此
现象
assert 0.1 + 0.2 == 0.3 失败。平均停顿这种算出来的数尤其容易中招。
根源
二进制浮点数表示不了 0.1，和 Java 的 double 一样。
做法
assert avg == pytest.approx(96.4, abs=0.05)。
6assert (条件, "说明") 永远通过← ④-2 assert 语法
现象
assert (1 == 2, "never fails") 通过了，只留下一条 PytestAssertRewriteWarning: assertion is always true。
根源
括号把两样东西包成一个非空元组，非空元组永远为真。
做法
写成 assert 1 == 2, "说明"，不加括号。
7直接写 async def test_...，跑不起来设计如此
现象
不装插件时报 async def functions are not natively supported，测试失败。
根源
pytest 本身不带事件循环，协程函数调用了只会得到协程对象。
做法
FastAPI 已经带了 anyio，它自带 pytest 插件：加 @pytest.mark.anyio 就能跑 实测；也可以装 pytest-asyncio。测接口用同步的 TestClient 就够了。

现象

使用规范：团队里怎么写

一个测试只验证一件事

名字写清楚验证什么：test_unknown_service_is_404。

挂了要读半天才知道哪儿坏了。

替身放在最外面那层

优先换网络（MockTransport），其次换依赖，最后才 monkeypatch。

替身换得太里面，真代码其实没测到。

共享准备写进 conftest.py

按目录分层：tests/conftest.py 放全局的，tests/api/conftest.py 放接口专用的。

每个文件复制一份准备代码。

测试之间不能有顺序依赖

任何一个测试单独跑都要能过；CI 里可以加 pytest-randomly 打乱顺序。

测试不碰真网络

需要真服务的放进单独的目录或标记（@pytest.mark.integration），默认不跑。

测试慢、受别人的服务影响而随机失败。

CI 里跑覆盖率，但不追 100%

覆盖率的陷阱：被替身换掉的代码

⑤ 的第 36 行就是例子：get_client 在所有测试里都被换掉了，它自己一次没执行过。替身越多，这种“看起来测了其实没测”的代码越多。补的办法是留一两个真起服务的冒烟测试，或者至少单测一下被替换的那个函数本身。

测超时，又不想真等

替身里 await asyncio.sleep(2) 能触发真的 asyncio.timeout(1.0)，但每次多等 1 秒。常见做法是把超时时间做成可配置（依赖或参数），测试里配成 0.01 秒；时间相关的逻辑把“当前时间”也做成可注入的。

用到：坑 4、实验台

1. 用一句话说出这一页的精华。

pytest 的测试是普通函数加普通 assert，assert 在导入时被改写成能解释失败原因的代码；fixture 按参数名注入、yield 前准备 yield 后收拾、作用域决定共用范围；配上 dependency_overrides 和 MockTransport，不起外部服务也能测完整条链路。

2. unittest 那种写法痛在哪？

要写类、继承 TestCase、记一堆 assertXxx；准备数据只有 setUp 一种粒度，不同测试要的东西不同时只能全准备一遍或拆类。

3. 坑 3“替身漏到下一个测试”是 ④ 哪条原理？

④-4：dependency_overrides 是挂在模块级 app 对象上的一张表，整个进程共用；不在 fixture 的收拾阶段清掉，后面所有测试都会看到它。

4. 预测：把 client fixture 改成 scope="module"，agent_logs 保持默认，pytest 会怎样？

报 ScopeMismatch：大作用域的 fixture 不能依赖小作用域的 fixture，因为 module 级的 client 活得比 function 级的 agent_logs 长，没法每个测试换一份。

从 ④-3 的作用域规则推出。

5. 预测：test_summary_marks_hung_host 里把替身对 order-04 的处理从“抛 ReadTimeout”改成“返回状态码 500、内容是空字符串”，修好之后的 main.py 会给 order-04 什么结果？

error="no pauses"。httpx 拿到 500 不会抛异常（除非调用 raise_for_status()），r.text 是空字符串，交给 parse 就是“没有停顿”。这其实掩盖了“日志代理出错了”这件事，值得再补一个检查状态码的分支和测试。

从 ④-4（MockTransport 让 handler 决定返回什么）和 FastAPI 页“错误要用状态码表达”推出。

6. 放回全景：第 10 站和第 2～9 站是什么关系？如果没有 dependency_overrides，只能用 monkeypatch 换 main.fetch，测试会少测到哪些东西？

第 10 站用 TestClient 直接按 ASGI 调用同一个 app，第 2 站之后的路由、依赖、校验、gather、响应模型全部照常执行，只有拉日志的网络被换掉。

如果换的是 fetch 整个函数，那 fetch 里的 asyncio.timeout、两类异常处理、调用 parse 的那一步都不会执行。⑤ 里那个 httpx.ReadTimeout 的 bug 就是在 fetch 里，用这种办法根本抓不到。
