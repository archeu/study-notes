怎么选模型：能力、价格、速度、开源闭源、国内外

没有“最好的模型”，只有“对这一类调用够用、又最便宜最快的模型”。办法是先按调用分类，再在自己的题上量：值班助手的告警分类、故障诊断、写报告，难度差几个数量级，没必要都用最贵的。实测本机两个 5～6 亿参数的小模型给 8 条告警分类，只对了 4 条和 2 条，而 4 条正则就全对了。榜单和直觉都替代不了这一步。

①要解决的问题：值班助手的每一次调用，该交给谁

在全景第 1 站，请求里要写 model 字段；第 10 站按这个模型的单价结算。值班助手上线后，一天大约有三类调用，难度和量都差得很远：

②不用它会怎样：三种常见的拍脑袋

拍脑袋的选法看起来的理由会出什么事
全部用最强的质量最好，省心告警分类每天 2000 次也按最贵的算，钱大头花在最简单的活上；延迟也高
全部用最便宜的 / 本地小模型省钱，数据不出门诊断质量不够；⑤ 实测 5 亿参数的模型连告警分类都只对一半
看排行榜第一公开评测分最高榜单题和你的题不一样；中文日志、你们的术语、你们的格式，它没考过
不懂精华时的典型误用：选型只比“每百万 token 单价”。各家分词不同（token 和计费 ④）、思考长度不同（推理模型 ④）、重试次数不同，单价低的不一定便宜。要比的是“完成一次任务、达到要求的质量，总共花多少钱、多少时间”。

③几种流派：模型从哪来

来源例子好处代价
国外闭源 APIClaude、GPT、Gemini能力上限高，不用管机器数据要出境；国内访问、付款、合规要单独解决
国内闭源 API各大厂和创业公司的模型服务访问稳定，合规路径清楚，价格通常有竞争力能力和生态因家而异，要自己量
开源权重，自己部署Qwen、DeepSeek、Llama、GLM 等数据完全不出门，能微调，按机器而不是按 token 付钱要 GPU 和运维；大尺寸的开源模型部署成本不低
开源权重，用托管服务云厂商托管的开源模型不用管机器，还能随时换成自部署数据仍然要发给托管方
不用模型规则、正则、传统分类器快、免费、可解释只适合规则写得出来的事（⑤ 的告警分类）

本页学的是一套选法，不是一个答案：按调用分类、列出约束、建一个小评测集、在候选上量，再按结果分配模型；站 03 用抽象层让“换模型”只改配置。具体型号和价格变得很快，这一页只写方法和已核对的 Claude 价格。

④核心取舍：五个维度，先硬约束，后软指标

先知道这些
  • 评测集：几十条带标准答案的真实样本，用来在候选模型上跑分。站 08 会系统地做，这一页先做一个 8 条的。
  • 首字延迟、输出速度：用户等到第一个字的时间，和之后每秒出几个字（上下文窗口 ④）。

取舍 1 · 先过硬约束：不满足就直接出局

硬约束问自己会刷掉谁
数据能不能出门日志里有没有用户手机号、订单金额？公司允不允许发到外部服务，允不允许出境？不允许出门：只剩自部署；不允许出境：刷掉境外服务
合规是对公众提供的生成式服务，还是内部工具？在国内对公众提供生成式 AI 服务要按《生成式人工智能服务管理暂行办法》履行备案等义务，具体以法务意见为准
窗口和输入类型单次最长要喂多少 token？要不要看图片、PDF？窗口不够的、不支持多模态的
必须的功能要不要工具调用、结构化输出、流式、提示缓存？不支持的（很多本地小模型的工具调用不稳）
延迟上限用户能等多久？分类要几百毫秒，诊断可以等十几秒太慢的，包括思考停不下来的

取舍 2 · 再比软指标：质量、成本、速度，在自己的题上量

指标怎么量容易犯的错
质量同一批真实样本，每个候选跑一遍，按事先写好的标准判对错只看几个例子凭感觉；只看平均分，不看错在哪（⑤ 里 0.6B 是全答“数据库”蒙对 2 条）
成本用每次调用的 usage 算“完成一个任务”的总花费，含思考和重试只比单价（② 的误用）
速度记录首字延迟和总耗时的分位数（P50、P95）只测一次；没测高峰时段

Claude 自家的三档就是现成的“质量—成本”梯子（按 Claude API 文档，2026-11 核对）：

模型输入 / 输出（美元每百万 token）窗口适合
Claude Opus 5.54 / 20100 万复杂诊断、agent、写代码；思考不能关，默认 effort medium
Claude Sonnet 5.52 / 10100 万日常的编码和 agent，速度和能力的平衡点
Claude Haiku 5.50.1 / 0.5（提示超过 10 万 token 时 0.5 / 2.5）100 万分类、路由、抽取、子任务：量大、要快

取舍 3 · 不必只选一个：按调用分配，留好退路

核心取舍：为什么不“一次选定、长期不变”

按调用分配 + 评测集 + 抽象层

  • 每类调用都用“够用的最便宜”，钱花在刀刃上。
  • 新模型出来，跑一遍评测集就知道该不该换，换只改配置。
  • 代价：要维护评测集和抽象层；不同模型的提示词可能要分别调。

一个模型包打天下，写死在代码里

  • 最简单，上线快。
  • 模型几个月一换代、价格常调，写死的选择很快过时；某家服务出故障时也没有退路。
决定胜负的约束：模型市场变得比业务快：能力、价格、型号每几个月就变一轮。能持续做对选择的，是“评测集 + 抽象层”这套机制，而不是某一次的结论。

⑤套进场景：给“告警分类”这一类调用选型

按 ④ 的顺序走一遍。硬约束：告警文本里没有用户数据，内部工具，延迟要几百毫秒以内，只需要输出一个类别。候选：4 条正则（不用模型）、本机两个开源小模型。评测集：8 条真实写法的告警，四类各两条（真要上线至少要几十条）。

读出来的结论
  • 两个小模型都不能用：0.5B 不认识的就往“GC”（系统提示里排第一的类别）上靠；0.6B 不管什么都答“数据库”。2/8 那两条是蒙对的，只看正确率会高估它。
  • 规则 8/8，但别高兴太早：这 4 条正则是照着这 8 条告警写的，换一批新写法的告警就会漏。真实做法常是“规则先判，判不出的再交给模型”。
  • 下一步该量谁：规则判不出的那部分，在几十条样本上量 Claude Haiku 5.5（量大、要快、单价最低的一档）；诊断那一类再在 Opus 5.5 和 Sonnet 5.5 之间量。这台机器没有 key，留到站 03 有 key 时做。
  • 这个过程比结论更值钱：硬约束 → 候选 → 自己的评测集 → 看错在哪 → 按调用分配。模型换代了，流程照样用。
到这里已经能交差了：给你一类调用，你能列出硬约束、挑出候选、搭一个小评测集量一遍，并给出“这一类用谁、为什么”的结论。
反例和误用：看榜单选（误用 1），只比单价（误用 2），把模型名写死（误用 3），评测集太小或照着答案写（误用 4）。

⑥反例和误用

第一圈 · 常见误用

1按排行榜选← ④ 取舍 2
现象
榜单第一的模型接进来，中文日志分类反而不如排名靠后的。
根源
公开榜单考的是通用题，你的题有自己的语言、术语和格式；榜单题还可能被训练数据“见过”。
做法
榜单只用来挑候选，最终以自己的评测集为准。
2只比每百万 token 单价← ④ 取舍 2
现象
换了一个单价便宜一半的模型，月账单没降多少，失败重试倒多了。
根源
同一段文字在不同分词器下 token 数不同；思考长度不同；质量差导致的重试和人工返工都是成本。
做法
比“完成一个任务的总成本”：用评测集跑完，按 usage 加总，再除以答对的条数。
3模型名写死在业务代码里← ④ 取舍 3
现象
模型下线、涨价、出了更好的，要改十几处代码；某家服务故障时没有备用。
根源
把“用哪个模型”这个经常变的决定，焊进了不常变的业务逻辑。
做法
业务只说“我要做哪一类事”，模型、参数、备用模型写在配置里，由抽象层解析（站 03）。
4评测集太小，或者照着答案写规则和提示词实测← ④ 取舍 2
现象
⑤ 的正则 8/8，上线一周就漏了一半新告警。
根源
8 条样本太少，而且规则就是看着这 8 条写的：考试题和复习题是同一套。
做法
评测集至少几十条、来自真实流量；留一部分“没看过的”做最终检验（站 08）。

第二圈 · 使用规范

  • 先写硬约束清单：数据、合规、窗口、功能、延迟，五条不满足的直接出局。防的是量完才发现不能用。
  • 每类调用一份评测集：分类、诊断、报告分开量，分开定模型。
  • 选型结论带日期：“2026-11，告警分类：规则 + Haiku 5.5，准确率 x%，每月 $y”，过三个月重跑一次。
  • 至少一个备用模型：主模型 429、过载或下线时能切过去（站 03 的出错处理）。

第三圈 · 开源和国内外，多想一步

自部署不等于便宜

按 token 付钱时，不用就不花钱；自部署按机器付钱，GPU 闲着也在烧。量小、波动大时 API 往往更便宜；量大且稳定、或者数据不能出门时，自部署才划算。站 11 会用本机实测算这笔账。

国内外不只是网络问题

用境外服务处理含个人信息的数据，涉及数据出境的合规要求；面向国内公众提供生成式 AI 服务，涉及备案。内部值班工具、日志脱敏后，约束会小很多。具体以公司法务和数据合规的意见为准。

速度要量分位数

同一个模型，在不同时段、不同地域的首字延迟能差几倍。上线前在真实网络环境下量 P50 和 P95，而不是看官方宣传的速度。

小模型也有位置

本页的 0.5B 模型分不了类，但更大一些的开源小模型经过微调，常能把单一分类任务做得又快又准（站 11 微调）。“小”不等于“不能用”，要看任务和有没有针对性训练。

实验台：按调用分配模型，一个月多少钱

先猜：三类调用全用 Opus 5.5，和“分类改用 Haiku 5.5、其余不变”相比，一个月能省下多少？

口径（为算账假设）：分类每次输入 400、输出 80（含少量思考）；诊断每次输入 6000、输出 2500（含思考）；报告每次输入 10000、输出 3000。不含提示缓存和批处理折扣。Claude 单价按文档；“规则”按 0 元计。这里只算钱，质量要靠评测集量，便宜的不一定够用。

↺回到⑤：改一改

  1. 新写法：再写 8 条“换了说法”的告警（比如“订单库 CPU 100%”“iOS 端支付页闪退”），不改正则，看规则还能对几条。（误用 4）

自测

1. 用一句话说出这一页的精华

先按调用分类、过硬约束，再在自己的评测集上量质量、总成本和速度，按调用分配“够用的最便宜”，用抽象层让换模型只改配置。

2. 为什么不能只比每百万 token 单价？

不同模型分词不同、思考长度不同、质量不同导致的重试和返工也不同；要比完成一个任务、达到要求质量的总成本。

从 ④ 取舍 2 推出

3. 0.6B 模型 8 条答对 2 条，说明它“有 25% 的能力”吗？

不说明。它 8 条全答“数据库”，那 2 条是碰巧本来就是数据库类。看错在哪比看正确率更重要。

从 ⑤ 实测和 ④ 取舍 2 推出

4. 预测：日志里有用户手机号，公司规定不能发到境外，值班助手的诊断还能用 Claude 吗？

不能直接发原始日志。要么先脱敏（去掉手机号等个人信息）再看合规是否允许，要么诊断这一类改用国内服务或自部署模型。这是硬约束，先于质量和价格。

从 ④ 取舍 1 推出

5. 预测：实验台里把诊断从 Opus 5.5 换成 Haiku 5.5，账单会降很多，为什么不直接这么做？

诊断是难度最高、错了代价最大的一类；省下的钱可能抵不上一次误判的损失。要先在诊断评测集上量 Haiku 的正确率，够用才换。

从 ④ 核心取舍和误用 2 推出

6. 放回全景：选模型影响全景的哪几站？如果第 1 站选错了模型（比如给诊断选了 0.5B 的小模型），整条链路会怎样？

影响第 1 站的 model 字段，以及由它决定的第 2 站分词器、第 3 站窗口大小、第 5～8 站的速度和能力、第 10 站的单价。选了 0.5B：第 3 站窗口可能装不下几千 token 的日志；装得下也会像本站各页实测的那样抄错行、数错、编版本号，第 10 站核对时大量不通过，值班助手等于没用。

档位：标准。本机跑过（2 核 ARM，llama.cpp b12618，Qwen2.5-0.5B-Instruct Q4_K_M 和 Qwen3-0.6B Q4_K_M（关掉思考），温度 0，Python 3.13，2026-11-22）：8 条告警的规则基线和两个小模型的分类结果、耗时。按文档（Claude API，2026-11 核对）：Opus 5.5、Sonnet 5.5、Haiku 5.5 的价格、窗口和适用场景。按法规名称：《生成式人工智能服务管理暂行办法》（具体义务以法务意见为准）。没有核对：其他厂商的具体型号和价格（变化太快，本页不写）。实验台的调用量和 token 数是为算账假设的。
