    02 大模型怎么工作入门11/23–12/06 · 2 周 · 52 小时 站在用它的人这边看懂模型：它一次写一个 token，为什么会编，为什么上下文越长越贵。 一句话怎么变成模型的回答 0%

    ① 先看全景

    一句话怎么变成模型的回答

    分词成 token，一个一个往后生成，采样挑词，直到停下

    打开全景页 →

    知识点 9 个

    • 一次只写一个 token：下一个词预测
    • token、分词和计费
    • 上下文窗口：输入输出共用，越长越慢越贵
    • 采样：temperature 和 top_p 改的是什么
    • 为什么会一本正经地编（幻觉）
    • 推理模型和“思考”：用 token 换质量
    • 注意力和 KV 缓存（只讲到够用）
    • Embedding：文本变向量，意思近的靠得近
    • 怎么选模型：能力、价格、速度、开源闭源、国内外

    值班助手 · 这一站

    三个小实验写成报告：同一段日志的 token 数和成本；温度 0 和 1 各跑 10 次看差别；把一条关键报错埋进长日志，看模型找不找得到。

    怎么算过关

    • 答得出：温度设成 0，为什么也不保证每次一样
    • 给一个调用场景，估得出大概花多少钱、多慢
    • 讲清幻觉从哪来，为什么“先查资料再回答”能缓解

    Java 老朋友

    上下文窗口 ≈ 堆内存上限，但装太满不会报 OOM，而是悄悄抓不住重点；Embedding 和 hashCode 正相反，hashCode 要散开，Embedding 要让意思近的靠在一起。

    够用的数学：向量、点积和概率

    工具定义≈ RPC 接口04

    像有名字、参数、返回值

    不像模型只提议调用，执行的是你的代码；它会传错参数

    Agent 循环≈ while + 状态机04

    像每轮看结果决定下一步

    不像下一步由模型决定，必须有上限

    记忆系统≈ 缓存 + 淘汰策略05

    像有写入、过期、淘汰

    不像先要判断值不值得记，新旧记忆还会互相矛盾

    RAG≈ 先查缓存再回源06

    像先查外部存储，再拼出答案

    不像查到的是“相似”不是“命中”，可能拿错

    MCP≈ JDBC 驱动 / SPI07

    像一套接口，各家实现，客户端不改

    不像驱动是你挑的可信代码，MCP 服务端可能不可信

    Dify 工作流≈ Flowable 流程引擎08

    像拖节点、连线、条件分支

    不像节点里是概率模型，每个节点都要评测

    多 agent≈ 微服务拆分08

    像拆开能并行，各管一摊

    不像每个 agent 都要重读上下文，token 成倍涨

    评测集≈ 单元测试09

    像改完跑一遍，防回归

    不像结果是通过率，要分清进步还是噪声

    护栏≈ Filter 链 / Spring Security10

    像进出都过一道检查

    不像攻击写在自然语言里，正则拦不全

    断点续跑≈ Kafka 的 offset 提交10

    像挂了从记下的位置接着跑

    不像重放一步，模型可能做出不同决定，工具要幂等

    微调≈ 改源码重新编译11

    像比改配置（提示词）改得深，效果稳

    不像结果不确定，要靠评测证明变好了，还可能把别的能力弄坏
