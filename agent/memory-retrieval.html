记忆怎么取：按相关性、时间、重要性召回

取记忆分两段：先过滤（团队、类型这类硬条件，不参加打分），再给情景记忆打分：相关（向量相似度）、新近（越久越低）、重要（写入时打的分），三项各自归一到 0～1 再加权相加。只看相似度不行：本机实测，问“是不是昨天那个问题”，昨天那条在 25 条里按相似度排第 12，因为“昨天”这两个字向量读不懂；三项不归一就相加也不行，量纲最大的那一项说了算。

全景：第二天再问同一个服务 · 第 2 站地图：站 05 · 记忆怎么取：按相关性、时间、重要性召回深度：懂机制

这一页的位置记忆分几种讲了按类型取：规矩按范围、事实按 key、经历按“相似度 × 新近”。这一页把经历的打分讲透；记忆怎么写存下的日期和重要性，就是这里的原料。

①为什么需要：41 条里挑几条放进上下文

在全景第 2 站，先按 team=trade 过滤，再给 41 条打分：相关（向量相似度）、新近、重要，取回 M1、M2、M3。规矩和事实按上一页的办法直接取；真正要“挑”的是情景记忆：交易组有 25 条病历，上下文里只放得下两三条。

②没有它会怎样：只按相似度取

最直接的办法：问题和 25 条病历都变成向量，取余弦相似度最高的 3 条。本机实测（Qwen3-Embedding-0.6B）：

1E15 11-06 order-svc 接口偶尔 800ms：下游冷启动0.6253 天
2E6 07-20 order-svc 全量下单失败 40 分钟（P0）0.610112 天

……………………
12E1 11-08 order-svc Full GC：导出读 41 万行（问题问的正是它）0.5091 天
  • 问题里写的是“P99 1.6 秒”，没写“Full GC”，所以最像的是另外几条讲 P99、讲耗时的病历。
  • “昨天”这个词，向量读不懂：它不知道今天是几号，也不会把“昨天”和“11-08”对上。
  • 25 条的相似度挤在 0.417～0.625 之间，排第 3 和排第 12 只差 0.09。
不懂精华时的典型误用：把记忆召回当成搜索，“最像的就是最该给的”。记忆有时间、有轻重，用户的问题里还常常带着时间指代（昨天、上次、刚才），这些相似度都看不见。

③相邻方案：怎么从一堆里挑几条

要求只看相似度只看时间（最近 N 条）多信号加权打分先粗召回，再让模型重排
“昨天那个问题”能取到不能：E1 排第 12能能：⑤ 里 E1 排第 2看粗召回有没有捞到它
半年前的 P0 大事故还能想起来能，看措辞不能能：重要性托底能
不被无关的新记忆挤掉能不能：昨天的误报也排前面能：相关性托底能
成本一次向量检索一条 SQL向量检索 + 几行算术多一次模型调用
能解释为什么取它一个分数一个时间三个分数，看得出谁拉高的模型说了算

本页学多信号加权打分：便宜、能解释、三个信号互相托底。记忆多到几千条时，在它前面加一层向量粗召回，在它后面可以再加模型重排（站 06 RAG 会讲重排）。

这套打分出自 Generative Agents（Park 等，2023）：25 个虚拟人物在小镇里生活，每个人的记忆流按“新近、重要、相关”三项打分取回。它是 Agent 记忆召回最常被引用的做法。

④原理：先过滤，再三项各自归一、加权相加

先知道这些
  • 余弦相似度：两个向量方向越接近越大，最大 1。见 Embedding 与向量相似度。
  • min-max 归一：把一组数线性拉到 0～1，最小的变 0、最大的变 1：(x − min) / (max − min)。
  • 记忆的类型：只有情景记忆参加打分。见 记忆分几种。

Java 老朋友：这三项你在缓存淘汰里都见过（Redis 的 LRU 和 LFU）：新近 ≈ LRU 看的“最近一次访问”，重要 ≈ LFU 看的“有多值钱”。不像的地方：淘汰是给整个缓存挑“谁该走”，和请求无关；召回是给这一次的问题挑“谁该进来”，所以多了“相关”这一项，而且每个问题的排名都不一样。

机制 1 · 过滤：硬条件写进 WHERE，不写进分数

  • 哪些是硬条件：团队（隔离）、类型、有效期（已作废、已过期的不取）。它们的答案只有“能”和“不能”，没有“比较能”。
  • 写在哪：在向量检索之前，作为 SQL 的 WHERE team = 'trade' AND kind = 'episodic' AND valid_to IS NULL。pgvector 里 WHERE 条件和向量距离排序写在同一条 SQL 里（索引和过滤一起用时的细节放到 ⑥）。
  • 写进分数会怎样：“团队匹配加 0.5 分”，别组的一条高相似记忆照样可能挤进前 3，等于隔离失效。

机制 2 · 三个信号：各自回答一个问题

信号回答什么怎么算本页 25 条的实测范围
相关 relevance和这次的问题像不像问题向量和记忆向量的余弦相似度0.417～0.625
新近 recency是不是最近的事指数衰减：0.5 ^ (过了几天 / 半衰期)，本页半衰期 30 天0.015～0.977
重要 importance这件事有多严重写入时打的 1～10 分，除以 100.2～1.0

Generative Agents 的原始做法：新近按“距上次被取用过了几个小时”衰减，每小时乘 0.995；重要性在记忆写入时让模型打 1～10 分（1 是刷牙这种日常，10 是分手这种大事）。值班助手把单位换成天、半衰期换成 30 天，意思一样。

机制 3 · 合起来：先归一，再加权

  • 为什么先归一：三项的范围差很多。实测新近横跨 0.015～0.977，相关只在 0.417～0.625 之间动。直接相加，新近的一点变化就盖过相关的全部差异，等于“只看新近”。各自用 min-max 拉到 0～1，三项才在同一把尺子上。
  • 再加权：score = α·相关 + β·新近 + γ·重要。Generative Agents 三个权重都取 1。值班助手里“昨天那个问题”这种问法多，新近可以重一点；问“以前有没有过类似的”时，相关重一点。
  • 取多少：按分数取前 K 条，再看 token 预算（上一站讲过每块要有上限）；最高分也很低时宁可不取，别把无关的旧事塞进上下文。

为什么这样设计：三个便宜的信号互相托底

过滤 + 三信号归一加权

  • 每个信号补另一个的盲区：新近补“昨天”，重要补“半年前的 P0”，相关挡住“昨天的无关误报”。
  • 只要一次向量检索加几行算术，几百条记忆毫秒级。
  • 能解释：哪一项把它拉上来的，一看分数就知道。
  • 代价：权重和半衰期要调，没有放之四海皆准的值。

把所有记忆交给模型挑

  • 模型读得懂“昨天”，也分得清轻重。
  • 每次会话开始都要把全部记忆读一遍，记忆越多越慢越贵。
  • 为什么挑这几条说不清，调不了。
决定胜负的约束：召回在每次会话开头都要跑，要快、要便宜，还要随记忆增长不变慢；而单个信号各有盲区。几个便宜信号相互托底，比一个昂贵的“全知”判断更合适。模型留给最后一步：在几十条候选里重排。
main.py（节选）半衰期、权重放到 ⑥
mine = [e for e in EPISODES if e.team == TEAM]   # 先过滤

def score(rows, a=1, b=1, c=1, half_life=30):
    rel = [r["sim"] for r in rows]
    rec = [0.5 ** (r["age"] / half_life) for r in rows]
    imp = [r["importance"] / 10 for r in rows]
    rel, rec, imp = minmax(rel), minmax(rec), minmax(imp)
    return [a*x + b*y + c*z for x, y, z in zip(rel, rec, imp)]

三个信号各防一种错

只有相关：取到措辞最像的，不一定是你问的那件。

只有新近：昨天的告警误报也排第二。

只有重要：每次都是那几条大事故，不管你问什么。

⑤亲眼看到：25 条病历，五种打分

交易组 25 条情景记忆（另有 6 条风控组的），日期从 5 月到昨天，每条带 1～10 的重要性。同一个问题“10:42 告警：order-svc P99 1.6 秒。是不是昨天那个问题？”，五种打分各取前 3。

读出来的结论
  • 单一信号都会错：只看相关漏掉了昨天；只看新近取到昨天另外两件无关的小事；只看重要每次都是那几条大事故。
  • 归一很要紧：不归一时，新近的范围（0.015～0.977）比相关（0.417～0.625）宽四倍多，结果和“只看新近”差不多，连 payment-svc 的病历都进来了。
  • 三项归一后相加：E15（3 天前、措辞最像）、E1（昨天、重要 8）、E6（P0 大事故）。E1 进来了，E6 当背景也说得过去；E15 那次是下游冷启动，和今天无关，它占了一个名额。这就是 ⑥ 要调权重、加门槛的原因。
到这里已经能交差了：先按团队和类型过滤，再给情景记忆算三项分数，各自归一后相加，取前 3。
已知还没处理的细节：时间指代（坑 1），不归一（坑 2），隔离写成分数（坑 3），新近按取用时间算的副作用（坑 4），重要性打分全挤在一起（坑 5），不相关也硬取满（坑 6）。

⑥细节

第一圈 · 注意事项

1“昨天”“上次”交给相似度实测← ④ 机制 2
现象
问“是不是昨天那个问题”，昨天那条排第 12。
根源
向量只编码措辞的意思，不知道今天几号，也不会把“昨天”换算成 11-08。时间要靠新近这一项，或者显式的时间条件。
做法
问题里有时间指代时，先把它换算成日期范围放进过滤条件（date >= '2026-11-08'）；没有时，靠新近项托底。
2三项不归一就相加实测← ④ 机制 3
现象
取回来的几乎都是最近几天的，包括别的服务的（⑤ 里的 E23）。
根源
相关只在 0.417～0.625 之间动，新近横跨 0.015～0.977；直接相加，范围宽的那项说了算。
做法
每一项在这一批候选里先 min-max 归一，再加权。换了 embedding 模型，相似度的范围会变，归一还能自动适应。
3团队隔离写成了加分项← ④ 机制 1
现象
风控组那条“11-08 risk-svc Full GC”（昨天、重要 8、措辞也像）出现在交易组的召回结果里。
根源
“能不能看”是硬条件，不是“看得多看得少”；写成分数，就总有一组权重让它挤进来。
做法
团队、类型、有效期一律放 WHERE；在召回代码外面再加一道断言：返回的每条 team 都等于当前用户的团队。
4新近按“上次被取用”算，常用的越来越常用← ④ 机制 2
现象
某条记忆被取用一次，新近分就回到满分，下次更容易被取到，越滚越靠前，挤占了真正相关的。
根源
Generative Agents 按距上次取用的时间衰减，模拟“想起一次就记得更牢”；在值班场景里，它会把一次被误取的记忆一直留在前排。
做法
值班助手按事件发生的日期算新近；“被取用多少次、取用后是否有帮助”单独记下来，交给评测和遗忘（下两页）去用。
5重要性打分全挤在 7、8 分← ④ 机制 2
现象
让模型给每条记忆打 1～10 分，大多数都是 6～8，重要性这一项几乎不起作用。
根源
不给标尺，“重要”没有参照：模型倾向于给个居中偏高的安全分。
做法
给明确的标尺（P0 事故 10、影响用户的故障 7、误报 2），最好用结构化字段算（故障级别、持续时间、影响面），而不是让模型凭感觉打。
6不相关也硬取满 K 条← ④ 机制 3
现象
问一个全新服务的问题，记忆块里照样塞进 3 条别的服务的旧病历，模型顺着它们去猜。
根源
归一后的分数是“这一批里的相对位置”，总有人排第一；它不表示“足够相关”。
做法
在归一之前，对原始相似度设一个下限（比如低于这批的中位数，或低于一个用评测集定的值）就不取；宁可记忆块为空。

第二圈 · 使用规范

  • 硬条件进 WHERE，软偏好进分数：防隔离被权重绕过。
  • 召回结果带上三项分数一起记日志：防“为什么取了这条”说不清，调权重时有数据可看。
  • 权重、半衰期、下限都是配置，按场景调，用评测集定：防拍脑袋。
  • 取回的记忆进上下文时带日期和分数来源：模型知道这条是“昨天的、很像的”还是“半年前的、很重要的”。

第三圈 · 优化和深处

记忆多到几万条

三项打分要对每条候选都算一遍，候选得先缩小。常见做法是两段：先用向量索引（如 pgvector 的 HNSW）按相关性粗召回前 50，再在这 50 条里算新近和重要、重新排序。注意：带 WHERE 条件时，近似索引可能先取出前 N 个再过滤，过滤掉太多就不够数，要调大候选数或用支持过滤的检索方式（站 06 讲向量索引时细说）。

再加一层模型重排

粗召回 + 打分之后剩十几条，可以交给模型（或专门的重排模型）按“对回答这个问题有没有用”再排一次。它读得懂“昨天”、分得清“同症状不同原因”，但每次会话多一次调用。值班助手先不加，等评测（下下页）说明打分不够用时再加。

自测

1. 用一句话说出这一页的精华

先用硬条件过滤，再给情景记忆算相关、新近、重要三项分，各自归一到 0～1 后加权相加；三个便宜的信号互相托底，比只看相似度可靠。

2. 只按相似度取，痛在哪？

相似度只看措辞：问题里没写“Full GC”，昨天那条就排第 12；“昨天”这种时间指代它也读不懂；25 条的分数挤在 0.2 的区间里，排名很脆。

3. 坑 2（不归一就相加）的根源是哪条原理？

④ 机制 3：三项的取值范围不同（实测新近 0.015～0.977，相关 0.417～0.625），直接相加时范围宽的那一项主导排名。

4. 预测：把半衰期从 30 天改成 1 天，三项归一后相加的前 3 会怎样？

1 天之外的新近分几乎都是 0，新近这一项变成了“是不是昨天或今天”。E1（昨天）升到第 1；E6 靠相关和重要还在第 2；E15 是 3 天前的，新近分只剩八分之一，只靠相关留在第 3。昨天那条 E7 误报相关和重要都低，还是进不来。可以在实验台上验证。

从 ④ 机制 2 的指数衰减和机制 3 的归一推出。

5. 预测：如果所有记忆的重要性都是 7 分，γ 调到 2 会怎样？

什么都不变：所有人的重要性一样，min-max 归一后全是 0（范围为 0 时按 0 处理），乘多大的权重都是 0。这就是坑 5 说的“重要性挤在一起就不起作用”。

从 ④ 机制 3 的 min-max 归一推出。

6. 放回全景：第 2 站前后各发生了什么？这一页讲的东西坏了，整条链路会怎样？

前面是第 1 站：新会话，短期记忆是空的。后面是第 3 站：取回的记忆带着日期放进上下文。召回坏了：只看相似度，第 3 站拿到的是 E15、E6、E10，没有昨天那条，第 7 站只能从零查起；隔离写成分数，第 3 站混进风控组的病历，答案里出现 risk-svc；不设下限，第 3 站塞进无关旧事，模型顺着它去猜。
