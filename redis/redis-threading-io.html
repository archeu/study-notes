IO 多路复用：一个服务员 + 呼叫铃

网络读写的老办法是一个连接一个线程，线程调 read 等数据，没数据就一直睡着。连接一多，线程就多到扛不住。多路复用是另一个思路：一个线程把所有连接交给内核，内核告诉它哪些可以读了。

    常踩的坑

    单线程的代价，就是任何一件慢事都会让所有人一起等。

    有人在线上执行了 KEYS *

    遍历几百万个 key，整个实例卡住几百毫秒到几秒。用 SCAN；还可以用 rename-command KEYS "" 或 ACL 禁掉它。

    删一个大 key，接口超时一片

    DEL 在主线程里一个个释放元素。用 UNLINK，或打开 lazyfree-lazy-user-del（Redis 第 05 篇）。

    BUSY Redis is busy running a script

    Lua 脚本跑太久，其他命令只能收到这个错误。脚本里别遍历大量 key；只读脚本可以 SCRIPT KILL，写过数据的只能 SHUTDOWN NOSAVE。

    开了 io-threads，QPS 没怎么涨

    I/O 线程只并行网络读写，不并行执行命令。小命令为主时网络不是瓶颈；线程数也别超过核数。想多用几个核，就多开实例或上集群。

    循环里一条条 GET，接口慢得离谱

    每条命令一次网络来回。用 MGET、HMGET，或者 Pipeline 一次发出去。

    16 核的机器，Redis 的 CPU 只到 100%

    命令执行只用一个核。要用满机器，就在一台机器上跑多个实例，或者用集群分片（Redis 第 03 篇）。

    ERR max number of clients reached

    默认最多 10000 个连接。几十个应用实例各配一个大连接池，很快就满。用 Lettuce 共享连接，或者把池子调小。

    Jedis 多线程共用一个连接，读到别人的回复

    Jedis 连接不是线程安全的。用 JedisPool，或者换 Lettuce。

    在 Lettuce 共享连接上用了 BLPOP，所有请求都卡住

    阻塞命令会占住这个连接。走 Spring 的 RedisTemplate 时会自动换独立连接；直接用 Lettuce 原生 API 时，要自己单独开连接。

    客户端说慢，SLOWLOG 里什么都没有

    慢日志只算执行时间。慢在排队（前面有慢命令）、网络、fork 停顿或客户端自己的线程池上。用 LATENCY DOCTOR 和客户端监控一起查。
